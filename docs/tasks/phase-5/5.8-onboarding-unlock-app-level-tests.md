# 5.8 — App-level end-to-end tests for onboarding/unlock

**Phase:** 5 — Review of Phase 4 · **Feature:** review fix (F8) · **Depends on:** — · **Status:** done

## Goal
Close the last gap in the T17 user-journey test pyramid: no automated test drives the very first
user-facing flow — a typed passphrase or stepped onboarding wizard, through real key events, into a
real `Effect::Unlock`/`GenerateAccount` dispatch, to landing on `Screen::Main`. Every downstream test
(`accept_to_chat.rs` and friends) bypasses this via a pre-provisioned account.

## Scope
- **In:** New App-level tests in the style of `accept_to_chat.rs` for: (a) typed passphrase → real
  `Screen::Unlock` dispatch → `Screen::Main`; (b) stepped onboarding sub-screens → real account
  generation/registration/bundle-publish → `Screen::Main`.
- **Out:** Any production code change, absent the same "report, don't patch around it" exception noted
  in 5.7.

## Deliverables
1. `apps/tui/tests/screens_unlock.rs` gains a real-key-event/real-worker boot test.
2. `apps/tui/tests/screens_onboarding.rs` gains a real-key-event/real-worker boot test covering the
   full wizard, not just individual sub-screen state transitions.

## Risks / notes
This flow was manually exercised (successfully) across all seven T17 exit-gate live PTY runs — that's
mitigation, not a substitute for a regression test. Keep both new tests independent of 5.7 (disjoint
files; may land in either order or in parallel).

## Tests

## Status
**Done, test-only, no production code changed.** Two new tests in `apps/tui/tests/screens_unlock.rs`
(typed-passphrase → real `Effect::Unlock` → real worker unwrap → `Screen::Main`; wrong-then-correct-
passphrase retry with attempt counting) and one in `apps/tui/tests/screens_onboarding.rs` (the full
stepped wizard — `ChooseStore` → `OrgHint` → `Generate` → `ShowIdentity` → `Register` →
`PublishBundle` → `Success` → `Main` — with a real keyfile, real `account.json`, and a real in-process
rendezvous server round trip for `Register`/`PublishBundle`) close the last gap in T17's user-journey test
pyramid.

**No bug found.** Both flows worked correctly end to end on first real run; the only fix needed was a
test-side rendering-width-wrap assertion correction.

**Genuinely end-to-end, confirmed by both review passes independently tracing the call chain and by
`test-engineer`'s mutation testing**: a mutation that made `run_unlock`'s real `scrypt`/`age` verification
unconditionally succeed regardless of passphrase correctness was caught **only** by the new
wrong-passphrase test — none of the pre-existing unit tests (which hand-build `WorkerEvent`s rather than
dispatching through the real worker) could have caught it. A mutation skipping the onboarding wizard's
`PublishBundle` step was caught by both the new full-wizard test and an existing narrower unit test.

**A real, closeable gap found and closed**: `test-engineer` found the wrong-passphrase retry test only
asserted "no leak" at the error-message-string level, never actually rendering the UI to confirm the
typed passphrase doesn't appear on screen — unlike its sibling happy-path test, which does. Closed: added
`render_app_to_text` assertions at both the just-typed and post-failure render points, plus (a
`code-reviewer` nit, also closed) asserting the *correct* passphrase is equally absent, not just the wrong
guess — mirroring `run_worker_account.rs`'s more complete precedent.

**Test isolation confirmed sound** by both reviews: the in-process rendezvous server binds an OS-assigned
ephemeral port (`127.0.0.1:0`, mirroring the already-reviewed `run_worker_account.rs::spawn_server`
precedent from task 4.30); `$MERIDIAN_HOME` is guarded per-file by a `Mutex`-serialized `EnvGuard`, and
each test file compiles to its own process, so no cross-file race is possible.

### Review round

`test-engineer` — **PASS with one should-fix, closed**. Independently mutation-tested three claims (all

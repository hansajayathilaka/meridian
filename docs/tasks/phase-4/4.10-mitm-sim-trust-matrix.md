# 4.10 — `meridian-mitm-sim` trust-state matrix

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T08 — Verification & Contact Trust · **Depends on:** 4.3, 4.4, 4.5, 4.9 · **Status:** pending

## Goal
Prove, with the adversarial harness, that a fully malicious rendezvous cannot complete an undetected
MITM against a verified or pinned contact — the headline acceptance criterion of Feature 08 — including
that 4.9's guarded re-handshake is un-triggerable into a substituted key.

## Scope
- **In:** `harnesses/mitm-sim/` **already exists** (`run.sh` + `README.md`) and is explicit that T08
  extends it — do not delete existing cells. Add: substitute-key attacks against `tofu`, `pinned`, and
  `verified` states; a pass/fail matrix; a cell scripting an attacker substituting a key **during 4.9's
  bundle-refetch window** and asserting the recovery path blocks/warns per 4.4 rather than silently
  accepting it.
- **Out:** any change to the harness's existing pre-T08 cells except what's needed to add the new
  matrix.

## Deliverables
1. Extended `harnesses/mitm-sim/run.sh` + new test cell(s) for the trust-state matrix.
2. Pass/fail matrix output: 0 silent successes against `verified`; 0 successes against `pinned` without
   the exact `verification-ux.md` warning shown.

## Risks / notes
- This task is what actually proves 4.9's recovery path is safe — sequencing it after 4.9 (not just
  after 4.3/4.4/4.5) is required, not incidental: testing "un-triggerable into a substituted key" is
  meaningless before the re-handshake path exists.
- Do not weaken any existing harness assertion to make a new cell pass.

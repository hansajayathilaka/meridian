# 2.5 — Discovery: DNS SRV `_meridian-fed._tcp` + `federation_map.toml` static mode

**Phase:** 2 — Cross-Org Federation · **Feature:** T06 — Cross-Org Federation · **Depends on:** — · **Status:** done

## Goal
Resolve an org domain to s2s endpoints via DNS SRV **or** a static map, with static/air-gap mode able
to fully disable DNS. Pure resolution — no sockets.

## Scope
- **In:** a `Discovery` trait; the `federation_map.toml` parser; an SRV resolver; mode precedence;
  negative-result handling. Also: settle the `federation_map` **config-file vs database-table**
  contradiction (see risks) before 2.11 hard-codes an answer.
- **Out:** dialling (2.4); policy (2.6).

## Deliverables
1. `apps/rendezvous/src/federation/discovery.rs`:
   `trait Discovery { async fn resolve(&self, domain: &str) -> Result<Vec<Endpoint>, DiscoveryError> }`,
   `StaticMap`, `SrvDiscovery`.
2. `apps/rendezvous/src/config.rs`: `discovery = "srv" | "static"`, `map_path`.
3. `demo/two-orgs/federation_map.toml` — the reference fixture consumed by 2.11.
4. Whichever of [data-model.md](../../architecture/data-model.md) or the feature spec is wrong is
   corrected so only one `federation_map` shape exists.
5. `apps/rendezvous/tests/federation_discovery.rs`: static-map hit and miss; malformed TOML rejected;
   SRV priority/weight ordering against a stub resolver; **static mode performs zero DNS lookups** —
   the air-gap assertion.

## Risks / notes
- **Live contradiction:** [data-model.md](../../architecture/data-model.md) defines `federation_map`
  as a **database table** (`domain PK, endpoint, ca_pin, policy`), while the
  [feature spec](../../architecture/features/06-cross-org-federation.md) and the
  [phase README](./README.md) define it as a **config file**, `federation_map.toml`. These disagree
  today. Pick one and fix the other doc — do not leave both.
- `TODO: confirm`: the `federation_map.toml` schema. The file is named in
  [deployment.md](../../operations/deployment.md) and the deployment-topology diagram, but its fields
  are never specified.
- `TODO: confirm`: behaviour when no SRV record exists — fall back to A/AAAA plus a default port, or
  refuse? The repo's fail-closed posture leans refuse, but this is an architect call.
- Shares `config::Federation` with 2.4 — sequence if one developer.
- Genuinely parallel with the server spine: this task has no dependencies and can start immediately.

## Outcome
`apps/rendezvous/src/federation/discovery.rs`: `Discovery` trait, `StaticMap` (parses
`federation_map.toml`, `pinned_identity` mandatory/fail-closed, ASCII-lowercased domain keys),
`SrvDiscovery<R: SrvResolver>` (stub-injectable, RFC 2782 priority/weight ordering, `Target == "."`
treated as no-record). `config::Federation` gained `discovery`/`map_path`, plus `Federation::validate()`
rejecting `discovery = "srv"` combined with a non-empty `ca_bundle_path` (would reopen ADR 0017 (a)'s
rejected "Option A" impersonation hole). `demo/two-orgs/federation_map.toml` reference fixture added.
Resolved the `data-model.md`/feature-spec `federation_map` contradiction in favor of the config file
(also fixed a second, missed instance in `docs/operations/deployment.md`). No-SRV-record: fail-closed
refuse, never falls back to A/AAAA. Pin field named `pinned_identity` (ADR 0017 C4's identity-name pin),
not `ca_pin` (would read as the rejected SPKI-fingerprint scheme).

**Reviews:** architect — consistent; confirmed both flagged calls (SRV fail-closed refusal,
`pinned_identity` naming). test-engineer — found the original air-gap "zero DNS lookups" proof
vacuous via mutation testing (a disconnected `TripwireResolver` never actually reachable from
`StaticMap::resolve`); replaced with an `LD_PRELOAD getaddrinfo(3)` interposition test that re-execs
the probe in a subprocess, verified against the same mutation. code-reviewer — request-changes;
found domain-lookup case-sensitivity and RFC 2782 `Target == "."` bugs, both fixed. security-reviewer
(added mid-task per code-reviewer's routing recommendation — this validates ADR 0017 C4's trust pin) —
approve-with-changes; escalated the case-sensitivity bug (could smuggle a duplicate/conflicting trust
pin past `DuplicateDomain`), found the `discovery=srv`+private-CA gap (fixed), and flagged that
`pinned_identity` isn't yet wired into `link::dial()`'s identity check — that wiring is task 2.7's job;
2.7's task file now carries an explicit deliverable + required test for it.

Tests: `cargo nextest run -p meridian-rendezvous --test federation_discovery` (19/19 pass, 1 `#[ignore]`d
probe by design), full crate 80/80 pass, clippy/fmt clean, `lint-server-no-core.sh` and
`check-docs.sh` pass.

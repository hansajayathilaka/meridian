# 5.8 — App-level end-to-end tests for onboarding/unlock

**Phase:** 5 — Review of Phase 4 · **Feature:** review fix (F8) · **Depends on:** — · **Status:** pending

## Goal
Close the last gap in the T17 user-journey test pyramid: no automated test drives the very first
user-facing flow — a typed passphrase or stepped onboarding wizard, through real key events, into a
real `Effect::Unlock`/`GenerateAccount` dispatch, to landing on `Screen::Main`. Every downstream test
(`accept_to_chat.rs` and friends) bypasses this via a pre-provisioned account.

## Scope
- **In:** New App-level tests in the style of `accept_to_chat.rs` for: (a) typed passphrase → real
  `Screen::Unlock` dispatch → `Screen::Main`; (b) stepped onboarding sub-screens → real account
  generation/registration/bundle-publish → `Screen::Main`.
- **Out:** Any production code change, absent the same "report, don't patch around it" exception noted
  in 5.7.

## Deliverables
1. `apps/tui/tests/screens_unlock.rs` gains a real-key-event/real-worker boot test.
2. `apps/tui/tests/screens_onboarding.rs` gains a real-key-event/real-worker boot test covering the
   full wizard, not just individual sub-screen state transitions.

## Risks / notes
This flow was manually exercised (successfully) across all seven T17 exit-gate live PTY runs — that's
mitigation, not a substitute for a regression test. Keep both new tests independent of 5.7 (disjoint
files; may land in either order or in parallel).

## Tests
`cargo nextest run -p meridian-tui --test screens_onboarding --test screens_unlock`

# 10.9 — Resume protocol: in-stream missing-range bitmap + redial integration

**Phase:** 10 — File Transfer Stream · **Feature:** T09 · **Depends on:** 10.7, 10.8 · **Status:** pending

## Goal
After a session drops mid-transfer and redials (ICE restart, session substrate invariant — ratchets and
now stream-level state outlive the transport), let the receiver tell the sender which byte ranges are
still missing so the sender resumes instead of re-sending the whole file.

## Scope
- **In:** a resume message carrying a missing-range bitmap, sent **in-stream** over `mrd.file/1`'s own
  already-open data channel (via task 10.4's `send_stream_frame`, handled in `FileStream::on_frame`
  itself) — **not** a new `CtrlFrame` variant. `docs/api/wire-protocol.md` §5 documents `Resume = {sid,
  bitmap: bstr}` as a ctrl frame, but `apps/envelope/src/ctrl.rs`'s `CtrlFrame` enum has no such variant
  today, and adding one would force `session.rs::handle_ctrl`'s exhaustive match to grow a
  file-transfer-specific arm — exactly the core-crate leakage task 10.4's review gate exists to reject.
  Resume-in-stream is the reading consistent with the settled substrate design; task 10.12 records the
  wire-protocol.md doc correction. Also: wiring the receiver's redial/session-restart signal (from
  `P2pSession::ice_restart`/session-reestablishment) to trigger sending this resume message once the
  stream is live again.
- **Out:** the sender/receiver engines themselves (10.7/10.8, already landed) — this task only adds the
  resume message schema, its handling, and the redial trigger.

## Deliverables
1. Resume message CBOR schema in `apps/streams` (in the `mrd.file/1` message family, not
   `meridian-proto`/`meridian-envelope`).
2. Sender-side: on receiving a resume message, skip already-acknowledged ranges and only send what's
   missing.
3. Receiver-side: on reconnect, send the current missing-range bitmap before expecting more chunks.
4. A loopback-transport test simulating a mid-transfer disconnect + redial + resume, asserting the
   acceptance criterion: resume never re-sends more than 2% of already-delivered data.

# 3.9 — Resolve the dead per-partner `policy` field in `federation_map.toml`

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F7) · **Depends on:** 3.1 · **Status:** pending

## Goal
An operator writing `policy = "closed"` per partner in the map must not silently get nothing.

## Scope
- **In:** architect picks one of — remove the field + its schema line (cleanest), reject/warn on
  presence, or actually enforce it. Then implement that one.
- **Out:** redesigning `FederationPolicy`.

## Deliverables
1. `apps/rendezvous/src/federation/discovery.rs` — L102/L261 (`Endpoint::policy`).
2. The documented map schema updated in the same PR (discovery/deployment doc).
3. `apps/rendezvous/tests/federation_discovery.rs` — a map containing `policy` produces the decided
   outcome (parse error / warning / enforcement), **not silence**.

## Risks / notes
- If "enforce" is chosen it must compose with 3.1's outbound choke point rather than duplicating the
  check in a second place — two policy gates that can disagree is worse than one.
- This is a documented config-schema change, so it needs architect sign-off regardless of option.

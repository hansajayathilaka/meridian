**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F18) · **Depends on:** 3.1, 3.2, 3.3 · **Status:** done

## Goal

## Scope
- **In:** `apps/rendezvous/tests/support/mod.rs` and `apps/cli/tests/support/mod.rs`; migrate

## Deliverables

   `spawn_c2s`/`spawn_federation` (+ `_handle` variants), `write_federation_map`, and a
   higher-level pair-boot helper. **API shape actually diverges between the two crates' harnesses**
   (see Outcome) — the two crates' tests need genuinely different shapes (rendezvous's one-way

## Outcome
`apps/rendezvous/tests/support/mod.rs` and `apps/cli/tests/support/mod.rs` replace ~11
near-duplicate copies of test-CA-generation + rendezvous server-boot boilerplate with one copy
each. All 11 files in Scope migrated; test counts, test names, and assertion content confirmed
byte-identical to pre-migration (`b17fe50`) across all 11 files — no behavior change, per this
task's own strict Scope. `run_federated_audit`'s (`apps/cli/src/opacity.rs`) session bootstrap was
checked and found already deduplicated via its existing `Party` helper, shared with `run_audit` —
not a `tests/` concern, no action needed.

**API shape diverges from the Deliverables section's original flat sketch, by necessity, not
oversight:** `boot_federated_pair(opts: FederatedPairOpts) -> FederatedPair` on the rendezvous
side is a one-way-dial pair (A dials out to B) — the shape `federation_{fetch,route,abuse,
outbound_policy}.rs` already used before this harness existed. The CLI side's
`boot_federated_pair_bidirectional() -> BidirectionalPair` is mutual-dial (both orgs dial each
other) with no config parameter — the shape `session_connect_federation.rs`/
`two_orgs_walkthrough.rs` need, since their WebRTC offer/answer and chat auto-ack both have to
cross the federation boundary in the direction opposite the initiating message. `TestCa::issue`
also differs by one parameter between the two crates (rendezvous: `issue(&self, dir, domain)`;
CLI: `issue(&self, dir, tag, domain)`, the tag needed to disambiguate co-located same-domain
identities in the bidirectional harness). None of this is a defect — the two crates' tests
genuinely need different shapes — but it diverges from the single flat signature list this task
file originally sketched, so recording it here rather than leaving an implicit mismatch between
spec and code.

Two files in Scope (`federation_fetch.rs`, `federation_route.rs`) use the shared low-level
primitives (`TestCa`/`base_config`/`spawn_c2s`/`spawn_federation`/`write_federation_map`) but keep
a small file-local `org_a_federation`/`org_b_federation` config builder rather than the
higher-level `boot_federated_pair`, because their tests need per-call variation (policy at both
call sites, non-default rate limits to deliberately trip a limiter, etc.) that doesn't map cleanly
onto `FederatedPairOpts`'s fixed shape. This is consistent with the task's Scope ("fold" the
duplicated boilerplate, not force every test onto one fixed high-level entry point) and was
verified by test-engineer's review to introduce zero config-default drift (see below).

**Review, two rounds:**
1. Combined pass (code-reviewer for the correctness/dead-code/naming lens, test-engineer for
   assertion-fidelity) — **no blocking findings**; the refactor was confirmed genuinely pure:
   test-engineer diffed test-function names (not just counts) across all 11 files and found zero
   renames, deep-diffed assertion bodies for 5 files including both hand-finished CLI files, and
   specifically hunted for (and found none of) the sharpest risk in this kind of refactor — a
   migrated test's original non-default config value (e.g. `federation_abuse.rs`'s deliberately
   low `fed_route_per_origin_per_min: 2` to trip a rate limiter) silently normalized to the
   harness's default. code-reviewer raised 4 should-fix hygiene findings, all closed in this same
   task: (1) `boot_rendezvous` was dead code (zero callers, hidden from clippy by the module's
   `#![allow(dead_code)]`) — deleted; (2) `FederatedPairOpts::a_pin_b_as` was dead (its
   doc-promised caller, `federation_fetch.rs`'s pin-mismatch test, never migrated onto
   `boot_federated_pair` — see above) — deleted, and `boot_federated_pair`'s pin logic simplified
   back to always pinning B's own domain now that the field is gone; (3) three stale doc comments
   left over from the extraction, pointing at names that no longer exist in-file
   (`federation_route.rs`'s `org_b_federation` reference, `federation_timeouts.rs`'s
   `mint_identity` reference, `two_orgs_walkthrough.rs`'s `TwoOrgs` reference) — all three
   corrected to name the actual current helpers; (4) this Deliverables section's flat API sketch
   didn't match what was built — corrected above.
2. A mid-task interruption (an earlier automated pass hit a session/API failure partway through)
   left 2 of the 11 files (`session_connect_federation.rs`, `two_orgs_walkthrough.rs`)
   un-migrated while the other 9 were already done; completed by hand afterward following the
   pattern the interrupted pass had already established (including a `boot_federated_pair_
   bidirectional()` helper it had pre-built in `apps/cli/tests/support/mod.rs` specifically
   anticipating these two files). Both review passes gave the hand-finished portions the same
   scrutiny as the rest and found no divergence in quality or fidelity.

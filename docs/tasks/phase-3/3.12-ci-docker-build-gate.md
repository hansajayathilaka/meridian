# 3.12 — Build the rendezvous image pre-merge (and run what we think we run)

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F12 + the unscheduled `--ignored` runner) · **Depends on:** — · **Status:** **done** — pre-merge docker build gate + scheduled capacity runner landed; branch-protection TODO left open pending human verification (see Outcome)

## Goal
The Dockerfile + entrypoint (privilege drop, chown, coturn logic) must be validated **before** merge,
and a scheduled runner must exist for the `#[ignore]`d capacity test.

## Scope
- **In:** a build-only `docker build -f apps/rendezvous/Dockerfile .` step in `ci.yml`; optionally a
  `docker run` smoke asserting bind + privilege drop; a scheduled job running
  `cargo test -p meridian-rendezvous -- --ignored`; verify branch protection actually gates the
  publish (closes `docs/operations/docker-image.md`'s branch-protection `TODO: confirm`).
- **Out:** publishing/signing (3.19's ADR decides that); a `demo/two-orgs` CI smoke (deferred — the
  report judges docker-only/human-run acceptable).

## Deliverables
1. `.github/workflows/ci.yml` — a new docker build job.
2. A scheduled workflow (or `schedule:` trigger) for the `--ignored` runner.
3. `docs/operations/docker-image.md` — the branch-protection TODO resolved with the **observed**
   setting, not an assumed one.

## Risks / notes
- This repo's recurring failure mode is **gates that cannot fail** (1.12, 1.28, 1.32, 2.16). The
  acceptance criterion is therefore two-part: the job passes on its own PR, **and** a
  deliberately-broken-Dockerfile trial run is recorded in the Outcome proving it goes red.
- `docker build` in CI needs no registry credentials (build-only, no push) — keep it that way so the
  gate cannot leak the publish credential.

### Landed

1. **`.github/workflows/ci.yml` — `docker-build` job** (`needs: lint`, runs in parallel with
   `test`/`build`/`supply-chain`/`docs`, same pattern as the existing independent jobs):
   - `docker/build-push-action@v6` with `push: false`, `load: true` — builds
     `apps/rendezvous/Dockerfile` on every PR, no push, and **no registry credential of any kind**:
     no `docker/login-action` step, no `packages: write` permission (the job's `permissions:` block
     only grants `contents: read`). This was a deliberate choice per the task's Risks note — the
     gate must never become a second path that can leak the `docker-publish.yml` publish
     credential.
   - A `docker run` smoke test: starts the built image with a `/data` named volume and the same
     `MERIDIAN_RENDEZVOUS_SERVER__*` env vars the real deploy compose files use, waits on the
     image's own `HEALTHCHECK` (so the `HEALTHCHECK` instruction itself is exercised, not just the
     server), then asserts three things the entrypoint is responsible for:
     - `curl /healthz` succeeds (the server actually bound and answers).
     - **PID 1's uid is 10001 (`meridian`), read from `/proc/1/status`** — not from a fresh
       `docker exec ... whoami`, which was checked locally first and found to be misleading: a new
       `exec` session defaults to root regardless of what the entrypoint's own exec'd process runs
       as, since the image has no `USER` instruction (by design — root only exists so
       `docker-entrypoint.sh` can `chown /data` before dropping via `gosu`). Reading `/proc/1/status`
       is the only way to check the uid of the process the entrypoint actually exec'd.
     - `/data` is owned by `meridian`, not `root` (proves the entrypoint's `chown -R meridian:meridian
       /data` ran).
   - A `cleanup` step (`if: always()`) removes the container and volume regardless of pass/fail.

2. **`.github/workflows/capacity-check.yml` — scheduled runner for the `--ignored` capacity test.**
   `schedule:` cron (weekly, Monday 06:00 UTC — `TODO: confirm` desired cadence; nothing in
   `docs/operations/` specifies one, and there's no on-call rotation yet to action a red run per
   `runbook.md`'s own TODO) plus `workflow_dispatch:` for manual runs. Raises `ulimit -n 20000`
   (GitHub-hosted runners' default soft limit is far below what `preflight_fd_limit` in
   `apps/rendezvous/tests/rendezvous.rs` requires for a 5k-connection run: `target * 2 + 64` fds),
   then runs exactly the invocation the test's own doc comment names:
   ```
   cargo test --release -p meridian-rendezvous -- --ignored capacity
   ```
   **Confirmed this is the right invocation, not just `-- --ignored`** (the task's phrasing): a
   plain `--ignored` filter would *also* pick up `federation_discovery.rs`'s
   `airgap_probe_static_map_resolve`, a **different** `#[ignore]`d test in the same package (task
   2.x's air-gap DNS tripwire) that is explicitly meant to be invoked only as an `LD_PRELOAD`
   subprocess by its own harness (`static_map_resolve_makes_zero_getaddrinfo_calls`), not run
   directly — its own doc comment says "do not run directly." The `capacity` substring filter
   scopes the scheduled job to exactly `capacity_concurrent_connections` and nothing else, in every
   test binary in the package. Verified by running both filters locally.
   - **Bonus finding, not required by this task but worth recording:** this session's sandbox has a
     20000 hard fd limit (vs. the 4096 hard limit task 1.19 hit), so
     `cargo test --release -p meridian-rendezvous -- --ignored capacity` actually **passed at the
     full 5,000-connection target** here — `1 passed` in 2.43s. This doesn't retroactively "prove"
     5k on a GitHub-hosted runner (task 1.19's spec note in
     `docs/architecture/features/02-rendezvous-mvp.md` stays as-is; a GH-hosted runner's fd limits
     are a separate environment this scheduled job will now actually characterize on a cadence,
     once cadence is confirmed), but it does confirm the invocation and the preflight check both
     work correctly end-to-end when the fd budget is available.

### The deliberately-broken-Dockerfile trial run (non-vacuity proof)

Per this task's own Risks note ("gates that cannot fail" — 1.12, 1.28, 1.32, 2.16), the acceptance
criterion is two-part: the job passes on the real Dockerfile, **and** a deliberately-broken trial
run is recorded proving it goes red. Both were run locally (this sandbox has no direct Docker
Engine internet egress by default — see the environment note below — but the break/revert trial
itself needed no network at all, since it fails at the `COPY` step before any network-dependent
`RUN`):

**1. Baseline (green).** `git diff apps/rendezvous/Dockerfile` clean, ran the actual multi-stage
build (network access provided via this sandbox's documented proxy workaround — irrelevant to real
CI, where GitHub-hosted runners have direct internet and the plain
`docker build -f apps/rendezvous/Dockerfile .` command runs with no modification needed) — full
`cargo build --release -p meridian-rendezvous --features sqlite` succeeded, image built, and the
exact smoke-test script now embedded in `ci.yml`'s `docker-build` job was run against it and passed:
```
health status: healthy
PID 1 uid inside container: 10001
/data owner: meridian
ok
SMOKE TEST PASSED
```

**2. Deliberate break.** Edited `apps/rendezvous/Dockerfile` line 8, changing
```diff
-COPY . .
+COPY ./this-path-does-not-exist .
```
and ran the exact gate command, `docker build -f apps/rendezvous/Dockerfile .` (plain, no proxy
workaround needed — the break is caught before any network call):
```
#11 [build 3/4] COPY ./this-path-does-not-exist .
#11 ERROR: failed to calculate checksum of ref ...: "/this-path-does-not-exist": not found
------
 > [build 3/4] COPY ./this-path-does-not-exist .:
------
Dockerfile:8
--------------------
   6 |     FROM rust:1-slim AS build
   7 |     WORKDIR /src
   8 | >>> COPY ./this-path-does-not-exist .
   9 |     ...
--------------------
ERROR: failed to build: failed to solve: failed to compute cache key: ...
```
Exit code `1`. **The gate goes red on a broken Dockerfile.**

**3. Revert.** `git checkout -- apps/rendezvous/Dockerfile`, then confirmed byte-identical to the
pre-break copy (`diff` against a backup taken before the edit: no output). `git status --porcelain
apps/rendezvous/Dockerfile` clean.

### Environment note (this session only, not a repo change)

This sandbox's Docker Engine has no direct internet egress — only this session's outbound HTTPS
proxy does, and containers can't reach `127.0.0.1:35833` or trust its re-terminated TLS CA by
default (documented at `/root/.ccr/README.md`, "docker build / docker run" section). Validating the
**actual, unmodified** `apps/rendezvous/Dockerfile`'s full `cargo build` end-to-end locally required
a throwaway, **never-committed** local variant (`--network host` plus a CA-trust/proxy-env shim
added only in a scratch copy) purely to get past this sandbox's own network isolation — it changed
nothing about the multi-stage structure, the `COPY` paths, or the entrypoint logic being validated,
and it never touched the committed `Dockerfile`. GitHub-hosted CI runners have direct internet
access, so `ci.yml`'s `docker-build` job needs no such workaround and runs the file exactly as
committed. All scratch files (`Dockerfile.localtest`, `ca-bundle.crt`) and test images/containers
were removed before finishing; `git status --porcelain` is clean of anything but the intended diff.

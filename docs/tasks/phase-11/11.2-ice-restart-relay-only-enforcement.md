# 11.2 — Enforce relay-only on `ice_restart`'s freshly-gathered candidates

**Phase:** 11 — Review of Phase 10 · **Feature:** review fix (F2) · **Depends on:** 11.1 (soft) · **Status:** pending

**User surface:** none — internal defense-in-depth hardening of the existing `ice_restart` signaling
path; no new client-visible behavior, so no TUI surface applies (Definition of Done gate 9).

## Goal
Close the fail-closed relay-only gap in `ice_restart`'s signaling path so a freshly-gathered non-relay
candidate can never leave the process under `IcePolicy::RelayOnly`, matching the guarantee the original
dial/answer handshake already enforces.

## Scope
- **In:** `apps/core/src/session.rs`'s `restart_offer_and_await_answer` and `answer_restart_offer` — add
  `enforce_relay_only(self.policy, &ice)?` immediately after each `candidate_strings(...)` call, before
  sealing/sending, mirroring the two existing call sites in the original handshake exactly (same
  fail-closed teardown semantics).
- **Out:** no change to `enforce_relay_only` itself, `IcePolicy`, or any other `ice_restart` behavior (the
  layered fingerprint check, the glare tie-break, `RESTART_GLARE_WINDOW`).

## Deliverables
1. `enforce_relay_only(self.policy, &ice)?` added in both `restart_offer_and_await_answer` and
   `answer_restart_offer`, right after their respective `candidate_strings(...)` calls.
2. New test exercising `ice_restart` under `IcePolicy::RelayOnly` with a transport stub/test double that
   injects a non-relay (host/srflx) candidate into the post-restart gather, asserting the call returns
   `SessionError::RelayOnlyViolation` and that nothing reaches `relay.send_tolerant`.

## Risks / notes
Not exploitable today only because the real backend sets `RTCIceTransportPolicy` once at construction and
never recreates the `RTCPeerConnection` on restart — this fix is defense-in-depth against exactly the
kind of transport-layer assumption drift the original check already refuses to trust (the existing F20
precedent). Keep the same `SessionError` variant and error text style as the original two call sites.

Soft-depends on 11.1: same file (`session.rs`), no functional overlap (different functions) — ordered
after purely to avoid rebase churn on a shared file.

## Tests
`cargo nextest run -p meridian-core` (existing `enforce_relay_only` unit tests plus the new
`ice_restart`-level test).

## Reviews
**security-reviewer** (mandatory — relay-only/IP-hiding is an anonymity-model "must never" invariant),
**code-reviewer**.

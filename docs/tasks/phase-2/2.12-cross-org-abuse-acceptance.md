# 2.12 — Cross-org abuse + acceptance suite (the phase exit gate)

**Phase:** 2 — Cross-Org Federation · **Feature:** T06 — Cross-Org Federation · **Depends on:** 2.6, 2.7, 2.8, 2.9, 2.10, 2.11 · **Status:** pending

## Goal
Turn Feature 06's acceptance criteria into executable gates: cross-org bundle substitution, rate
limits, allowlist/`closed` rejection, oversized envelopes, server-kill continuity, and the opacity
audit at **both** servers.

## Scope
- **In:** the A2×2 cross-org malicious-server substitution test; the abuse tests; the
  kill-either-rendezvous continuity test; the opacity audit run at both servers; wiring into
  `harnesses/mitm-sim` and CI.
- **Out:** new product behaviour. This task adds tests only — anything it uncovers becomes a bug-fix
  task or a Phase-3 finding.

## Deliverables
1. Extend the `test-tamper-hook` feature so server B can substitute a bundle **on the federated path**,
   with the same F17 discipline: `#[cfg(feature = "test-tamper-hook")]`, absent from release builds,
   runtime-gated by `allow_test_tamper`.
2. `apps/rendezvous/tests/federation_abuse.rs`; `apps/cli/tests/two_orgs_walkthrough.rs`.
3. `harnesses/mitm-sim/`: a cross-org cell —
   [threat-mitigation-matrix.md](../../security/threat-mitigation-matrix.md) names T06 as the owner of
   A2×2.
4. Opacity audit at both servers → `grep -c plaintext` = 0.
5. Continuity test: both servers killed post-setup, the P2P data channel survives — the T04 property,
   now cross-org.
6. CI wiring in `.github/workflows/ci.yml`.

## Risks / notes
- **Never weaken a security assertion to go green.** A failure here is a real defect
  ([CONTRIBUTING.md](../../../CONTRIBUTING.md) DoD).
- Must not contradict [ADR 0016](../../adr/0016-envelope-deniability.md)'s mitm-sim obligations —
  task 1.32 owns that thread; this extends it cross-org rather than forking it into a second one.
- Assert the tamper hook is **inert without the cargo feature**. This is the task-1.28 lesson:
  resolver-2 unification silently enabled `test-tamper-hook` workspace-wide, so every
  `cfg(not(feature))` guard was compiled out under `cargo test --workspace`. The package-scoped
  default-features CI step must cover federation too.
- Watch for vacuous passes — pin outcomes to specific error variants on the specific side, the way
  1.28's outcome was pinned to `Rejected(Chat(BadSignature))` on the responder.

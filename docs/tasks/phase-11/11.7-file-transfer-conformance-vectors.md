# 11.7 — Conformance vectors for Phase 10's new wire surfaces

**Phase:** 11 — Review of Phase 10 · **Feature:** review fix (F7) · **Depends on:** — · **Status:** pending

**User surface:** none — test-fixture/docs task, no production or client-visible change (Definition of
Done gate 9 doesn't apply).

## Goal
Pin this phase's new wire surfaces — the `mrd.file/1` manifest CBOR encoding, the BLAKE3 merkle chunk
framing, the resume-bitmap wire shape, the per-stream HKDF-export `info` byte layout, and
`SignalContent::IceRestartOffer`/`Answer` — into byte-fixed conformance vectors before a second client
(T11) can silently diverge from them.

## Scope
- **In:** `test-vectors/` — new fixtures for each wire shape above, generated via the repo's `xtask`
  vector-regeneration tooling following the existing `ratchet-v2.json`/`envelope-v2.json` pattern (new
  file(s) — naming decided by the architect sign-off below), plus updating `test-vectors/README.md`/
  `CLAUDE.md` to document the new file(s).
- **Out:** no change to any of the wire shapes themselves — this task locks in what already shipped in
  Phase 10, it does not modify it. Explicitly out of scope: extending the chunk wire shape with a proof
  field — if 11.8 later does that, its own task must add or amend the chunk-framing vector this task
  locks in today; that is 11.8's residual to flag, not this task's to anticipate.

## Deliverables
1. A short architect pre-check (folded into this task, matching the Phase-7 7.5 precedent) deciding: new
   vector file name(s)/grouping, and boundary-case sizes worth including (e.g. a single-leaf/empty-file
   manifest, a multi-leaf merkle proof, an all-missing vs. all-present resume bitmap).
2. New/updated `test-vectors/*.json` fixture(s) covering: `FileManifest` CBOR encoding, one `ChunkFrame` +
   its BLAKE3 leaf/merkle-proof construction, the resume-bitmap byte layout, the per-stream HKDF-export
   `info` layout (`stream_export_info`), and `SignalContent::IceRestartOffer`/`Answer` CBOR encoding.
3. `test-vectors/README.md` and `test-vectors/CLAUDE.md` updated to list the new file(s).
4. If a re-derivation test is warranted (matching the crypto conformance test pattern) rather than only
   the regenerate-and-diff self-consistency check — decide with the architect and add it if so.

## Risks / notes
`TODO: confirm` exact vector file name/grouping and boundary sizes — decide with the architect, don't
guess. No stream type currently consumes the HKDF-export primitive (N3, informational) — vector it
anyway, since it's still a pinned wire-relevant derivation, just an unused one today.

## Tests
Regenerate vectors via `xtask` and confirm no diff against committed fixtures; plus whichever crate's
`cargo nextest run` gains the new re-derivation test if one is added.

## Reviews
**architect** (mandatory — vector shape/boundary-case sign-off, matching the 7.5 precedent),
**code-reviewer**.

# 11.1 — Namespace `open_stream`'s `sid`/channel-label derivation to fix concurrent-open collisions

**Phase:** 11 — Review of Phase 10 · **Feature:** review fix (F1, blocking) · **Depends on:** — · **Status:** pending

**User surface:** none — session-substrate internal fix (`meridian-core`); no client-visible behavior
change beyond making concurrent bidirectional transfers work instead of silently corrupting, so no new
TUI surface applies (Definition of Done gate 9).

## Goal
Eliminate the deterministic `sid` collision in `P2pSession::open_stream` when both peers concurrently
open the same bidirectional stream type, so `mrd.file/1` (and any future `Bidir` stream type) can never
have two independently-opened streams bound to the same wire channel label.

## Scope
- **In:** `apps/core/src/session.rs` — `next_sid`/`open_stream`'s local counter, `stream_channel_label`'s
  derivation, and the `handle_ctrl` `Open`/`Accept` arms, which must agree with whatever new derivation
  is chosen. A short architect consult folded into this task (not a separate pre-task — the derivation is
  a small, bounded decision, not a new protocol surface) to ratify the exact namespacing scheme before
  implementation.
- **Out:** no change to the `StreamType` trait, the stream registry, or any other stream type's behavior.
  No new ADR expected (implementation-level fix to an existing substrate primitive, mirroring how task
  10.4's substrate-completion work landed without one) — if the architect judges the fix changes
  wire-visible protocol shape beyond channel-label derivation, escalate to `/adr` rather than proceeding
  silently.

## Deliverables
1. Architect-ratified namespacing scheme recorded in this task's Risks/notes (e.g. reusing the existing
   identity-key lexicographic tie-break already used for dial/answer roles and `ice_restart` glare — even
   `sid` for the smaller-key identity, odd for the larger; or an explicit originator marker folded into
   `stream_channel_label`).
2. Fix in `apps/core/src/session.rs`: `next_sid`/`open_stream`, `stream_channel_label`, and the
   `handle_ctrl` `Open`/`Accept` arms updated to agree on the same derivation on both sides.
3. Regression test proving two concurrent bidirectional `open_stream` calls (same stream type, both
   directions) never collide on `LoopbackTransport` (`apps/core/tests/p2p_session.rs`), plus an analogous
   test under `--features webrtc` confirming two `RTCDataChannel`s never bind to the same negotiated SCTP
   stream.

## Risks / notes
This is a pinned wire-shape derivation other stream types will rely on — get the architect's sign-off on
the exact scheme before writing the fix, not after. Confirm the chosen scheme doesn't affect anything
`test-vectors/` pins (no existing vector currently covers the ctrl-frame `sid` field). `TODO: confirm` the
exact namespacing scheme with the architect — do not guess it independently of that sign-off.

## Tests
`cargo nextest run -p meridian-core`; `cargo nextest run -p meridian-core --features webrtc`; the new
regression test(s).

## Reviews
**architect** (mandatory — wire-shape sign-off on the `sid`/label derivation), **security-reviewer**
(session/transport substrate — confirms the fix can't be starved/griefed by a peer racing opens),
**code-reviewer**.

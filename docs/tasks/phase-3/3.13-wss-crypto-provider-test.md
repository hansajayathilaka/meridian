# 3.13 — Test the `wss://` crypto-provider install

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F13) · **Depends on:** 3.4 (if the integration form is chosen) · **Status:** in review

## Goal
Deleting `ring::default_provider().install_default()` or the TLS feature must turn CI red, not ship a
runtime panic.

## Scope
- **In:** extract the install into a named, testable `fn install_crypto_provider()`; a unit test
  asserting `CryptoProvider::get_default().is_some()` after it runs; **preferred stronger form** — an
  integration test in `apps/cli/tests/wss_tls.rs` connecting `SignalingClient::connect` to a
  self-signed TLS WebSocket listener (reusing 3.4's `TestCa`).
- **Out:** changing TLS root selection (`native-roots` vs `webpki-roots`) — only the misleading
  *comment* is fixed, in 3.21/N3.

## Deliverables
1. The extracted `install_crypto_provider()` in `apps/cli/src/main.rs` (or `meridian-signaling`).
2. The test(s) above.

## Outcome
Extracted `install_crypto_provider()` into `apps/signaling/src/client.rs` (not `apps/cli/src/main.rs`
— `meridian-signaling` is where `SignalingClient::connect`, the sole `wss://` entry point in this
codebase, lives), called at the top of `connect()` itself rather than left for `main()` to remember —
this also closes the same latent defect for any future native binary embedding `meridian-core`
directly (e.g. a Tauri desktop backend) that main.rs's original fix didn't reach. `apps/cli/src/main.rs`'s
own install call and its `rustls` dependency were removed as redundant.

**Both test forms were built.** Unit test (`client.rs`'s `install_crypto_provider_installs_a_default`)
asserts `CryptoProvider::get_default().is_some()` after the call. Stronger/preferred form
(`apps/cli/tests/wss_tls.rs`, `test-support`-gated `SignalingClient::connect_with_test_ca_pem`) connects
through a real self-signed TLS handshake — a small TLS-terminating proxy (standing in for the reverse
proxy that terminates `wss://` in production, ADR 0008) in front of a real in-process rendezvous server,
using 3.4's `TestCa` adapted with an IP SAN (`127.0.0.1`, not a DNS name) to avoid hostname-resolution
ambiguity, since `TestCa` was built s2s-mTLS-shaped and this is a plain client TLS test.

**Mutation-check finding (important, not just a formality):** disabling `install_crypto_provider()`'s
body turns the **unit test** red (confirmed, then green again on restore) — a genuine, non-vacuous
proof. The **integration test stays green regardless**, because rustls 0.23's
`ClientConfig::builder()`/`ServerConfig::builder()` silently self-install a provider via
`CryptoProvider::get_default_or_install_from_crate_features()` whenever exactly one provider
crate-feature is compiled in — true everywhere in this workspace (only `ring`, never `aws-lc-rs`,
confirmed via `cargo tree -f "{p} {f}"`). An attempt to force genuine ambiguity via rustls's
`custom-provider` feature (scoped to `apps/cli`'s dev-dependency edge) did make the integration test
mutation-sensitive, but broke `session_demo_webrtc.rs` (ICE/DTLS) under `--features webrtc` — Cargo's
workspace-wide feature unification applied `custom-provider` to `dtls` too (a transitive dependency of
`webrtc`/`meridian-transport`, which also uses rustls internally and was relying on the same fallback,
unaudited). Reverted; documented in both files' doc comments. **Conclusion:** the unit test is the
task's actual red/green mutation-check; the integration test is retained for its independent value
(proves the full `wss://` handshake plumbing works end-to-end against a real cert) but is not, in this
workspace's dependency-feature configuration, independently sensitive to this one line.

**CI invocation:** neither test is behind a Cargo feature of `apps/cli` itself. `meridian-signaling`'s
`test-support` is requested unconditionally from `apps/cli`'s `[dev-dependencies]` (same shape as the
pre-existing `test-tamper-hook` pattern this repo's `ci.yml` already documents relying on) — it
activates automatically via dev-dependency feature unification whenever any `meridian-cli` test target
is built. `cargo test --workspace` (`ci.yml` line 52) already runs both new tests; no `ci.yml` change
needed.

**Tests:** `cargo nextest run -p meridian-signaling` 1/1; `cargo nextest run -p meridian-cli --test
wss_tls` 1/1; `cargo nextest run -p meridian-signaling -p meridian-cli` 34/34; `cargo nextest run -p
meridian-cli --features webrtc` 39/39; `cargo nextest run -p meridian-rendezvous` 160/160 (2
pre-existing `#[ignore]`s); `tools/lint-server-no-core.sh` OK. `cargo fmt` clean; `cargo clippy
--all-targets -- -D warnings` clean for `meridian-signaling` (± `test-support`) and `meridian-cli` (±
`webrtc`).

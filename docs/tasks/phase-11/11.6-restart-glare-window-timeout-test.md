# 11.6 — Make `RESTART_GLARE_WINDOW` test-overridable; cover the timeout-fallback branch

**Phase:** 11 — Review of Phase 10 · **Feature:** review fix (F6) · **Depends on:** 11.1, 11.2 (soft) · **Status:** done

**User surface:** none — coverage task with a minimal test-only hook into existing `ice_restart` logic; no
production behavior change (Definition of Done gate 9 doesn't apply).

## Goal
Prove the larger-key side's glare-window timeout-then-fallback branch in `ice_restart` actually completes
a working restart, closing the only untested branch in that method.

## Scope
- **In:** `apps/core/src/session.rs` — make `RESTART_GLARE_WINDOW` injectable (a parameter threaded
  through the relevant private helper, or a `#[cfg(test)]`-gated override) so a test can force the timeout
  deterministically, plus a new test that drives two `P2pSession`s where the larger-key side's window
  elapses with no incoming offer, asserting the fallback restart (self-offering) still completes
  successfully.
- **Out:** no change to the glare tie-break logic itself, the layered fingerprint check, or
  `RESTART_ANSWER_TIMEOUT`.

## Deliverables
1. `RESTART_GLARE_WINDOW` made test-overridable in `apps/core/src/session.rs` (exact mechanism —
   parameter vs. `#[cfg(test)]` const override — left to the implementer/reviewer, whichever is the
   smaller, least invasive change).
2. New test forcing the larger-key side's window to elapse (e.g. by delaying the smaller-key side's offer
   past a shrunk test window) and asserting both sides still converge on a working, reconnected session.

## Risks / notes
Keep the production-path default value of `RESTART_GLARE_WINDOW` unchanged — this task only adds a
test-time override, never weakens the real timeout. This is real, reachable production code, not a
theoretical branch — treat the new test as a genuine regression pin.

Soft-depends on 11.1 and 11.2: same file and same `ice_restart` area; 11.2 in particular touches the exact
functions (`restart_offer_and_await_answer`/`answer_restart_offer`) this task's new test drives through,
so landing after avoids a rebase touching the same lines twice.

## Tests
`cargo nextest run -p meridian-core`.

## Reviews
**test-engineer** (coverage-gap task), **code-reviewer**.

## Outcome
`ice_restart`'s body extracted into a new `pub async fn ice_restart_with_glare_window(..., glare_window:
Duration)`; `ice_restart` becomes a two-line forwarder using the real `RESTART_GLARE_WINDOW` constant
(unchanged, 5s). **Chosen mechanism ratified on review**: neither of the two options the Scope text named
(a private-helper parameter, or a `#[cfg(test)]`-gated override) actually works here — `pub(crate)` is not
visible from `apps/core/tests/p2p_session.rs`'s separate integration-test crate, and `#[cfg(test)]` on the
library is inactive when that crate is compiled as an external dependency — so a real `pub` sibling method
(mirroring the existing `dial`/`dial_with_config`, `answer`/`answer_with_config` precedent already in this
file) was the only mechanism that could work at all. Confirmed no doc-sync entry needed: `core-api-
contracts.md` already omits the same-shaped `dial_with_config`/`answer_with_config` siblings, so it's a
curated stable-interface list, not an exhaustive `pub` inventory.

New test drives a genuine glare-timeout-then-fallback: Bob (larger key) forced to a 50ms virtual window
via the override, Alice's real, correctly-sealed-and-fingerprinted `IceRestartAnswer` deliberately
delivered only at virtual t=500ms (`#[tokio::test(start_paused = true)]` makes the ordering deterministic,
not a wall-clock race). Traced end to end: the fallback path exercises the same real AEAD/ratchet decrypt,
eid-dedup, and layered fingerprint checks as the honest path — nothing bypassed. Assertions prove genuine
convergence (unchanged cached fingerprint, live chat in both directions afterward on the same session),
not just a bare `Ok`.

Combined test-engineer/code-reviewer pass: **PASS, zero blocking findings**. Production default and
`ice_restart`'s real-caller behavior confirmed byte-for-byte unchanged; tie-break, fingerprint check, and
`RESTART_ANSWER_TIMEOUT` confirmed untouched. `meridian-core` 172/172 (177/177 with `--features webrtc`),
clippy clean both configs.

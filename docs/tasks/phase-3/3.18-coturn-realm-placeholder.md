# 3.18 — Fix the live coturn `realm` placeholder

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F19) · **Depends on:** — · **Status:** pending

## Goal
`infra/deploy/docker-compose.yml` must stop booting coturn with the literal realm
`<CHANGE_ME — org TURN realm, e.g. turn.chat.example>`.

## Scope
- **In:** comment out the `realm=` directive in `infra/coturn/turnserver.conf:15` (matching how
  `static-auth-secret` two lines up is treated) and pass `--realm` on the command line in **both**
  compose files.
- **Out:** other coturn config review — PR #40 already swept the trailing-comment class.

## Deliverables
1. `infra/coturn/turnserver.conf`, `infra/deploy/docker-compose.yml`,
   `infra/deploy/dokploy.compose.yml`.
2. A one-line note in the deployment doc if the realm must match a domain.

## Risks / notes
- coturn consumes **everything after a directive** as its value — the same parser behaviour that
  PR #40 documented in this very file. `dokploy.compose.yml` already passes `--realm` (L78) and so is
  unaffected; `docker-compose.yml` does not, and is.
- Record the observed coturn log line showing the intended realm in the Outcome — this is the kind of
  fix that is easy to assert and hard to have actually verified.

## Tests
```
docker compose -f infra/deploy/docker-compose.yml config
docker compose -f infra/deploy/dokploy.compose.yml config
```
plus a manual `docker compose up coturn` with the realm log line recorded.

# 3.4 — Extract the shared s2s test harness (PKI + server boot)

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F18) · **Depends on:** 3.1, 3.2, 3.3 · **Status:** pending

## Goal
One `make_ca` + server-boot fixture instead of 8 (soon 11) copies — debt flagged by 2.7/2.8/2.9/2.12/2.15.

## Scope
- **In:** `apps/rendezvous/tests/support/mod.rs` and `apps/cli/tests/support/mod.rs`; migrate
  `federation_{mtls,fetch,route,abuse}.rs`, the three suites added by 3.1–3.3, and
  `apps/cli/tests/{federation_errors,federation_route_hint,session_connect_federation,two_orgs_walkthrough}.rs`;
  fold `run_federated_audit`'s duplicated session bootstrap.
- **Out:** any behaviour change, new test cases, or change to what a migrated test asserts. **Pure
  refactor — same assertions, same names.**

## Deliverables
1. Two `support/mod.rs` files exposing `TestCa::new()`, `TestCa::issue(domain)`,
   `boot_rendezvous(cfg) -> (AppState, SocketAddr)`, `boot_federated_pair()`.
2. All 11 test files migrated, each noting the fixture is dev-dep-only.

## Risks / notes
- **Must be `support/mod.rs`, not `support.rs`** — a bare `tests/support.rs` is compiled as its own
  test binary.
- Sequenced deliberately **after** the blocking gate: 3.1–3.3 must not wait on an 11-file refactor.
  Accepting three more `make_ca` copies for one PR window is the cheaper trade.
- Everything from 3.5 onward that adds a rendezvous/cli test uses this harness — so it must land
  before them or the 12th copy appears.

## Tests
```
cargo nextest run -p meridian-rendezvous
cargo nextest run -p meridian-cli
cargo test -p meridian-rendezvous --features test-tamper-hook
bash tools/lint-server-no-core.sh && bash tools/lint-server-no-core.sh --selftest
```
The lint run matters: it confirms the harness's dev-deps stay out of the `-e normal` graph, i.e.
server ⊬ core still holds.

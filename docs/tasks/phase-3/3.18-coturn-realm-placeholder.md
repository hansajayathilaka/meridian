# 3.18 — Fix the live coturn `realm` placeholder

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F19) · **Depends on:** — · **Status:** done

## Goal
`infra/deploy/docker-compose.yml` must stop booting coturn with the literal realm
`<CHANGE_ME — org TURN realm, e.g. turn.chat.example>`.

## Scope
- **In:** comment out the `realm=` directive in `infra/coturn/turnserver.conf:15` (matching how
  `static-auth-secret` two lines up is treated) and pass `--realm` on the command line in **both**
  compose files.
- **Out:** other coturn config review — PR #40 already swept the trailing-comment class.

## Deliverables
1. `infra/coturn/turnserver.conf`, `infra/deploy/docker-compose.yml`,
   `infra/deploy/dokploy.compose.yml`.
2. A one-line note in the deployment doc if the realm must match a domain.

## Risks / notes
- coturn consumes **everything after a directive** as its value — the same parser behaviour that
  PR #40 documented in this very file. `dokploy.compose.yml` already passes `--realm` (L78) and so is
  unaffected; `docker-compose.yml` does not, and is.
- Record the observed coturn log line showing the intended realm in the Outcome — this is the kind of
  fix that is easy to assert and hard to have actually verified.

## Tests
```
docker compose -f infra/deploy/docker-compose.yml config
docker compose -f infra/deploy/dokploy.compose.yml config
```
plus a manual `docker compose up coturn` with the realm log line recorded.

## Reviews
- **devops** · **code-reviewer**.

## Outcome
Commented out `turnserver.conf`'s live `realm=<CHANGE_ME ...>` directive (matching the
`static-auth-secret` precedent two lines above) and added `--realm=${TURN_DOMAIN:-turn.example.com}`
to `infra/deploy/docker-compose.yml`'s coturn command (it previously passed no `--realm` at all).
`dokploy.compose.yml` already passed `--realm` correctly and was left untouched. Added a one-line
deployment.md note (§9.3a) explaining the realm has no cryptographic match requirement with
rendezvous's `MERIDIAN_RENDEZVOUS_TURN__REALM` (confirmed against `apps/rendezvous/src/turn.rs`:
realm is echoed to the client, not part of the HMAC computation), but both compose files derive it
from the same `TURN_DOMAIN` var for operator consistency.

Observed coturn startup log confirming the fix (`docker compose -f infra/deploy/docker-compose.yml
up coturn`, `TURN_SHARED_SECRET` set to a dummy test value):
```
INFO Default realm: turn.example.com                    # TURN_DOMAIN unset, default fallback
INFO Default realm: turn.myorg.example                   # TURN_DOMAIN=turn.myorg.example
```
No `CHANGE_ME` placeholder observed in either run; `dokploy.compose.yml`'s coturn boots with its
pre-existing `--realm` intact and unaffected.

Reviews: code-reviewer — **pass**, no blocking findings (reproduced the same log-line verification
independently before this Outcome was written). devops — **pass**, no blocking findings; reran the
verification with an overridden `TURN_DOMAIN` and confirmed `dokploy.compose.yml` resolves
independently with its own required vars. One non-blocking observation (docs/deployment.md's
"both compose files key off `TURN_DOMAIN`" note doesn't hold for `docker-compose.yml`'s rendezvous
side today, since that service's `environment:` block is a pre-existing commented-out scaffold
stub, unrelated to this task) — not fixed, out of this task's scope per its own "Out" line.

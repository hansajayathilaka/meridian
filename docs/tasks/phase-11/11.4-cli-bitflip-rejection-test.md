# 11.4 — Real-CLI-path bit-flip rejection test

**Phase:** 11 — Review of Phase 10 · **Feature:** review fix (F4) · **Depends on:** 11.3 (soft) · **Status:** done

**User surface:** none — coverage-only task, no production code change expected (Definition of Done
gate 9 doesn't apply).

## Goal
Prove the real `meridian send` CLI receive path actually rejects a bit-flipped chunk end to end, closing
the gap between the module doc's claim and what's actually tested at the shipped layer.

## Scope
- **In:** `apps/cli/src/send.rs` — add a test variant of
  `send_and_receive_round_trip_over_loopback_is_byte_identical` that flips one ciphertext byte in one
  `tagged_chunk_frame` (reusing `corrupted_chunk_adversarial.rs`'s real-sealing-then-flip technique) and
  asserts `run_responder`/`finalize_transfer` return an authentication error (the
  `open_chunk(...).map_err(...)` branch) with no output file ever created.
- **Out:** no production code change expected — this is a coverage-only task. If the new test surfaces a
  real defect, fix it genuinely (never weaken the assertion to pass) and flag the fix as an unplanned but
  necessary addition to this task's scope.

## Deliverables
1. New test in `apps/cli/src/send.rs` (e.g.
   `a_bit_flipped_chunk_is_rejected_and_the_file_is_never_written`), following the existing round-trip
   harness's setup but corrupting one real, sealed chunk frame's ciphertext byte before it's sent,
   asserting on both the returned error and the absence of any file in the output directory.

## Risks / notes
Keep the injection point at the same layer `corrupted_chunk_adversarial.rs` uses (mutate the real sealed
frame bytes after `send_chunk_frame`'s real construction, not a `Transport`-level proxy) so the test
exercises `FileReceiver`/`open_chunk`'s AEAD check specifically, not the outer ratchet AEAD.

Soft-depends on 11.3: touches the same `run_responder`/`finalize_transfer` functions 11.3's N1 fix
touches — landing after avoids rebase churn on the same functions.

## Tests
`cargo nextest run -p meridian-cli`.

## Reviews
**code-reviewer**, **test-engineer** (coverage-gap task — its sole deliverable is a test).

## Outcome
Added `corrupted_tagged_chunk_frame` (mirrors `corrupted_chunk_adversarial.rs`'s real-sealing-then-flip
technique) and `a_bit_flipped_chunk_is_rejected_and_the_file_is_never_written` to `apps/cli/src/send.rs`'s
test module. The corrupted frame crosses a genuine outer ratchet seal/open via `P2pSession::send_stream_frame`/
`pump()` before reaching `finalize_transfer`'s `open_chunk` AEAD check — confirmed by tracing the actual
call path (`FileStream::on_frame` just buffers raw bytes, no AEAD of its own) and by the test itself
passing rather than failing earlier at the ratchet layer. Asserts both `run_responder`'s aggregate error
and, more precisely, a direct `finalize_transfer` call's error text ("failed to authenticate", confirmed
the unique string for exactly the `open_chunk` branch, distinct from decode/merkle/overflow errors), plus
a real filesystem check that no output file is ever created. No production defect found; pure
coverage-only addition, nothing outside `#[cfg(test)]` touched.

Combined code-reviewer/test-engineer pass: **PASS, zero blocking findings**. One cosmetic nit (stray
whitespace in an `.expect()` message) fixed in the same commit. `meridian-cli` 92/92 (98/98 with
`--features webrtc`), clippy/fmt clean.

# 5.11 — Extract shared `observe_into_live_trust` helper

**Phase:** 5 — Review of Phase 4 · **Feature:** review fix (N1) · **Depends on:** — · **Status:** done

## Status

Extracted `App::observe_into_live_trust(&mut self, main_idx: usize, pubkey: [u8; 32], hint: &str, at:
u64)` in `apps/tui/src/app.rs` (placed between `App::reclaim_trust` and `App::apply_accepted_request`).
It contains exactly the `live_trust_idx` stack-walk-and-dispatch block that was duplicated verbatim
between `App::apply_accepted_request` and `App::apply_added_contact`: scan `self.screens[main_idx +
1..]` for the first `Screen::Chat`/`Screen::Verify`, and route `trust.observe(pubkey, hint, at)` there
if found, else onto `Screen::Main` at `main_idx` directly (a no-op if `main_idx` no longer names a
`Screen::Main`, mirroring the old inline code's own defensive `let Some(...) else { return; }`).

Both call sites now compute their own `main_idx` (as before — each still needs it afterward for its own
post-observe steps: `main.chat.accept_request` + `contacts::apply_update` in
`apply_accepted_request`; `contacts::apply_update` + `main.contacts.add = None` in
`apply_added_contact`) and call `self.observe_into_live_trust(main_idx, added.pubkey, "",
added.added_at)` in place of the removed ~20-line block. Doc comments on both methods were trimmed to
reference the new helper's own doc comment instead of re-deriving the "moved, not cloned" / `Ctrl-R`
interleaving reasoning twice; no doc content describing behavior was dropped, only relocated to the one
place it now lives.

**No behavioral subtlety found between the two original call sites' stack-walk-and-observe blocks** —
they were byte-for-byte identical (same `main_idx + 1..` scan, same `Chat`/`Verify` match arms, same
`unreachable!` message, same `""` hint literal — not `added.hint`, in either — and same
`added.added_at` timestamp argument). The only differences between the two methods are *after* this
block (accept-request bookkeeping vs. add-contact bookkeeping plus the 4.46 interleaving-gap fix), which
were left untouched and are outside the extracted helper. `AddedContact::hint` (a display-only String
field, distinct from the `""` literal both call sites pass to `observe`) was not threaded through the
helper's `hint` parameter — the parameter exists per the task's suggested signature and both current
callers happen to pass `""`, but nothing forces that; a future caller can pass a real hint without
changing the helper.

### Review round
**reviewer** (security-reviewer + code-reviewer combined pass) — **PASS on both lenses, no blocking
findings.** Independently re-traced both original call sites line-by-line against the diff's removed
code (not just trusting this Status section) and confirmed the extraction is genuinely
behavior-preserving: no mutation of `self.screens` occurs between computing `main_idx` and the helper
call in either caller, so no reordering/stale-index risk was introduced by moving the block into a
method call. Confirmed the `Chat`/`Verify` match arms and `unreachable!` invariant were copied verbatim.
One **non-blocking** observation: `AddedContact::hint` is a real field that neither call site threads
into `observe_into_live_trust`'s `hint` parameter (both pass `""`) — confirmed via the diff this is a
**pre-existing quirk carried over unchanged**, not something this refactor introduced (the removed
inline code already used the `""` literal at both sites). Left as-is per this task's Scope (pure
refactor, no behavior change); worth a small future task to decide whether `added.hint` should flow
through or the parameter should be dropped, but not blocking 5.11.

## Goal
Collapse the ~20-line stack-walk-and-`trust.observe` dispatch logic duplicated verbatim between
`App::apply_accepted_request` and `App::apply_added_contact` into one shared helper. This exact
reconciliation logic has been the source of three real defects this phase (4.42, 4.45, 4.46) — worth
de-duplicating before a fourth caller appears and the two copies drift.

## Scope
- **In:** `apps/tui/src/app.rs::apply_accepted_request` (lines ~2215–2249) and `::apply_added_contact`
  (lines ~2302–2343) — extract a shared `fn observe_into_live_trust(&mut self, main_idx, pubkey, hint,
  at)`.
- **Out:** Any behavior change — this is a pure refactor; both call sites must behave identically to
  before.

## Deliverables
1. The shared helper, called from both existing sites.
2. Existing coverage (`accept_to_chat.rs`, `run_worker_contacts.rs`, `screens_contacts.rs`) passes
   unchanged — no new test is required if the extraction is behavior-preserving, but re-run the full
   suite to confirm.

## Risks / notes
This is security-adjacent code (trust-state reconciliation) — even though it's a pure refactor, give it
a real review pass, not a rubber stamp, given its defect history.

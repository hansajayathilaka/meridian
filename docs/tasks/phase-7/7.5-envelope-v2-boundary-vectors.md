# 7.5 — Boundary-case conformance vectors for `envelope-v2.json`

**Phase:** 7 — Review of Phase 6 · **Feature:** review fix (F7) · **Depends on:** — · **Status:** pending

## Goal
Add boundary-shape vectors to `test-vectors/envelope-v2.json` beyond the existing three
near-identical-`ct` cases, so the conformance suite exercises edge shapes, not just one canonical case.

## Scope
- **In:** `tools/xtask/src/vectors/envelope.rs`'s `generate_envelope_v2` — add to the `cases` list:
  1. An empty-`ct` boundary case (`ct: vec![]`).
  2. A large-`ct` boundary case, paired with the existing maximal-preamble shape (`prekey-with-opk`
     already covers the largest *preamble* variant, since `Prekey`'s fields are fixed-width 32-byte
     arrays — there's no smaller/larger preamble shape to add; the genuinely untested boundary is `ct`
     length). `TODO: confirm` with architect: no design doc specifies a maximum envelope/`ct` size —
     propose a representative "large" size (e.g. 65535 bytes) rather than inventing one silently; get
     architect sign-off on the exact byte count before regenerating.
  Regenerate via `cargo run -p xtask -- vectors`; the existing three vectors must stay byte-identical
  (confirm via `git diff`) — only new vectors are added.
- **Out:** `tools/xtask/src/vectors/ratchet.rs`/`ratchet-v2.json` — F7's finding names only
  `envelope-v2.json`/`envelope.rs`; `ratchet-v2.json` already varies its preamble per-step and has no
  analogous thin-coverage gap. If broader `ratchet.rs` vector coverage turns out to be warranted, that's
  a scope expansion beyond this finding and belongs in a future review, not silently folded in here.

## Deliverables
1. Updated `generate_envelope_v2` with the two new cases.
2. Regenerated `test-vectors/envelope-v2.json`.

## Risks / notes
The `TODO: confirm` on the large-`ct` byte count is a real open question, not a rubber-stamp — get
architect sign-off on the specific size before regenerating, not after.

## Tests
`cargo run -p xtask -- vectors && git diff --exit-code test-vectors/envelope-v2.json` (should show only
additions), then `cargo nextest run -p meridian-crypto --test conformance` (the independent-re-derivation
consumer of `envelope-v2.json`).

## Reviews
**architect** (mandatory — the `TODO: confirm` on vector size needs a decision, and conformance-vector
changes are wire-critical) + **code-reviewer**.

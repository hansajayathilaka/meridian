# 4.31 — Real `run_worker`: contacts & contact-detail persistence

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client (gap closure) · **Depends on:** 4.19 · **Status:** pending

## Goal
Execute `AddContact`/`ImportContactQr`/`SetPetname`/`SetUserBlocked`/`SetPolicyOverride`/`DeleteContact`
for real, so the Contacts and Contact Detail screens' actions actually persist.

## Scope
- **In:** `run_worker` arms for these six effects, mirroring `apps/cli/src/contact.rs::cmd_add`/
  `cmd_rename`/`cmd_block` and — direct prior art — `apps/tui/tests/at_rest_audit.rs`'s own hand-rolled
  worker logic for this exact group (same `TrustStore::observe` → conditional `set_petname` order, same
  "read the real post-`observe` `Contact` back, never assume a fresh-TOFU shape" discipline
  `AddedContact`'s own doc comment already requires).
- **Out:** navigation (Contacts/ContactDetail screens already push/pop correctly once reached — reaching
  them live is 4.36/4.37's job).

## Deliverables
1. Six `run_worker` arms: `AddContact`, `ImportContactQr`, `SetPetname`, `SetUserBlocked`,
   `SetPolicyOverride`, `DeleteContact`.
2. Tests per effect against a real temp store, including the re-add-of-already-known-contact edge case
   `AddedContact`'s own doc comment calls out explicitly (must not regress TOFU state or petname on a
   duplicate add).

## Risks / notes
- **Petname is never derived from wire content** — reconfirm this worker path only ever writes the
  petname the screen already validated locally, never anything sourced from the peer.
- No dependency on 4.29, 4.30, or any other task in this gap-closure set — independently testable today.

## Tests
`cargo nextest run -p meridian-tui --test run_worker_contacts` (new file).

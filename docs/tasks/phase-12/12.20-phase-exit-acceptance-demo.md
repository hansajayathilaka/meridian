# 12.20 — Phase exit: acceptance demo + doc sync

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 (phase-exit gate) · **Depends on:** 12.16,
12.17, 12.18, 12.19 · **Status:** pending

**User surface:** none new — this task verifies, it doesn't add. No TUI surface applies (T11 as a whole
has none, per this phase's own architect-consult note).

## Goal
Run the feature spec's own demo script end to end for real and record the result honestly, mirroring
Phase 10's 10.17/10.24 and Phase 8's 8.14 precedent — including their willingness to spin off a
gap-closure fix-task (as Phase 10 did with 10.19–10.24) rather than silently downgrade a real finding to
a pass.

## Scope
- **In:** run the spec's demo script live — `docker compose -f demo/two-orgs up`, browser account
  creation (WebCrypto key non-extractable, confirmed live not just asserted), CLI↔browser chat + a
  200 MB file transfer, safety-number QR verification matching on both sides, a signed-MSI install +
  updater-rejects-tampered-update test on a real Windows VM/runner, the 9/9 interop matrix (12.17), and
  the byte-identical conformance-vector check (12.18) all passing; measure the real gzipped WASM bundle
  size and hard-gate it at <4 MB (12.10 only reported this, this task enforces it); sync
  `docs/tasks/phase-12/README.md`'s exit-criteria section and any design docs found drifted during the
  live run.
- **Out:** re-litigating any already-settled architect-consult decision (ADR 0026/0027, the wasm32
  substrate shape) — a defect found here against those decisions is a bug in the *implementation* of the
  decision, not a reason to reopen the decision itself, unless the defect reveals the decision was
  actually wrong, in which case escalate rather than deciding unilaterally in this task.

## Deliverables
1. A demo transcript (mirroring `phase-10/10.24-demo-transcript.md`'s style) capturing the actual
   commands run and their real output, not a paraphrase.
2. `docs/tasks/phase-12/README.md` — exit-criteria section updated with the real result (PASS, or a
   recorded blocking finding per the Phase-10-precedent handling below).
3. Any doc-sync fixes for drift found live.

## Risks / notes
If a real, live defect is found (mirroring Phase 10's `ice_restart` no-op discovery at its own first
exit-gate attempt), this is recorded as a **phase-exit-blocking finding, not silently downgraded to a
pass** — the phase stays open until a gap-closure task lands and this exit gate is re-run clean, exactly
as Phase 10's README itself did. Do not lower the acceptance bar (e.g. accepting a >4 MB bundle, or
skipping the real Windows-VM updater test in favor of a weaker proxy) to make this task pass artificially.

## Tests
The full demo script itself, run live: `docker compose -f demo/two-orgs up`, the CLI↔browser↔desktop
walkthrough, `bash harnesses/interop-matrix/run.sh`, `bash harnesses/cross-client-conformance/run.sh`,
plus `cargo build --workspace`, `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --
-D warnings`, and every touched crate/package's own test suite (Rust + `pnpm`) run clean.

## Reviews
**reviewer** (combined pass: code-reviewer + security-reviewer + architect lenses, matching the Phase
10/Phase 8 exit-gate precedent for a whole-phase closing gate).

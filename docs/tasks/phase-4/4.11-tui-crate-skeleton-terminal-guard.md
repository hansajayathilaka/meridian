# 4.11 — `apps/tui` crate skeleton + terminal guard

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client · **Depends on:** 4.1 · **Status:** pending

## Goal
Stand up the `meridian-tui` crate with its Elm-style runtime split and terminal-restoration guard —
first, per the feature spec's own risk note, because a crash that leaves raw mode on is the single most
damaging bug class in a TUI.

## Scope
- **In:** new `apps/tui` crate per ADR 0020: `App` owning all state, synchronous pure `update`, pure
  `render`, screen stack; event loop over `crossterm` events + a tokio worker channel + 250ms tick
  ([tui-client.md §4](../../architecture/tui-client.md#4-runtime-structure)); `Effect` as the only path
  to network/keystore/disk, executed by a worker task reporting back as `AppEvent`; RAII terminal guard
  (raw mode + alternate screen) whose `Drop` restores them, installed with a panic hook and
  `SIGINT`/`SIGTERM` handler.
- **Out:** any screen content (4.16+); config/store (4.14/4.15); the `meridian tui` subcommand wiring
  itself (4.12, though this crate is what it wires to).

## Deliverables
1. `apps/tui/src/app.rs` (or equivalent): `App`, `AppEvent`, `Effect`, `update`, `render` skeleton
   (screens are empty/placeholder at this point).
2. `apps/tui/src/terminal.rs`: RAII guard + panic hook + signal handler.
3. **Panic-restores-terminal test** — force a panic mid-render, assert raw mode and alternate screen are
   undone. Ships in this task per the spec's explicit risk note.

## Risks / notes
- **Terminal restoration is a reliability invariant, not a nicety** — this is why it ships with its own
  test in the very first task rather than being folded into a later one.
- `render` and `update` must never await or perform I/O — this is what makes `ratatui::backend::TestBackend`
  snapshot testing possible for every later screen task.

## Tests
`cargo nextest run -p meridian-tui`

## Reviews
- **security-reviewer** — required; terminal-restoration is called out as a reliability invariant with
  its own test obligation.
- **test-engineer** — required; the panic-restoration test is adversarial in shape (force a panic, assert

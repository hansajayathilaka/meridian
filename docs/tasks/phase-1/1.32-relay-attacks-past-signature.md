# 1.32 — Relay attacks that PASS the envelope signature check

**Phase:** 1 — Review of Phase 0 · **Feature:** on-the-fly (surfaced by 1.28's security review) ·
**Depends on:** 1.28 · **Status:** **done** — [PR #32](https://github.com/hansajayathilaka/meridian/pull/32)

## Goal
Cover the malicious-relay attacks that 1.28 does **not** reach. 1.28's byte-level rewrite is stopped at
the Ed25519 signature check — provably so: `MessageEnvelope` has four fields and `signing_input` covers
`sender_pub + prekey + ct`, with `sig` the remainder, so *every* byte is either signed or is the
signature and any mutation fails CBOR decode or `verify`. That means the ratchet AEAD, the skipped-key
store, and the §4.6 DTLS-fingerprint cross-check are **never exercised by a hostile relay** today.

A routing-only relay has strictly stronger attacks that need **no key material** and **do** pass the
signature check:
1. **Forged `Deliver.from`** — the server sets this field itself (`apps/rendezvous/src/ws.rs`
   `handle_route`), so forging it is free. Probes `ChatError::SenderMismatch` in
   `apps/core/src/chat.rs`, which no test currently drives from a hostile server.
2. **Replay** of a previously-delivered blob.
3. **Reorder / drop / delay.** (Delivered with a scope correction the test-engineer review made
   explicit: *delay* is the degenerate case of reorder **for ordering only** — a delayed-but-in-order
   message is indistinguishable from an honest one to a ratchet, so a `delay` flag would just be the
   honest control. The one observable delay attack is aging past `PREV_GENERATION_GRACE_SECS`, which
   is **not** covered and is recorded as frontier item 6 in `harnesses/mitm-sim/README.md`.)
4. **Cross-delivery** of a valid envelope from a different session.
All four are implementable in the `test-tamper-hook` with byte-level buffering only — no envelope
construction, which the server cannot do (no `meridian-envelope` dependency, no ratchet state).

## Scope
- **In:** extend `test-tamper-hook` with the above modes (each independently gated); harness cells
  asserting each fails closed and is diagnosable; assert the anti-DoS property that already holds —
  a rejected prekey envelope consumes **no** OTK and installs **no** session, since `open_bytes`
  verifies the signature before `take_otk_secret`.
- **Out:** production code paths; anything requiring the server to construct or sign an envelope.

## Risks / notes
Fold this into **one** thread with [ADR 0016](../../adr/0016-envelope-deniability.md)'s test
obligations, which already require preamble-mutation mitm-sim cells (`used_opk`→`None`,
`used_opk`→another held OTK, `used_spk`→previous generation) and record that preamble mutation is an
untested gap **even in v1**. Do not file two overlapping efforts. Note the recorded tension in ADR
0016: the strategy's "0 silent successes" mitm-sim invariant must be re-scoped to "outside the

## Status — done

### What landed
- **`apps/rendezvous/src/route_tamper.rs`** (new, `#[cfg(feature = "test-tamper-hook")]`) — the
  byte-level attack planner: `spoof_from`, `replay`, `reorder`, `drop`, `cross_deliver`, plus 1.28's
  `rewrite`. Operates only on `Vec<u8>` and `[u8; 32]` routing keys; constructs, decodes, signs and
  inspects nothing. 7 unit tests.
- **`apps/rendezvous/src/config.rs`** — six new `allow_test_route_*` mode flags, all `false` by
  default. `allow_test_route_tamper` becomes the **umbrella** gate and arms nothing on its own;
  1.28's byte rewrite is now `allow_test_route_rewrite`. (Fail-closed direction: a config that set
  only the old flag now tampers with nothing.)
- **`apps/rendezvous/src/ws.rs`** — `handle_route` split into a `deliver_one` helper shared by the
  honest path (the only one compiled without the feature) and the hook's multi-delivery loop; a
  withheld blob is still acked `delivered: true`, which is the lie a real dropping relay tells.
- **`apps/rendezvous/tests/rendezvous.rs`** — one inertness test per mode + an all-modes-on test
  (`#[cfg(not(feature = ...))]`), and `umbrella_flag_alone_arms_no_attack` *with* the feature. The
  CI step `cargo test -p meridian-rendezvous` (1.28) covers the *inertness* tests with no change: it
  is package-scoped and runs the whole default-feature binary. The feature-**on** tests needed a new
  CI step — see R1 under Reviews.
- **`apps/cli/tests/relay_attacks.rs`** (new) — 5 adversarial cells + a control, each against a real
  in-process server with exactly one mode armed, each pinning a specific variant on a specific side.
- **`apps/core/tests/preamble_mutation.rs`** (new) — ADR 0016's obligations: forged prekey envelope
  claiming `from = Alice`, and `used_opk`→`None` / `used_opk`→another held OTK / `used_spk`→previous
  generation. Each asserts rejection at the signature, **OTK pool depth unchanged** (counted, with a
  positive control proving the counter is sensitive), **no session installed** (whole `ChatState`
  byte-identical), and **the genuine envelope subsequently succeeds** — the anti-DoS property.
- **Docs** — `harnesses/mitm-sim/{run.sh,README.md}` (stale "still open" prose corrected, cells
  tabulated with scope boundaries), `auth.rs`'s `rewrite_routed_blob` doc, `rendezvous.example.toml`,

### Non-vacuity, verified by neutering
With `allow_test_route_tamper` forced to `false` (hook inert, honest server), **all five adversarial
cells fail** and the control still passes — each on its own attack-specific assertion, not on a
generic one: `Opened(...)` where a rejection was required (spoof_from, cross_deliver, drop), the
explicit "the hook did not actually replay anything" branch (replay), and the "the relay must
actually have swapped the two blobs" check (reorder). The preamble cells self-check the same way:
`mutate_unsigned` asserts the preamble really changed, and neutering one mutation trips it.

### Finding raised, NOT fixed (production, out of this task's scope)
**A single replayed envelope permanently poisons the receiving ratchet chain.**
`Ratchet::decrypt` (`apps/crypto/src/ratchet.rs`) advances `ckr` and `nr` *before* `aead_open` and
does not roll them back when it fails, so after one duplicate every subsequent genuine message from
that sender fails with `Crypto(Crypto)` — measured directly. That is an unauthenticated,
key-material-free, permanent session DoS mountable by any relay, and it also breaks benign duplicate
delivery. The Double Ratchet spec requires discarding state changes when decryption raises. Reported
rather than fixed (`Out:` puts production code paths out of scope) and **not** asserted either way in
the replay cell, since asserting today's behaviour would entrench it.

**Triaged (security review R7): production fix, filed as [task 2.13](../phase-2/2.13-ratchet-replay-dos.md).**
It also now has a home outside this task file — the A2/A3 rows of
[threat-mitigation-matrix.md](../../security/threat-mitigation-matrix.md) carry it as an open defect,
so it survives this phase being archived. It is a defect rather than an accepted residual because it
contradicts threat-model goal 6 ("availability degradation is honest but not silent"); recording it
as a residual instead would need explicit security-reviewer sign-off.

## Reviews — both required sign-offs obtained

**security-reviewer — APPROVE-WITH-CHANGES**, R1–R7 all applied (commit `560f895`). Hard checks 1–6
(plaintext, contact graph, identifiers/PII/push, server-asserted keys, mailbox, DTLS-SRTP binding):
no violations introduced. The two findings that changed the work:
- **R1** — the feature-**ON** half of the gate had no deterministic invocation. `route_tamper`'s unit
  tests and both runtime-gate tests are `cfg(feature = "test-tamper-hook")`, so the package-scoped
  default-features step compiles them out and mitm-sim's filtered call skips them; they ran only as a
  side effect of resolver-2 unification via `apps/cli`'s dev-dep pin. This is the same accidental
  coupling 1.28's review flagged, load-bearing in the *other* direction — dropping that pin would
  have silently stopped running every runtime-gate test everywhere. Fixed with an explicit CI step.
- **R7** — the replay/ratchet defect below needed a home outside a task file that gets archived at
  phase close.

**test-engineer — APPROVE** (3 minor corrections, all applied). It did not take non-vacuity on trust;
it re-derived it by neutering code and observing failure:
- Hook made inert → **5 of 6 cells fail, each on its own attack-specific assertion**, control passes.
- `SenderMismatch` check deleted → **exactly one** cell fails. Sensitive *and* attributive.
- Signature check stubbed → all 4 preamble cells fail with residual `Desync`: the OTK **is** consumed
  and a poisoned session **is** installed. That is the ADR 0016 C2 exposure, measured.
- Signature stubbed **and** the `BadSignature` pin loosened to `Err(_)` → the cells **still** fail, on
  the OTK-depth counter and the no-session-installed assertion. So the three anti-DoS properties are
  independently load-bearing, not redundant with the error-class pin.
- The R3 reorder addition was checked the same way: arming `replay` alongside `reorder` trips the
  no-third-delivery assert, and an injected `nr += 1` ratchet bug trips the second-pair assert while
  every pre-R3 assertion still passes — so it catches a class the earlier version missed.

Corrections applied: the CI comment's claim that `--workspace` compiles the runtime-gate tests out was
measurably false (it runs them today, via the dev-dep accident) and is now stated precisely; the
"delay is a degenerate reorder" note is qualified to *ordering only*, with grace-window aging named as
uncovered; and the hand-rolled spoof-key recomputation is now explicitly pinned to the hook so it
cannot silently go vacuous.

## Result vs acceptance criteria
All four in-scope attacks land as their own independently-gated server modes, plus 1.28's rewrite
retrofitted behind its own flag: `spoof_from` → `SenderMismatch`; `replay` → refused at the ratchet;
`reorder` → tolerated, nothing lost, forged, or duplicated, and the session keeps working;
`drop` → denial stays denial, never forgery; `cross_deliver` → `UnknownPrekey`. The anti-DoS property
is measured, not restated: OTK depth is counted out of the canonical CBOR with a positive control
proving the counter is sensitive, and the whole `ChatState` is asserted byte-identical after a
rejection. ADR 0016's preamble-mutation obligations are discharged client-side (the server has no
envelope types and cannot mutate signed bytes). Byte-level buffering only — no new dependency, and
all four invariant lints pass.

**Scope correction, recorded rather than papered over:** *delay* gets no flag, because a
delayed-but-in-order message is indistinguishable from an honest one; the one observable delay attack
is aging past the SPK grace window, which is uncovered and now named in the harness frontier list.

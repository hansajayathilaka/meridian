# 2.12 — Cross-org abuse + acceptance suite (the phase exit gate)

**Phase:** 2 — Cross-Org Federation · **Feature:** T06 — Cross-Org Federation · **Depends on:** 2.6, 2.7, 2.8, 2.9, 2.10, 2.11 · **Status:** done

## Goal
Turn Feature 06's acceptance criteria into executable gates: cross-org bundle substitution, rate
limits, allowlist/`closed` rejection, oversized envelopes, server-kill continuity, and the opacity
audit at **both** servers.

## Scope
- **In:** the A2×2 cross-org malicious-server substitution test; the abuse tests; the
  kill-either-rendezvous continuity test; the opacity audit run at both servers; wiring into
  `harnesses/mitm-sim` and CI.
- **Out:** new product behaviour. This task adds tests only — anything it uncovers becomes a bug-fix
  task or a Phase-3 finding.

## Deliverables
1. Extend the `test-tamper-hook` feature so server B can substitute a bundle **on the federated path**,
   with the same F17 discipline: `#[cfg(feature = "test-tamper-hook")]`, absent from release builds,
   runtime-gated by `allow_test_tamper`.
2. `apps/rendezvous/tests/federation_abuse.rs`; `apps/cli/tests/two_orgs_walkthrough.rs`.
3. `harnesses/mitm-sim/`: a cross-org cell —
   [threat-mitigation-matrix.md](../../security/threat-mitigation-matrix.md) names T06 as the owner of
   A2×2.
4. Opacity audit at both servers → `grep -c plaintext` = 0.
5. Continuity test: both servers killed post-setup, the P2P data channel survives — the T04 property,
   now cross-org.
6. CI wiring in `.github/workflows/ci.yml`.

## Risks / notes
- **Never weaken a security assertion to go green.** A failure here is a real defect
  ([CONTRIBUTING.md](../../../CONTRIBUTING.md) DoD).
- Must not contradict [ADR 0016](../../adr/0016-envelope-deniability.md)'s mitm-sim obligations —
  task 1.32 owns that thread; this extends it cross-org rather than forking it into a second one.
- Assert the tamper hook is **inert without the cargo feature**. This is the task-1.28 lesson:
  resolver-2 unification silently enabled `test-tamper-hook` workspace-wide, so every
  `cfg(not(feature))` guard was compiled out under `cargo test --workspace`. The package-scoped
  default-features CI step must cover federation too.
- Watch for vacuous passes — pin outcomes to specific error variants on the specific side, the way
  1.28's outcome was pinned to `Rejected(Chat(BadSignature))` on the responder.

## Outcome
Tests-only, as scoped, plus the one narrow production extension the task itself calls for:
`apps/rendezvous/src/federation/inbound.rs`'s `handle_fed_fetch` gained a `#[cfg(feature =
"test-tamper-hook")]` bundle-substitution branch (reusing `crate::auth::substitute_bundle`,
runtime-armed by the same pre-existing `allow_test_tamper` flag from task 1.28 — no new config key,
no wire change, since `FedFetchBundle` carries no per-request opt-in bit and a real malicious B
wouldn't wait to be asked). New tests: `apps/rendezvous/tests/federation_abuse.rs` (route-dimension
rate-limit enforcement — closing a gap only fetch had covered before; allowlist-miss rejection with
a genuine positive-control admit test; oversized-envelope restated cross-org; the A2×2 malicious-
server bundle-substitution test, pinned to `SignalError::BundleVerification`; the F17 structural-
inertness counterpart) and `apps/cli/tests/two_orgs_walkthrough.rs` (a CLI-subprocess message-
request-gate-then-delivery walkthrough, and the deliverable-5 continuity test — kills **both**
rendezvous servers via `JoinHandle::abort()` post-P2P-establishment, chat still flows both ways over
`LoopbackTransport`). `apps/cli/src/opacity.rs` gained `run_federated_audit` (opacity "at both
servers," scanning the real `meridian-proto` s2s wire encoding, not just the c2s shape) plus a
non-vacuity test proving the scan is sensitive to a fed-only leak. New cross-org cells in
`harnesses/mitm-sim/run.sh` and `harnesses/opacity-audit/run.sh`; CI wiring in
`.github/workflows/ci.yml` alongside the existing 1.28/1.32 tamper-hook two-step pattern (which
already picks up the new package-scoped tests with no edit needed).

**Reviews:** security-reviewer — APPROVE-WITH-CHANGES. Confirmed the tamper hook is structurally
inert without the feature (not merely untriggered — the substitution code is provably absent from
the compiled default-features binary), `allow_test_tamper` arming the federated path unconditionally
doesn't open any new release-reachable surface, the A2×2 outcome is pinned to a specific variant with
a real non-vacuity check (reading B's own store to confirm genuine substitution, not a store miss),
and the federated opacity audit's mutation-test claim is backed by a permanent regression test
(`federated_opacity_scan_is_sensitive_to_a_fed_only_leak`), not a one-off manual check. Required
change (completed): a real, independently-confirmed finding — `session::answer`'s wait for an offer
(`recv_sdp`, both call sites in `answer_with_config`) is unbounded, the mirror of task 1.33's dialer-
side fix, newly reachable because a federated route can be rejected server-side before any offer
ever arrives — filed as its own tracked task, **2.17**, rather than left as prose in a review
summary (mirrors 2.9→2.15, 2.10→2.14). Non-blocking nit (fixed): a misleading rationale comment in
the route rate-limit test claimed varying the target account was what kept the per-account limiter
from tripping first, when the per-account key is actually the sender (`req.from`, constant across
the test's calls) — the origin budget trips first because it's simply tighter, not because of the
varying target; comment corrected.
architect — consistent. Confirmed the tamper-hook extension stays inside `apps/rendezvous`'s
existing crypto/trust boundary (never imports `meridian-signaling`, doesn't touch ADR 0017's
peer-auth/`from`-attestation), the new mitm-sim cell extends task 1.32's existing thread rather than
forking a second one (satisfying ADR 0016's obligation), and Phase 2's exit criteria (opacity at both
servers, substituted-bundle-fails-closed, kill-continuity) are now genuinely proven, not merely
asserted. Independently reached the same 2.17 conclusion as security-reviewer, including the same
recommended scope and severity classification (availability-only, mirrors 1.33).
test-engineer — PASS. Independently reproduced both required mutation tests (disabling the
substitution call; injecting a real plaintext leak into the fed-hop transcript) from a clean start,
confirmed byte-identical restoration after each. Verified the continuity test's kill mechanism is
real (wrote a standalone scratch test proving `JoinHandle::abort()` actually frees the listening
socket) and that `LoopbackTransport` is structurally incapable of secretly routing through the
servers. One noted, non-blocking observation: because the data plane is `LoopbackTransport` (which
never touches the rendezvous servers regardless), the test's own assertions would still pass even if
`kill_both_servers()` were skipped entirely — its falsifiable value is narrower than "chat
interruption is the signal that the kill worked," and rests on the code-level guarantee (traced, not
just tested) that the data plane never routes through the servers in the first place. Matches the
same known limitation as the pre-existing T04 test (`p2p_session.rs::server_down_chat_continuity`,
same `MemRelay`-drop pattern) — not a defect specific to this task, recorded for honesty.
code-reviewer — approve-with-nits. Traced the rate-limit test's budget arithmetic against the actual
`FederationLimits`/`route_foreign` code (confirmed correct — each unreachable-target call consumes
exactly one origin-budget unit via the reachability pre-check, no double-counting) and confirmed no
hidden background tasks or connection pooling could keep the "killed" servers relevant to the
continuity test's outcome. Should-fix, not blocking: the two new test files add a fifth/sixth
near-identical copy of the two-org PKI/server-harness boilerplate already duplicated across
`federation_{mtls,fetch,route}.rs` and `{federation_errors,federation_route_hint,
session_connect_federation}.rs` — debt flagged as overdue by 2.7/2.8/2.9/2.15's own outcomes and
still unaddressed; recommended as an explicit Phase-3 fix-task (extract `tests/support.rs` for both
`apps/rendezvous` and `apps/cli`) rather than left to recur again. Nits, not fixed: the new CI step
is intentionally redundant with earlier steps (named for exit-gate discoverability, not new
coverage — acknowledged in its own comment); `run_federated_audit` duplicates ~15 lines of
session-bootstrap logic from the existing `run_audit` rather than sharing a helper; the task file's
own Scope line ("kill-either") is looser than its Deliverable 5 ("kill both") — pre-existing wording
inconsistency, not introduced here, and the implementation correctly follows the stricter deliverable
(a valid superset proof of "either").

# 6.6 — Test re-pointing: v1 detector → v2 AEAD, plus the new C3/R1 adversarial cells

**Phase:** 6 — Envelope v2 · **Feature:** ADR 0016 (test obligations) · **Depends on:** 6.3 · **Status:** done

## Goal
Satisfy ADR 0016's explicit instruction: the v1-pinned test cells "fail at the v2 cutover regardless —
the detector they name ceases to exist... Re-point, never delete." Also close the two test obligations
the ADR marks "OPEN (v2)": the sign-flipped-`sender_pub` case (C3) and the documented KCI cell (R1).

## Scope
- **In:**
  - `apps/core/tests/preamble_mutation.rs` (the mitm-sim harness): every cell currently asserting
    `ChatError::BadSignature` re-pointed at whatever v2's real AEAD-failure detector is (determined by
    6.3's actual returned error type — do not guess in advance). Keep all four ADR-required properties:
    rejection by the new detector, OTK-pool depth unchanged (with a positive control), no session
    installed (`ChatState` byte-identical), and the genuine envelope subsequently succeeding.
  - `apps/core/tests/chat_manager.rs`: new cell — sign-flipped `sender_pub` (`A` vs. `−A`) is rejected,
    proving the AAD's raw-Ed25519-encoding requirement (C3) is actually enforced, not just the
    Montgomery-normalized form.
  - New KCI cell (R1): an "enumerated accepted residual" test proving — not silently — that an
    attacker holding only the responder's signed-prekey secret can forge a first-contact session. Per
    `testing/strategy.md`'s "0 silent successes outside the enumerated accepted residuals" rule, this
    is documented-by-test, not swept under a passing suite.
- **Out:** `apps/rendezvous`/other production-code comment fixes (moved to 6.7 — those are doc
  corrections, not test re-pointing); the `eid`/AAD/commit-on-decrypt implementation itself (6.3, 6.4).

## Outcome

**Verified — `apps/core/tests/preamble_mutation.rs` was already correctly re-pointed by task 6.3;
no changes made to that file.** Read the real `open_bytes` code path
(`apps/core/src/chat.rs`, first-contact branch, `!self.sessions.contains_key(&envelope.sender_pub)`)
rather than trusting 6.3's Outcome section: every cell in this file drives a **first-contact**
(no prior session) preamble mutation, and on that branch a failed decrypt propagates as
`provisional.decrypt(&envelope.ct, &preamble)?` — i.e. `CryptoError` converted via `#[from]` into
**`ChatError::Crypto(_)`**, never `ChatError::Desync` (that variant is reserved for the *existing*
two-header-key branch further down `open_bytes`, per its own doc comment — first contact has no
prior session to desync from, so `note_desync` is deliberately not called on this path) and never a
generic upstream shortcut: `establish_responder_session_provisional` only returns `UnknownPrekey` if
`peek_spk_secret`/`peek_otk_secret` find nothing, and every mutation in this file (`used_opk→None`,
`used_opk→`another held OTK, `used_spk→`previous generation) deliberately references *real* prekey
material Bob still holds, so that shortcut is provably never what's under test. The shared assertion
helper `assert_rejected_for_free` already asserts all four ADR-required properties for every one of
the three preamble-mutation cells plus the forged-`from` cell: (1) rejection is specifically
`ChatError::Crypto(_)`; (2) OTK-pool depth unchanged, with a positive control (the genuine envelope's
subsequent OTK consumption) proving the counter is sensitive; (3) no session installed — in fact the
whole `ChatState` is byte-identical before/after (CBOR comparison); (4) the genuine envelope
subsequently succeeds. All four properties already held for every cell; **no edits were needed or
made to this file.**

**New (genuinely absent before this task, confirmed by grep):**

1. **`apps/core/tests/chat_manager.rs::sign_flipped_sender_pub_is_rejected`** (C3, closes the
   OPEN(v2) item). Design: take a genuine Alice→Bob opening envelope, flip the sign bit (top bit of
   the last byte of the compressed Ed25519 encoding) of the claimed `sender_pub`, and re-route with a
   matching `from` (so only the C3 AAD property is exercised, not the unrelated `SenderMismatch`
   check). Proves the raw-Ed25519 (never Montgomery-normalized) AAD requirement in
   `apps/crypto/src/x3dh.rs::derive`'s doc comment is actually enforced: every DH leg that touches the
   claimed sender's identity key goes through `ed25519_pub_to_x25519` first, which is defined purely
   from the curve's y-coordinate and therefore sign-blind — so `root`/`hka`/`nhkb` come out
   bit-identical for `A` and the flipped `A'`. If the AAD were built from that same normalized form
   (or anything short of the raw 32-byte Ed25519 encoding), this flipped envelope would decrypt
   successfully under an identity Alice never asserted, with no signature left to catch it. The test
   asserts rejection is specifically `ChatError::Crypto(_)` (confirmed via the same code-path read
   above — flipping the sign bit always yields a validly-parseable, different Ed25519 point, since for
   any encoded `y` both roots of `x² = c` are valid curve points, so this never degenerates into a
   trivial malformed-key rejection) and that the genuine, unmutated envelope still opens afterward.

2. **`apps/core/tests/chat_manager.rs::kci_forged_first_contact_from_stolen_spk_secret_succeeds_r1_accepted_residual`**
   (R1, closes the OPEN(v2) item). Threat model, read directly from ADR 0016 R1 rather than guessed
   from the name: an attacker who has obtained **only** a responder's signed-prekey (SPK) **secret**
   — never that responder's identity key, and never the impersonated sender's identity key or store —
   can forge a complete first-contact session claiming to be from any sender, because
   `DH1 = DH(IK_sender, SPK_responder)` is commutative and therefore equally computable as
   `DH(SPK_responder_priv, IK_sender_pub)` — exactly the stolen secret combined with the sender's
   already-public identity key. The test implements a minimal test-local `SecretStore`
   (`StolenSpkStore`) that answers *only* that one DH query (matched by the query's `input` shape —
   the responder's real SPK public key, exactly what `x3dh::initiate`'s `store_dh` call passes) and
   honestly refuses every other, via `meridian_crypto::test_support::{dh, ed25519_pub_to_x25519}` (the
   crate's own audited-primitive re-exports, already exposed for this exact purpose — no crypto
   hand-rolled, no widening of `test_support` needed). Composed with the real, unmodified
   `ChatState::start_initiator_session`/`seal_outbound`, this produces a wire blob that Bob's real
   `open_bytes` independently re-derives the identical session for and accepts.
   - **Why the passing assertion is correct, not overclaiming or underclaiming.** R1 is already
     enumerated as an accepted residual in ADR 0016 (compensating controls: C1's enforced SPK
     rotation + keystore-grade SPK handling) — this task does not extend that list, and the test's
     doc comment says so explicitly, framing the assertion as documenting an already-ratified
     residual, per `docs/testing/strategy.md`'s "0 silent successes outside the enumerated accepted
     residuals" rule (the one enumerated exception, not a new one this task is choosing to accept).
     It does not overclaim by stopping at "the forgery succeeds": it also pins the residual's
     documented *boundary* — a second part of the same test gives the attacker the most she could
     ever legitimately construct (a vault entry for the stolen SPK secret, no OTK, no identity key)
     and confirms she still cannot decrypt Alice's own genuine first message, because that requires
     `DH2 = DH(EK_A, IK_B)` — the *responder's* real identity key, which `StolenSpkStore` structurally
     refuses to fabricate (`StoreError::UnsupportedOp`) rather than return a plausible-looking wrong
     answer. A third part confirms safety-number verification does not distinguish the forged session
     from a genuine one (`meridian_crypto::safety_number` is a pure function of the two genuine public
     keys), matching ADR 0016 R1's explicit claim.

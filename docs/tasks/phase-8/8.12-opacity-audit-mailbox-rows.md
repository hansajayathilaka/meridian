# 8.12 — Opacity/at-rest audit extension for mailbox rows

**Phase:** 8 — Offline Ciphertext Mailbox · **Feature:** T07 · **Depends on:** 8.2 · **Status:** pending

## Goal
Satisfy the feature spec's acceptance criterion "opacity audit covers at-rest DB pages (no
plaintext, headers encrypted)" — extend the existing opacity-audit harness rather than building a
new one.

## Scope
- **In:** extend `harnesses/opacity-audit` to scan the SQLite mailbox table's raw pages (once 8.2
  lands) for plaintext leakage — same technique the harness already applies to other tables
  (`prekeys`, `device_records`, etc.), reused, not reinvented. Confirm the header-encryption claim
  (Double Ratchet's encrypted-headers variant, system-design §4.3) holds for a mailbox-queued
  envelope exactly as it does for a live-routed one — this is a corollary of the transport-
  independence invariant 8.10 already exercises, checked here from the at-rest angle instead.
- **Out:** no changes to the ratchet/header-encryption code itself — this task is audit coverage
  only; if it finds a real leak, that becomes its own follow-up finding, not silently patched here
  without review.

## Deliverables
1. `harnesses/opacity-audit` extended to include the `mailbox` table in its page scan.
2. A test proving the harness actually detects a planted-plaintext regression (write a raw
   known-plaintext string into a mailbox row directly via the store's test-only path, confirm the
   harness's scan flags it) — the harness must be shown to actually work, not merely run clean by
   default.

## Risks / notes
An opacity audit that only ever passes proves nothing; the planted-plaintext non-vacuity check in
Deliverable 2 is the load-bearing part of this task, matching this project's established discipline
for every "prove the security property, don't just assert it" task (7.4, 8.9).

## Tests
`harnesses/opacity-audit/run.sh` (or whatever the harness's existing invocation is — follow its own
README).

## Reviews
- **security-reviewer** — the harness extension itself, and confirms the planted-plaintext test is
  a genuine non-vacuity proof.

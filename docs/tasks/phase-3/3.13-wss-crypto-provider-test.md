# 3.13 — Test the `wss://` crypto-provider install

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F13) · **Depends on:** 3.4 (if the integration form is chosen) · **Status:** in progress

## Goal
Deleting `ring::default_provider().install_default()` or the TLS feature must turn CI red, not ship a
runtime panic.

## Scope
- **In:** extract the install into a named, testable `fn install_crypto_provider()`; a unit test
  asserting `CryptoProvider::get_default().is_some()` after it runs; **preferred stronger form** — an
  integration test in `apps/cli/tests/wss_tls.rs` connecting `SignalingClient::connect` to a
  self-signed TLS WebSocket listener (reusing 3.4's `TestCa`).
- **Out:** changing TLS root selection (`native-roots` vs `webpki-roots`) — only the misleading
  *comment* is fixed, in 3.21/N3.

## Deliverables
1. The extracted `install_crypto_provider()` in `apps/cli/src/main.rs` (or `meridian-signaling`).
2. The test(s) above.

## Risks / notes
- Every `wss://` connection was **dead on arrival** before PR #42 (runtime panic, no CryptoProvider),
  and nothing tests it — the only wss path today is behind docker, which CI never runs.
- **CI invocation:** `apps/cli` has `default = []` and the rustls dep is unconditional, so
  `cargo test --workspace` runs it. **If** the test ends up behind any feature, this task MUST add an
  explicit named step to `ci.yml` — state which case applies in the Outcome. (Three prior traps:
  1.12, 1.28, 1.32.)

## Goal

## Scope
- **In:** a live PTY run of the **full**, corrected demo script from
  [17-terminal-tui-client.md](../../architecture/features/17-terminal-tui-client.md)'s "Working output"
  (post-4.47's fix), for a **file-backed** account and an **OS-keystore** account, covering every step:
  1. onboarding → registered → bundle published → `Screen::Main`, both account types;
  2. initiator adds the responder by `mrd1:` id with petname "bob" and sends a first-contact message;
  3. responder sees the message request (key + safety number + intro) and accepts;
  4. responder opens a chat with the accepted sender and replies (4.42's fix, re-confirmed);
  5. `^V`/`v` shows the same 60-digit safety number on both sides → mark verified on both — **including,
     this time, the initiator marking their own plainly-added contact verified in the same session,
     without a restart (4.46's own fix — the exact step 4.45 found broken)**;
  6. restart both peers (`pkill` + relaunch) and confirm contact list, petnames, **full history** and
     the ratchet session are all restored with no re-handshake and no duplicated messages (4.44's fix,
     re-confirmed);
  7. `meridian tui --export-json <path>` + the **corrected** `jq '.contacts[0].petname' <path>/contacts.json`
     invocation (4.47's own fix) returns `"bob"`.
  Also: record the file-backed session-start latency observed here and compare it against 4.43's and
  4.45's own recorded before/after numbers (4.45 measured onboarding 2.27 s–4.36 s, restart 5.66 s–10.69 s)
  — a regression to minutes is a failure of this gate even if every functional step passes.
  Re-run the standing regression set every prior attempt held itself to: `cargo test -p meridian-tui
  --all-targets --no-fail-fast`, `cargo test -p meridian-cli --bins`, `cargo test -p meridian-tui --test
  live_session_e2e`, `bash harnesses/mitm-sim/run.sh` (T08 regression), `bash tools/lint-tui-no-cli.sh`,
  `bash tools/check-docs.sh`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt
  --check`, plus 4.46's and 4.47's own new targets.
  Hold to the **two-independent-runs discipline** 4.28/4.38/4.41/4.45 all used — implementer once,
  `reviewer`/`test-engineer` once, independently. **Not relaxed:** four exit-gate attempts in a row have
  each found a real defect this exact way.
- **Out:** any new feature code; fixing anything newly found live here. **If a genuine defect surfaces,
  report it honestly in this task's own Status section, do not fix it here, file a new task (working
  number 4.49), and leave both the exit-criteria checkbox and the carry-forward note open** — the same
  non-negotiable rule 4.28, 4.38, 4.41 and 4.45 all held. Never weaken an assertion (this task's own, or
  4.42's/4.43's/4.44's/4.46's/4.47's) to make the demo appear to pass.

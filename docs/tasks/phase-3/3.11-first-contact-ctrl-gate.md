# 3.11 — Thread first-contact state into `decide_open` (ctrl-frame gate)

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F11) · **Depends on:** 3.10 · **Status:** done

## Goal
Close the loophole where an undecided peer's `CtrlFrame::Open` is auto-accepted because
`decide_open` hardcodes `first_contact: false`.

## Scope
- **In:** thread the pending-request / `chat_first_contact_gate` signal into
  `PolicyCtx.first_contact`; remove the "T08 wires real first-contact state" hardcode.
- **Out:** new policy semantics for what first-contact ctrl traffic is *allowed* to do (that is
  existing policy, now correctly fed); registering new stream types.

## Deliverables
1. `apps/core/src/session.rs` (L790) — real first-contact state in `PolicyCtx`.
2. A test that a peer with an undecided `MessageRequest` gets `first_contact: true` and the policy
   decision it implies, for a registered **non-chat** stream type.

## Risks / notes
- Impact is limited today (small registry) but becomes live the moment a file/media stream type
  registers — 2.10/2.14 claimed first contact was gated, and for ctrl frames it is not.
- The gate must be **registry-agnostic**, not a per-type allowlist (stream-registry contract:
  additive stream types touch the registry only).
- **Fallback:** if the signal is not cleanly reachable from `session.rs`, record it as an explicit
  T08 follow-up on the 2.14 task file and downgrade this task to that record — **only with architect
  sign-off**, never silently.

## Outcome

**Clean path taken — no architect sign-off needed for a fallback (none was taken).** The signal was
cleanly reachable: `decide_open` (called from `handle_ctrl`, which already receives `chat: &mut
ChatState` for every `CtrlFrame::Open`) now takes `chat: &ChatState` and derives `first_contact` as:

```rust
let first_contact =
    self.chat_first_contact_gate || chat.pending_request(&self.peer_ik).is_some();
```

Two signals, combined, because neither alone is correct on its own:
- `self.chat_first_contact_gate` (already a `P2pSession` field, set at construction from
  `chat.has_session(&peer_ik)` before the offer/answer handshake, task 2.14) — catches a peer who
  opens some *other* stream type **before** ever sending a first chat content frame (no
  `MessageRequest` exists yet to check).
- `chat.pending_request(&self.peer_ik).is_some()` — the **live** signal, reusing `ChatState`'s
  already-public accessor (task 2.10/3.10) rather than duplicating any `pending_requests`
  bookkeeping. This catches the case `chat_first_contact_gate` alone misses: it clears the instant
  the first chat content frame is *processed* (`pump`'s `CHAT_LABEL` arm), independent of whether
  the resulting `MessageRequest` has actually been decided — so a peer who sent one chat message,
  still awaiting accept/reject, and then opens a second (non-chat) stream would wrongly read
  `first_contact: false` using `chat_first_contact_gate` alone. This is exactly the review finding's
  named risk ("becomes live the moment a file/media stream type registers").

The old "T04 has no persisted contact list yet; T08 wires real first-contact state" hardcode/TODO is
gone. The fix is registry-agnostic by construction: `decide_open` computes `first_contact` once from
session/`ChatState` state and hands it to `StreamType::on_open` via `PolicyCtx` for *any* registered
`ty` — chat included — with zero per-type branching; the built-in `ChatStream` doesn't override
`on_open` (still auto-accepts, unaffected), so this only changes behavior for stream types that
choose to consult `first_contact` in their own policy hook, exactly the extension point the registry
contract promises.

Added `ctrl_open_gates_on_undecided_message_request_for_a_non_chat_stream_type` to
`apps/core/tests/p2p_session.rs`: a throwaway non-chat `Probe` stream type (`mrd.probe/1`) whose
`on_open` records the `PolicyCtx.first_contact` it was handed into a shared `AtomicBool`. The test
drives Alice's first chat content frame to Bob (gated as an undecided `MessageRequest`,
`chat_first_contact_gate` cleared as a side effect), then has Alice open the *unrelated* probe
stream and asserts Bob's `decide_open` fed `first_contact: true` into `Probe::on_open` — proving the
fix reads live `pending_request` state and not just the already-cleared session-level flag. A
second assertion, after `accept_request`, confirms `first_contact: false` once the contact is
decided. Verified this test is a real regression check (not a tautology) by reverting only
`session.rs` and confirming the new test fails against the pre-fix hardcoded `false`.

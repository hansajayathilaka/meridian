# 11.6 — Make `RESTART_GLARE_WINDOW` test-overridable; cover the timeout-fallback branch

**Phase:** 11 — Review of Phase 10 · **Feature:** review fix (F6) · **Depends on:** 11.1, 11.2 (soft) · **Status:** pending

**User surface:** none — coverage task with a minimal test-only hook into existing `ice_restart` logic; no
production behavior change (Definition of Done gate 9 doesn't apply).

## Goal
Prove the larger-key side's glare-window timeout-then-fallback branch in `ice_restart` actually completes
a working restart, closing the only untested branch in that method.

## Scope
- **In:** `apps/core/src/session.rs` — make `RESTART_GLARE_WINDOW` injectable (a parameter threaded
  through the relevant private helper, or a `#[cfg(test)]`-gated override) so a test can force the timeout
  deterministically, plus a new test that drives two `P2pSession`s where the larger-key side's window
  elapses with no incoming offer, asserting the fallback restart (self-offering) still completes
  successfully.
- **Out:** no change to the glare tie-break logic itself, the layered fingerprint check, or
  `RESTART_ANSWER_TIMEOUT`.

## Deliverables
1. `RESTART_GLARE_WINDOW` made test-overridable in `apps/core/src/session.rs` (exact mechanism —
   parameter vs. `#[cfg(test)]` const override — left to the implementer/reviewer, whichever is the
   smaller, least invasive change).
2. New test forcing the larger-key side's window to elapse (e.g. by delaying the smaller-key side's offer
   past a shrunk test window) and asserting both sides still converge on a working, reconnected session.

## Risks / notes
Keep the production-path default value of `RESTART_GLARE_WINDOW` unchanged — this task only adds a
test-time override, never weakens the real timeout. This is real, reachable production code, not a
theoretical branch — treat the new test as a genuine regression pin.

Soft-depends on 11.1 and 11.2: same file and same `ice_restart` area; 11.2 in particular touches the exact
functions (`restart_offer_and_await_answer`/`answer_restart_offer`) this task's new test drives through,
so landing after avoids a rebase touching the same lines twice.

# 12.10 — `meridian-wasm` crate scaffold + smoke build + bundle-size report

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** 12.4 · **Status:** done

**User surface:** none directly — build-pipeline foundation for the browser `Transport` shim (12.11) and
IndexedDB store (12.12). No TUI surface applies.

## Goal
Scaffold `apps/wasm`, the wasm-bindgen cdylib crate `stack.md`'s documented target layout calls for,
wrapping `meridian-core`'s identity/store/crypto/session facade — using `LoopbackTransport`/
`MemorySecretStore` stand-ins, not the real browser impls — to prove the bindgen build pipeline end to
end before the real, harder pieces (browser `Transport`, `WebCryptoSecretStore`+IndexedDB) are wired in.
This directly follows the feature spec's own risk note: "schedule the WASM smoke build as day-1 of this
task regardless [of the ratchet library's wasm32 story]."

## Scope
- **In:** `apps/wasm` crate scaffold; `wasm-bindgen`/`tsify` wiring into `just codegen`, emitting
  `bindings/typescript`; a `wasm-pack build --release` CI step reporting gzipped bundle size (informational
  only at this stage — the hard <4 MB gate is task 12.20's); a smoke test round-tripping
  `generate_account`/`sign`/`safety_number` through the compiled `.wasm` in a headless runner.
- **Out:** the real `BrowserTransport` (12.11) and `WebCryptoSecretStore`/IndexedDB store (12.12) wiring
  — this task's stand-ins are deliberately not the production implementations, exactly so this task can
  land independently and prove the pipeline before those harder pieces exist.

## Deliverables
1. `apps/wasm/Cargo.toml`, `apps/wasm/src/lib.rs`.
2. `wasm-pack build -p meridian-wasm --release` CI step + size report.
3. Smoke test: `generate_account` → `sign` → `verify` and `safety_number` round-trip through the
   compiled artifact.

## Outcome
Scaffolded `apps/wasm` (`meridian-wasm`), a wasm-bindgen cdylib depending only on `meridian-core` +
`wasm-bindgen` (confirmed via `Cargo.lock` diff: exactly one new package entry, no transitive crates
leaked in). Exports `generate_account`/`WasmAccount::sign`/`verify`/`safety_number` backed by
`identity::MemorySecretStore` — no browser API surface, no `Transport`/`SecretStore` real implementation
(those are separate tasks, 12.11/12.12). `tools/xtask codegen` gained its wasm-bindgen half, emitting to
`bindings/typescript/generated` (reusing the pre-existing `.gitignore` pattern). A new `wasm-build` CI job
runs `wasm-pack build apps/wasm --release --target web` plus an informational gzipped-size report
(118,981 bytes gzipped — the hard <4MB gate belongs to task 12.20) and `wasm-pack test --node apps/wasm`.

Two real, task-file-corrected discoveries: `wasm-pack build` takes a positional crate path, not `cargo`'s
`-p`/`--package` flag (the task file's own literal test command was wrong — the actual invocation used
throughout the crate's docs/CI/xtask is `wasm-pack build apps/wasm --release`); and `wasm-pack`'s bundled
`wasm-opt`/binaryen downloader hit a `ureq`-vs-proxy quirk specific to this sandbox (a plain `curl` to the
same URL worked fine), worked around by pre-populating the tool's cache rather than disabling `wasm-opt`
— expected to be a non-issue on a real CI runner with unrestricted internet.

Headless-runner choice for this task's smoke test: **`wasm-pack test --node`**, recorded for 12.11/12.12/
12.13 to reuse unless their own tests need a real browser API (in which case 12.5's real-Chromium approach
is the right precedent) — this task's test only calls plain functions through the wasm boundary, so Node
is sufficient and avoids the Chromium/ChromeDriver version-matching fragility 12.5 hit (reconfirmed here:
this sandbox has a chromedriver binary but no matching Chrome/Chromium browser binary at all).

The combined review (architect + code-reviewer) returned **PASS** on both lenses, zero blocking findings,
after independently reproducing the real `wasm-pack build --release` (produced a valid 243,345-byte
`.wasm` artifact) and the smoke test (2/2 pass, confirmed both are genuine assertions — a generate→sign→
verify round trip plus a negative tampered-message case, and a safety-number commutativity/length/
digit-only check — not vacuous stand-ins), and confirming the `apps/wasm` vs. `stack.md`'s literal
`crates/meridian-wasm` path naming is pre-existing, repo-wide drift (every crate already lives under
`apps/*`) rather than something this task introduced.

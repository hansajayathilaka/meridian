# 9.8 — Lock `MailboxAck{ids:[]}` conformance vector

**Phase:** 9 — Review of Phase 8 · **Feature:** review fix (F8) · **Depends on:** — · **Status:** done

**User surface:** none — dev-tooling conformance-vector addition; no client/server behavior change
(Definition of Done gate 9).

## Goal
Close a conformance-vector gap directly echoing Phase 7's F7 finding ("conformance vectors cover only
one canonical shape"): `test-vectors/c2s-v1.json`'s `mailbox-ack` vector locks only the populated
`MailboxAck{ids:[1,2,3]}` shape. `MailboxAck{ids:[]}` is a real, reachable wire shape — used whenever
`discard_pending_mailbox_ack` empties the accumulator before a flush — that's proven for
`meridian-proto`'s own encode/decode symmetry (`apps/proto/tests/roundtrip.rs::mailbox_ack_and_ack_ok_roundtrip`)
but not byte-locked across implementations, so CLI/WASM/mobile could silently drift on the empty-array
CBOR shape (`0x80`) with nothing to catch it.

## Scope
- **In:** add a `mailbox-ack-empty` case to `tools/xtask/src/vectors/c2s.rs`, following the same
  non-vacuity discipline the rest of task 8.4's vectors use (neutralize-field/confirm-fail/restore
  cycle), and lock its `frame_hex` in `test-vectors/c2s-v1.json` via the repo's standard `xtask`
  regeneration path.
- **Out:** No other vector shapes — this task is scoped to the one named gap.

## Deliverables
1. A new `mailbox-ack-empty` conformance vector in `test-vectors/c2s-v1.json`, generated via `xtask`,
   with a non-vacuity check proving the vector would actually catch a regression in empty-array
   encoding.

## Risks / notes
No file overlap with other phase-9 tasks — independent. Follow the exact regeneration/verification
procedure task 8.4 (and Phase 7's 7.5) used, since both are recorded as having caught real
fixture-corruption or non-vacuity issues by doing this carefully rather than trusting a first pass.

## Tests
`cargo run -p xtask -- vectors check` (or the repo's equivalent vector-lock verification command),
`cargo nextest run -p meridian-proto`.

## Reviews
**architect** (conformance-vector/wire-contract discipline), **test-engineer** (non-vacuity
verification).

## Outcome
Added `mailbox-ack-empty` to `tools/xtask/src/vectors/c2s.rs`, regenerated into
`test-vectors/c2s-v1.json` (`frame_hex` ending `0x80`, the CBOR empty-array marker). All 12
pre-existing vectors stay byte-identical. Non-vacuity independently re-verified by test-engineer with a
different corruption than the implementer's own check, plus an added fields-vs-frame_hex cross-check
proving the conformance test genuinely re-derives bytes rather than replaying `frame_hex`.

architect PASS with one should-fix, closed in the same batch: this Goal's own "reachable whenever
`discard_pending_mailbox_ack` empties the accumulator before a flush" claim is factually wrong —
`SignalingClient::ack_pending_mailbox` early-returns with no network I/O when the accumulator is empty,
so this shape is not actually emitted end-to-end by this repo's own reference client today. The vector
remains warranted on the grounds architect independently verified instead: the wire spec places no
non-emptiness constraint on `MailboxAck.ids`, the server explicitly documents handling an empty/all-
foreign id set, and the vector guards against a future `#[serde(skip_serializing_if)]` regression
silently changing the empty-array shape to an omitted key. Corrected in the code comment
(`tools/xtask/src/vectors/c2s.rs`); this Goal section is left as the original review-time framing. One
non-blocking nit also noted (the new vector's `id: 13` breaks ascending order in the JSON array —
cosmetic, no protocol constraint, not fixed).

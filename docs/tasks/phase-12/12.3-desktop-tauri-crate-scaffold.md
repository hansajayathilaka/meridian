# 12.3 — `apps/desktop` Tauri crate scaffold (Rust side)

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** — · **Status:** pending

**User surface:** desktop app shell foundation (Rust backend only — no window UI yet, that's 12.15). No
TUI surface applies; this is a new client platform, not a new protocol feature (see
[phase-12/README.md](./README.md#architect-consult-substratestoresigning-decisions-settled-before-task-breakdown)
point 5).

## Goal
Add a new Cargo workspace member, `apps/desktop` (Tauri v2, per [ADR 0010](../../adr/0010-desktop-shell-tauri.md)),
running `meridian-core` in-process and wiring **the existing** `apps/store::OsSecretStore` and
`apps/transport::WebRtcTransport` — per the architect consult's point 1, desktop needs zero new
`SecretStore`/`Transport` code, only Tauri integration. Exposes the `core-api-contracts.md` operation
surface to the WebView via Tauri commands/events.

## Scope
- **In:** `apps/desktop` crate scaffold; `Cargo.toml` root `members` update; construction of
  `OsSecretStore::new(...)` and `WebRtcTransport::new()` exactly as `apps/cli` already does (same
  crates, same feature flags — build with `--features webrtc` on `meridian-transport`/`meridian-core`,
  matching the CLI); Tauri `#[command]` handlers covering account lifecycle, chat send/receive,
  contacts/trust, and stream/file operations from `core-api-contracts.md`; Tauri events for inbound
  message/state-change push to the frontend.
- **Out:** any new `SecretStore`/`Transport` implementation (there is none — reuse only); the TS-side
  adapter consuming these commands (12.6); the actual window UI (12.15); updater/signing config (12.16).

## Deliverables
1. `apps/desktop/Cargo.toml` (new workspace member).
2. `apps/desktop/src/main.rs` — Tauri app entry, `OsSecretStore`/`WebRtcTransport` construction.
3. `apps/desktop/tauri.conf.json` — minimal config (window/bundle identifiers; updater config deferred
   to 12.16).
4. `apps/desktop/src/commands.rs` — Tauri `#[command]` handlers.
5. Tests exercising the command handlers directly (not through a real WebView) against a real
   `meridian-core` session over `LoopbackTransport` for determinism, confirming the command layer
   correctly marshals requests/results without altering `meridian-core` behavior.

## Risks / notes
Secret material (raw seeds, session keys) must never cross the Tauri IPC boundary in plaintext — only
operation *results* (already the shape `core-api-contracts.md`'s functions return) should ever reach
the JS side. This is the same discipline `apps/cli` already follows (the CLI process never prints key
material outside explicit, logged `export`/`--export-json`-style paths); do not introduce a new leak
surface via a Tauri command that returns raw key bytes.

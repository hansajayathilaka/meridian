# 10.12 — `mrd.file/1` spec section + wire/design doc corrections

**Phase:** 10 — File Transfer Stream · **Feature:** T09 · **Depends on:** 10.4, 10.6, 10.9 ·
**Status:** done

**User surface:** none — this is a doc-only task.

## Goal
Write the `docs/api/stream-types-v1.md` section for `mrd.file/1`, precise enough that a third-party
engineer could implement it from the doc alone (the feature's own acceptance criterion: an engineer not
on this task builds a toy `mrd.echo/1` stream from the doc in under a day), and correct the two
implementation-precision gaps this phase's planning surfaced in existing docs.

## Scope
- **In:**
  1. New `mrd.file/1` section in `docs/api/stream-types-v1.md`: manifest schema, the exact merkle
     construction (from task 10.3's Outcome), the exact per-chunk AEAD nonce encoding (from task 10.5's
     Outcome), the resume-in-stream design (from task 10.9), backpressure watermark behavior (task
     10.7).
  2. Correct `docs/api/wire-protocol.md` §5: the `Resume = {sid, bitmap: bstr}` line documents a ctrl
     frame that was never implemented and, per task 10.9's settled resolution, never will be (resume
     rides in-stream) — annotate or remove this line so the doc matches what's actually built.
  3. Small `/doc-sync` correction to `docs/architecture/system-design.md` line ~202 ("the initiator
     opens a new SCTP data channel") to reflect task 10.4's actual symmetric-explicit-open design.
  4. Note in `docs/architecture/system-design.md` §7.2 (or `stream-types-v1.md`) recording reshare/dedup
     of identical ciphertext as an explicit follow-up, per the feature spec's own out-of-scope note.
- **Out:** any code change — this is a doc-only task, run after the shapes it documents have actually
  landed (hence its dependency on 10.4/10.6/10.9).

## Deliverables

## Outcome
Wrote the `mrd.file/1` section in `docs/api/stream-types-v1.md` (registration, `on_open` policy,
manifest schema, the exact merkle construction, per-chunk AEAD, wire chunk body/frame-tag framing, the
in-stream resume design, and backpressure watermarks — all traced byte-for-byte from the actual shipped
code in `apps/streams/src/{merkle,chunk,resume,sender,file}.rs`, not from the original task plans,
which in a couple of places (nonce encoding, watermark values) differ subtly from what was actually
built). Also rewrote that doc's general "Stream framing" section, which the implementation review found
was stale (claimed a stream key derived once at `OPEN` with a length prefix; the shipped design
ratchet-seals every frame directly with no length prefix, plus a currently-unused per-frame HKDF
export) — corrected it against `apps/core/src/session.rs`/`apps/crypto/src/ratchet.rs` directly, since
leaving it wrong would have made the new `mrd.file/1` section self-contradictory with the rest of the
doc. Corrected `docs/api/wire-protocol.md` §5 (removed the never-built `Resume` ctrl-frame line, with a
note pointing to the in-stream design) and §6 (matching the stream-framing correction). Corrected
`docs/architecture/system-design.md` line ~202 (symmetric explicit-open, not initiator-only) and added
a §7.2 status note on reshare/dedup being design-permitted but unimplemented.

One explicitly disclosed gap, not invented around: `mrd.file/1`'s wire chunk body (`{i, data}`) has no
merkle-proof field, and `FileReceiver::receive_frame` (task 10.8) takes a `MerkleProof` as a
caller-supplied argument with no wire mechanism defined for how it gets there — documented honestly as
an open `TODO: confirm` in the new spec section rather than inventing a resolution, per the "insert
TODO: confirm — do not invent" rule.

The **architect** review lens (this task's sole named reviewer) returned **PASS**, independently
re-deriving every pinned claim against the actual source rather than trusting the doc text: confirmed
the merkle construction, per-chunk AEAD, wire framing, resume bitmap encoding, and backpressure
watermarks all match the shipped code byte-for-byte; confirmed the stream-framing rewrite is accurate
against `session.rs`/`ratchet.rs`; confirmed the two stale-line corrections are faithful (cross-checked
against tasks 10.4's and 10.9's own Outcome sections); confirmed the disclosed merkle-proof gap is real,
not an oversight or already resolved elsewhere; hand-verified both new anchor links resolve under
GitHub's heading-slug algorithm; and confirmed the general extension contract (independent of
file-transfer-specific content) stays clear for a `mrd.echo/1` implementer — the actual acceptance bar
task 10.17 exercises. The review found two additional stale-doc defects adjacent to this task's own
scope, closed in a same-task follow-up: `system-design.md` §5.3's framing bullet (a second instance of
the same "one ratchet step per stream setup"/length-prefix staleness, one line above the already-planned
line-202 correction) and `apps/transport/src/webrtc_backend.rs`'s module doc (explicitly named by task
10.4's own Outcome as belonging to this task, still described per-stream data channels as a "future"
state when the shipped code already opens one symmetrically on every accepted stream) — both corrected.
Also closed two minor should-fixes the same review flagged: `apps/streams/src/merkle.rs`'s own stale
`TODO: confirm` on the empty-file convention (now pinned, matching the new spec section precisely) and
an internal contradiction in `system-design.md` §7.2 ("ACKs ranges on ctrl" — no such mechanism exists —
sitting next to the newly-added, accurate in-stream-resume correction).

`bash tools/check-docs.sh` clean throughout (3549+ relative links checked, zero broken).

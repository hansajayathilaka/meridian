# 3.15 — Doc-sync the federation wire/deploy facts

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F14 + F15) · **Depends on:** 3.5 · **Status:** pending

## Goal
A second implementation coded from the protocol doc alone must not drift on the frame ceiling, the
default port, or the fetch rate-limit axis.

## Scope
- **In:** `docs/api/federation-protocol-v1.md` §1 — `MAX_FRAME_LEN` (1 MiB) as the s2s frame **and**
  route-envelope ceiling; §1 / a deployment note — default port **8444** with a
  "non-IANA-registered, operator-configurable" note; §4 — the ADR 0017 C5 reinterpretation (the
  fetch per-account axis is keyed on `req.target` because `FedFetchBundle` has no `from`) with its
  residual.
- **Out:** any ADR — the report is explicit that these are doc-sync only (bilateral rate limiting is
  policy per ADR 0002). Also out: changing any of the values.

## Deliverables
1. `docs/api/federation-protocol-v1.md` §1 + §4.
2. A deployment note in `docs/operations/deployment.md`.
3. The two `TODO: confirm` markers removed **at their sources** (`apps/rendezvous/src/config.rs`
   around the port default, and the tracker/2.4 references).

## Risks / notes
- Grouped because F14 and F15 are paragraph-level edits to the same doc in the same review — one PR,
  one architect pass.
- Depends on 3.5: if 3.5 changes the metering, §4 must describe the **landed** behaviour, not the
  behaviour at report time.

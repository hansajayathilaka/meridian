# 4.47 — Fix `--export-json` demo-script/spec wording (directory layout, not a flat file)

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client (gap closure, doc-only fix for one of 4.45's secondary findings) · **Depends on:** — · **Status:** pending

## Goal
Correct the T17 feature spec's demo script (and any other doc making the same assumption) so that its
own literal `--export-json` + `jq` invocation actually runs as written, instead of failing with `jq:
Could not open ...: Is a directory` — closing the one secondary finding from 4.45 that genuinely needs a
change (the OS-keystore restart-methodology finding needs no task at all, per 4.45's own Status section:
it is already a recorded test-methodology note, not a defect).

## Scope
- **In:**
  - `docs/architecture/features/17-terminal-tui-client.md`'s "Working output" demo script
    (currently `$ meridian tui --export-json /tmp/dump.json && jq '.contacts[0].petname' /tmp/dump.json`)
    rewritten to the correct invocation against the real, intentional directory layout
    `apps/tui/src/store/export.rs::export_json` produces (confirmed by reading the function directly:
    `<dest>/contacts.json`, `<dest>/history/<peer-hex>.jsonl`, `<dest>/outbox.json`, `<dest>/state.json`,
    permission-hardened 0700/0600) — e.g.
    `$ meridian tui --export-json /tmp/dump && jq '.contacts[0].petname' /tmp/dump/contacts.json`.
  - A grep-confirmed sweep of every other `--export-json` mention across `docs/` for the same flat-file
    assumption — 4.45 named exactly one line, but the same mistake could be repeated elsewhere; each
    other mention found must be corrected or explicitly confirmed already-correct (name which, don't
    silently skip).
  - Route through the `/doc-sync` discipline: the code (`export_json`'s directory layout) is the
    correct, already-tested, already-permission-hardened design — per 4.45's own Status section's
    explicit recommendation ("the directory layout is the more defensible design ... recommend fixing
    the spec/demo-script wording, not the code"). **Do not change `export_json`'s behavior.**
- **Out:** any code change to `apps/tui/src/store/export.rs` or its tests; the `Effect::AddContact`
  reconciliation fix (task [4.46](./4.46-add-contact-trust-reconciliation.md) — unrelated root cause,
  traced by 4.45's own Status section to task 4.15, three tasks before `Effect::AddContact` (4.19) even
  existed); the OS-keystore restart-methodology finding (per 4.45's own Status section, this needs no
  code or doc task at all).

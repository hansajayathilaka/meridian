# 10.10 — CLI `meridian send`

**Phase:** 10 — File Transfer Stream · **Feature:** T09 · **Depends on:** 10.7, 10.8, 10.9 ·
**Status:** pending

## Goal
Give the reference CLI client a `send` subcommand matching the feature spec's demo script:
`meridian send mrd1:<bob>@org-b.test ./video-1GiB.bin`, with a progress bar and an accept/reject prompt
on the receiving end.

## Scope
- **In:** `apps/cli/src/` — a new `send`/file-transfer module wiring `meridian-streams`'s sender/receiver
  engines to a live `P2pSession` (orchestration only, per `apps/cli/CLAUDE.md`: the CLI is a driver, not
  where protocol logic lives), a progress bar rendering the sender engine's progress events, and a
  terminal prompt for the recipient's accept/reject decision when `FileStream::on_open` doesn't
  auto-accept.
- **Out:** the TUI surface (10.11, separate crate/screen); any protocol logic — if this task finds itself
  writing chunking/AEAD/merkle code in `apps/cli`, that logic belongs in `apps/streams` instead.

## Deliverables
1. `meridian send <mrd1-id> <path>...` subcommand (multi-file batch per the feature spec's "multi-file
   batches" in-scope item).
2. Progress bar output matching the demo script's shape (`38% ▓▓▓▓▓░░░░ 41 MB/s`).
3. Accept/reject prompt on the receiving side for a non-auto-accepted incoming file.
4. Tests: CLI-level integration test driving a send/receive pair over the loopback transport.

## Risks / notes
Match the feature spec's exact demo script as closely as practical — it's the acceptance criterion this
task feeds into (task 10.17's full demo run reuses this).

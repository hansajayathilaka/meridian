# 4.17 — Unlock screen

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client · **Depends on:** 4.13, 4.15 · **Status:** pending

## Goal
Let a returning user with an existing file-backed account unlock it; OS-keystore-backed accounts skip
this screen entirely.

## Scope
- **In:** masked passphrase entry, retry with attempt count, no invented lockout policy
  (`TODO: confirm` an attempt policy per [tui-client.md §7](../../architecture/tui-client.md#7-what-the-user-sees-when-things-go-wrong)
  if one is ever wanted — do not invent one now).
- **Out:** onboarding (4.16); the passphrase's underlying crypto (already exists in `meridian-store`).

## Deliverables
1. `apps/tui/src/screens/unlock.rs`.
2. Screen-snapshot tests; retry-with-attempt-count test; no secret ever rendered (masked input,
   verified structurally — the passphrase buffer never appears in a snapshot).

## Tests
`cargo nextest run -p meridian-tui --test screens_unlock`

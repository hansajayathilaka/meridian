**Phase:** 10 — File Transfer Stream · **Feature:** T09 · **Depends on:** 10.1–10.16, 10.18 ·
**Status:** pending

## Goal
Close Phase 10: run the feature's full acceptance demo end-to-end exactly as scripted, run the
feature's own named acceptance gate (an engineer not on this task implements a toy `mrd.echo/1` stream
from `docs/api/stream-types-v1.md` alone in under a day), and do a final doc-sync pass.

## Scope
- **In:** the full demo script from `docs/architecture/features/09-file-transfer.md` (`meridian send`,
  mid-transfer network cut + resume, final `sha256sum` parity check), run live; the reference
  third-party check; a final `/doc-sync` sweep confirming everything task 10.12 wrote matches what
  actually shipped (in case any later task in the phase drifted from what 10.12 documented).
- **Out:** fixing any defect found here belongs in a new fix-task (following the Phase 4/8 precedent of
  re-attempting the exit gate after a fix), not silently patched into this task's own scope.

## Deliverables
1. A demo transcript (`phase-10/10.17-demo-transcript.md` or similar, following the Phase 6/8 precedent).
2. Record of the third-party implementability check's outcome (pass/fail, and if fail, what the doc was
   missing — feeds a fix-task, not a silent doc patch here).
3. Tree green workspace-wide: `cargo build --workspace`, `cargo fmt --all -- --check`, `cargo clippy
   --workspace --all-targets -- -D warnings`, full test suite.

plainly: "if they can't, the contract doc fails acceptance") — follow the Phase 4 precedent of a new
gap-closure task + a re-run of this exit gate, rather than lowering the bar.

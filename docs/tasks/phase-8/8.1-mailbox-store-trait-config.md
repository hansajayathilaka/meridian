# 8.1 — Mailbox store trait + in-memory impl + config surface

**Phase:** 8 — Offline Ciphertext Mailbox · **Feature:** T07 · **Depends on:** — · **Status:** pending

## Goal
Give the rendezvous server a place to durably hold TTL-bounded, quota-capped ciphertext for an
offline recipient, and an org-configurable knob to size/disable it — with no route-path wiring yet.

## Scope
- **In:** extend the `Store` trait (`apps/rendezvous/src/store.rs`) with mailbox operations:
  `mailbox_enqueue`, `mailbox_list_for_recipient` (ordered `arrived_at`/`id`),
  `mailbox_delete_by_ids` (scoped to the caller's own `recipient_pub`),
  `mailbox_purge_expired`, `mailbox_size_bytes_for_recipient` (quota accounting). Implement all of
  them against the existing in-memory `Store` impl. Add a `[mailbox]` config section to
  `apps/rendezvous/src/config.rs` (`struct Mailbox { ttl_days: u32, quota_mb: u32 }`, default
  `ttl_days = 14`), following the existing `Turn`/`Federation` structs' figment/fail-closed
  pattern (rendezvous-protocol-v1.md §5).
- **Out:** no SQLite persistence (8.2), no wiring into `handle_route`/`handle_fed_route` (8.5/8.6),
  no wire/proto changes (8.3), no purge job scheduling (8.9) — this task only builds the seam and
  proves it in isolation.

## Deliverables
1. `Store` trait additions in `apps/rendezvous/src/store.rs` (mailbox methods) + in-memory impl.
2. `Mailbox` config struct in `apps/rendezvous/src/config.rs`, wired into `Config`, with
   `MERIDIAN_RENDEZVOUS_MAILBOX__TTL_DAYS` / `MERIDIAN_RENDEZVOUS_MAILBOX__QUOTA_MB` env overrides
   and a fail-closed load error on an unparseable value (matching every other section).
3. Unit tests: enqueue → list returns it in order; delete-by-id removes only the matching row and
   only for the matching `recipient_pub` (a delete request naming another recipient's row id is a
   no-op, not an error); size accounting reflects `size_bytes` sums per recipient; `ttl_days = 0` is
   representable in config (this task only stores the value — the "genuinely disables the store"
   behavior is 8.5/8.6's job).

## Risks / notes
Mirror `data-model.md`'s mailbox table shape **exactly** (`id INTEGER PK` server-assigned,
`recipient_pub`, `blob BLOB` opaque, `arrived_at`, `expires_at`, `size_bytes`) — do not invent
columns. `blob` must never be deserialized inside this crate (no-serde-on-blob lint,
`tools/lint-no-serde-on-blob.sh`) — treat it as `OpaqueBlob`/`Vec<u8>` throughout, same discipline
as the existing bundle/route path. Do not let `mailbox_delete_by_ids` trust the id alone — always
filter by `recipient_pub` too, since 8.7's `MailboxAck` handler depends on this method being safe
to call with attacker-influenced ids.

## Tests
`cargo nextest run -p meridian-rendezvous --lib store::`

## Reviews
- **security-reviewer** — at-rest ciphertext-only shape, quota accounting correctness, the
  recipient-scoped delete invariant (this is the load-bearing check 8.7 relies on).
- **code-reviewer** — trait/config shape, fail-closed config discipline.

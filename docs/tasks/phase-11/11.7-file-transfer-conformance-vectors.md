# 11.7 — Conformance vectors for Phase 10's new wire surfaces

**Phase:** 11 — Review of Phase 10 · **Feature:** review fix (F7) · **Depends on:** — · **Status:** done

**User surface:** none — test-fixture/docs task, no production or client-visible change (Definition of
Done gate 9 doesn't apply).

## Goal
Pin this phase's new wire surfaces — the `mrd.file/1` manifest CBOR encoding, the BLAKE3 merkle chunk
framing, the resume-bitmap wire shape, the per-stream HKDF-export `info` byte layout, and
`SignalContent::IceRestartOffer`/`Answer` — into byte-fixed conformance vectors before a second client
(T11) can silently diverge from them.

## Scope
- **In:** `test-vectors/` — new fixtures for each wire shape above, generated via the repo's `xtask`
  vector-regeneration tooling following the existing `ratchet-v2.json`/`envelope-v2.json` pattern (new
  file(s) — naming decided by the architect sign-off below), plus updating `test-vectors/README.md`/
  `CLAUDE.md` to document the new file(s).
- **Out:** no change to any of the wire shapes themselves — this task locks in what already shipped in
  Phase 10, it does not modify it. Explicitly out of scope: extending the chunk wire shape with a proof
  field — if 11.8 later does that, its own task must add or amend the chunk-framing vector this task
  locks in today; that is 11.8's residual to flag, not this task's to anticipate.

## Deliverables
1. A short architect pre-check (folded into this task, matching the Phase-7 7.5 precedent) deciding: new
   vector file name(s)/grouping, and boundary-case sizes worth including (e.g. a single-leaf/empty-file
   manifest, a multi-leaf merkle proof, an all-missing vs. all-present resume bitmap).
2. New/updated `test-vectors/*.json` fixture(s) covering: `FileManifest` CBOR encoding, one `ChunkFrame` +
   its BLAKE3 leaf/merkle-proof construction, the resume-bitmap byte layout, the per-stream HKDF-export
   `info` layout (`stream_export_info`), and `SignalContent::IceRestartOffer`/`Answer` CBOR encoding.
3. `test-vectors/README.md` and `test-vectors/CLAUDE.md` updated to list the new file(s).
4. If a re-derivation test is warranted (matching the crypto conformance test pattern) rather than only
   the regenerate-and-diff self-consistency check — decide with the architect and add it if so.

## Risks / notes
`TODO: confirm` exact vector file name/grouping and boundary sizes — decide with the architect, don't
guess. No stream type currently consumes the HKDF-export primitive (N3, informational) — vector it
anyway, since it's still a pinned wire-relevant derivation, just an unused one today.

**Architect-ratified decision:**
1. **Two files, not one**, split by owning crate/domain: `test-vectors/file-transfer-v1.json`
   (`FileManifest`, `ChunkFrame`+BLAKE3 merkle, resume bitmap — all `meridian-streams`, its first vector
   file) and `test-vectors/session-substrate-v1.json` (`stream_export_info`, `SignalContent::IceRestartOffer`/
   `IceRestartAnswer` — core/envelope session-lifecycle plumbing, different crates from the first group).
2. **Boundary cases, refined**: manifest keeps single-leaf/empty-file (root = `BLAKE3(0x00)`); chunk
   framing adds both a short/non-power-of-two final chunk AND an odd-leaf-count case producing a
   `ProofStep::Promoted` step (the exact construction with a prior real domain-separation bug) alongside a
   clean power-of-two multi-leaf proof; resume bitmap needs a **mixed pattern crossing a byte boundary**
   (e.g. 9 leaves, received {0,1,3}) in addition to all-missing/all-present, since a uniform 0x00/0xFF
   bitmap can't pin bit order or catch an off-by-one; `stream_export_info` adds `sid = 0` and `sid =
   u64::MAX` to pin the 8-byte big-endian boundary; `IceRestartOffer`/`Answer` get one canonical vector
   each plus one with an empty `ice` candidate list.
3. **Re-derivation test required only for `stream_export_info`** (expose it via a `test_support` module
   mirroring `meridian_crypto::test_support`, add a dedicated re-derivation test in `apps/core` — same bug
   class as `x3dh.rs`'s divergent-label negative test). The other four wire surfaces are ordinary public
   serde/CBOR shapes already exercised by real round-trip/shape-assertion unit tests in-crate —
   `xtask regenerate-and-diff` self-consistency alone is sufficient, matching the accepted
   `federation-v1.json` precedent.

## Tests
Regenerate vectors via `xtask` and confirm no diff against committed fixtures; plus whichever crate's
`cargo nextest run` gains the new re-derivation test if one is added.

## Reviews
**architect** (mandatory — vector shape/boundary-case sign-off, matching the 7.5 precedent),
**code-reviewer**.

## Outcome
Two new vector files generated via a new `tools/xtask/src/vectors/{file_transfer,session_substrate}.rs`
from real code (not hand-authored): `test-vectors/file-transfer-v1.json` (FileManifest, ChunkFrame+BLAKE3
merkle, resume bitmap) and `test-vectors/session-substrate-v1.json` (stream_export_info,
SignalContent::IceRestartOffer/Answer), covering every architect-ratified boundary case. `stream_export_info`
made `pub(crate)` and exposed via a new `apps/core::test_support` module (a thin forwarding fn, since a
bare `pub use` of a `pub(crate)` item hits E0364 regardless of the containing module's own visibility —
marking it plain `pub` instead would have leaked it into `session`'s real public surface). A dedicated
re-derivation test (`apps/core/tests/stream_export_info_conformance.rs`) re-runs the real function against
every committed vector, per the architect's decision that this is the one wire surface (of five) needing
one beyond `xtask regenerate-and-diff` self-consistency.

Combined architect/code-reviewer pass: two non-blocking findings, both fixed in this same commit before
finalizing: (1) a doc comment mis-stated *why* the bare `pub use` failed (blamed `session`'s own public-ness
rather than the item's `pub(crate)` visibility, which is the actual E0364 trigger regardless of module
visibility — corrected, and the real reason for choosing a wrapper over just marking the item `pub`
clarified separately); (2) the divergent-domain-tag meta-test independently reimplemented the tag as a
hardcoded literal rather than mutating a copy of the real constant, unlike its stated `x3dh.rs` precedent —
fixed by exposing a new `STREAM_EXPORT_INFO_TAG` constant (mirroring `X3DH_INFO`) through `test_support`
and having the test mutate a copy of *that*. **PASS, zero blocking findings** after these fixes; every
ratified boundary case (empty-file manifest root = BLAKE3(0x00), a genuine `ProofStep::Promoted` step,
short/non-power-of-two final chunk, byte-boundary-crossing resume bitmap, sid=0/u64::MAX big-endian
boundaries, empty-ice-list signaling vectors) independently hand-verified byte-correct by the reviewer.
No wire-shape changes. `meridian-core` 174/174, full workspace clippy clean, `tools/check-docs.sh` clean,
`xtask vectors` regeneration confirmed deterministic and diff-free.

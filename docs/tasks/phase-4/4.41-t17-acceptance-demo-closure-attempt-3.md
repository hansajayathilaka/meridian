## Scope
- **In:** a live PTY run of the full demo script
  ([17-terminal-tui-client.md](../../architecture/features/17-terminal-tui-client.md)'s "Working output")
  for a **file-backed** account (the type that surfaced Defect B) and, environment permitting, an
  **OS-keystore** account (if this sandbox's `gnome-keyring`/dbus limitation — documented by 4.38's own
  Evidence 3 — still holds, fall back to `live_session_e2e`'s in-process OS-keystore coverage exactly as
  4.38 did, and say so explicitly again, not silently). Re-run `apps/tui/tests/live_session_e2e.rs` (now
  unconditional per 4.39) and confirm green. Re-run the T08 regression check,
  `bash harnesses/mitm-sim/run.sh` — same standing precedent 4.28 and 4.38 both held themselves to. Hold
  to the same two-independent-runs discipline 4.28/4.38 used (implementer once, `reviewer`/`test-engineer`
  once, independently) — not relaxed, given both of the two prior exit-gate attempts found a real defect
  this exact way.
- **Out:** any new feature code; fixing anything newly found live here. If a genuine third defect surfaces,
  report it honestly in this task's own Status section, do not fix it here, file a new task number
  (working number 4.42), and leave both the exit-criteria checkbox and the carry-forward note as still
  open — the same non-negotiable rule 4.28 and 4.38 both held.

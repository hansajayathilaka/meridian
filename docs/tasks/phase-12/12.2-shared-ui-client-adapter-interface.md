# 12.2 — `shared-ui` package + `MeridianClientAdapter` TS interface

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** — · **Status:** done

**User surface:** foundational — no screens yet, but this is the seam every browser/desktop screen
(12.7–12.9) and both concrete platform adapters (12.6, 12.13) build against. No TUI surface applies
(ADR 0012: SvelteKit/Tauri UI is out of the TUI's scope by construction).

## Goal
Scaffold the `shared-ui` pnpm package — Svelte visual primitives (message list, contact row, layout
shell) shared between the browser and desktop UIs per ADR 0012 — plus a platform-agnostic TypeScript
interface, `MeridianClientAdapter`, mirroring `core-api-contracts.md`'s operation surface (account
generate/open, chat send/receive, contacts/trust, stream/file ops, verification). Concrete platform
adapters (browser wasm-bindgen, desktop Tauri) implement this interface in later tasks; screens are
written once against the interface and a fake implementation, then reused by both shells unmodified.

## Scope
- **In:** `shared-ui` package scaffold (`package.json`, `pnpm-workspace.yaml` entry, build/lint/test
  scripts replacing `apps/web`'s current TODO placeholders where shared); the `MeridianClientAdapter`
  TypeScript interface; a `FakeMeridianClientAdapter` test double for screen-level component tests
  (in-memory, deterministic, no real crypto/network).
- **Out:** any concrete adapter implementation (browser: 12.13; desktop: 12.6); any actual screen
  (12.7–12.9); the `meridian-wasm` crate itself (12.10).

## Deliverables
1. `shared-ui/package.json`, `pnpm-workspace.yaml` entry.
2. `shared-ui/src/lib/adapter.ts` — the `MeridianClientAdapter` interface.
3. `shared-ui/src/lib/fake-adapter.ts` — `FakeMeridianClientAdapter` test double.
4. Base layout/primitive components used by later screen tasks (message list, contact row, shell).
5. `shared-ui/src/lib/adapter.test.ts` (or equivalent) exercising the fake adapter's contract.

## Risks / notes
`core-api-contracts.md`'s operation list is explicitly "illustrative," not exhaustive — it names no
bulk "list contacts"/"list conversations" query, which every screen needs. `TODO: confirm` — derive the
missing enumeration operations from what `apps/cli`/`apps/tui` already call into `meridian-core` for the
equivalent screens (grep their command handlers), rather than inventing new core behavior; if a genuinely
new core-level query is needed that neither existing client calls today, flag it back rather than adding
one silently — that would be a `meridian-core` API change requiring its own review, out of this task's
scope.

## Outcome
Landed `shared-ui/` (workspace entry in `pnpm-workspace.yaml`): the framework-agnostic
`MeridianClientAdapter` interface (`src/lib/adapter.ts`, each operation tagged with the CLI/TUI/core
call it was derived from), `FakeMeridianClientAdapter`, three Svelte primitives (`MessageList`,
`ContactRow`, `AppShell`), and a **reusable contract suite** — `runAdapterContractTests` exported on the
`shared-ui/contract-tests` subpath. Tasks 12.6 and 12.13 must run their concrete adapters through it
(with the hook capabilities set, so none of the trust-gate tests are skipped). 42 tests, `svelte-check`
and `eslint` clean, `pnpm install --frozen-lockfile` ok.

**Operations deliberately left out** (no existing client calls a core query for them, so nothing was
invented — this task forbade it): a conversation list / unread counts / last-activity (the TUI keeps
those in its own local `contacts.json`; a list is `listContacts()` + `loadHistory()`), a pixel/SVG QR
render (core only has `render_terminal`, so the interface has `renderQrText` — **12.8 may need a new
core-level render op, flag it there**), file resume/cancel/auto-accept/save-to-browser, and global
settings. Three operations are TUI-local rather than core (`loadHistory`, `deleteContact`,
`setPolicyOverride`); persistence is for 12.12/12.3 to bind.

**Review (architect + code-reviewer, one combined pass):** architecture PASS conditional on two fixes,
correctness PASS. Both conditions were fixed in this task and independently re-verified:
- `deleteContact` is now a *binding* "MUST NOT reset trust/block/pin state" rule (the fake models trust
  records and display entries separately); block → delete → re-add stays gated.
- The send gate is MUST, not SHOULD, for both `sendMessage` and `sendFile` (adapters re-check
  `can_send` in the same call; `blocked` and `warn` both reject `send-blocked`). `meridian-core`'s send
  path does not call `can_send` today, so the TUI is the only enforcer — a core-level enforcement is a
  `meridian-core` API question outside this task, and is what makes the contract suite the guard.
Fake-fidelity gaps and the TypeScript pin (`~5.9.3`; typescript-eslint/svelte-check exclude 7.x) were
fixed too.

**Ratified, not changed:** `registerAccount(server, invite)` / `publishBundle(server, otkCount)` stay
exposed because they mirror the TUI/CLI onboarding flow; folding bundle publishing (and the OTK count,
a protocol parameter a screen should not choose) into `registerAccount` is the stronger shape and is a
candidate for 12.13/12.6 to adopt. `markVerified(peerId)` takes no proof, mirroring core's
`mark_verified` — the verification screen (12.8) is the only guard until a core-side
`confirmSafetyNumber` exists.

**Not wired:** no CI or Justfile step runs the `shared-ui` tests yet (CI has no pnpm jobs at all, the
Justfile recipes are stubs). `apps/web`'s placeholder scripts are untouched since it doesn't consume the
package yet. Root `package.json`'s `"packageManager": "pnpm@9"` is an invalid version string
(pre-existing).

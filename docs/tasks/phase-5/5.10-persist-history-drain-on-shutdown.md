# 5.10 — Drain/flush-on-shutdown hook for `Effect::PersistHistory`

**Phase:** 5 — Review of Phase 4 · **Feature:** review fix (F10) · **Depends on:** — · **Status:** pending

## Goal
Close the `PersistHistory` drain-window flake found by 4.51's own test-engineer pass during restart
probing: a message that just rendered live can fail to survive a restart if the process is killed within
~2s of appearing, because its async write to `history.jsonl` hasn't landed on disk yet.

## Scope
- **In:** `apps/tui/src/lib.rs::run()` (no drain/flush hook currently exists on shutdown), and
  `apps/tui/src/worker.rs` near `run_persist_history`. Give history-persist effects a drain window or an
  explicit flush-on-shutdown hook before process exit.
- **Out:** Any other effect's shutdown durability — scoped to `PersistHistory` only, the one this
  finding names; a broader shutdown-durability audit is a separate concern if warranted later.

## Deliverables
1. A drain window or flush-on-shutdown hook ensuring in-flight `PersistHistory` writes complete before
   the process exits.
2. A regression test reproducing the current gap (kill within ~2s of a message rendering, confirm it's
   currently lost) that flips to passing once the fix lands.

## Risks / notes
Confirmed still present and still untested by this review's test-engineer pass — no reproduction test
exists anywhere in the current tree.

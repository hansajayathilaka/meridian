# Phase 3 — Review Report

**Reviews:** Phase 2 (Cross-Org Federation, tasks 2.1–2.17), the Phase-1 follow-ups 1.32/1.33 that
landed in the same window, and the untracked out-of-band PRs #36–#42 (figment config / ADR 0018,
Docker Hub publish pipeline, Dokploy deploy stack + fixes, coturn config fixes, CLI `wss://`).
Diff window `3ad5d49..9f81e1c` (~148 files, ~17.8k insertions). ·
**Date:** 2026-08-05 · **Reviewers:** code-reviewer, security-reviewer, architect, test-engineer

## Summary
Phase 2 is architecturally **sound** — ADR 0017 (C1–C7), ADR 0016's deferral obligations, ADR 0018,
the server⊬core dependency contract, and the six anonymity "must never" invariants all **hold** in
the code as it stands (server never decodes envelopes, no per-peer metric label, no contact graph,
bundle trust stays client-side, wss:// verifies certs with no insecure escape hatch, the 2.13 ratchet
fix is failure-atomic). The per-task reviews did their job on the crypto/opacity core.

But the sweep found **three blocking defects that per-task reviews structurally could not see**,
all on the federation *server* plane and all in the seams *between* tasks 2.6/2.7/2.8: (B1) the
outbound federation path enforces **no policy** — a `closed`/`allowlist` server still dials any
client-named domain, which in SRV mode is a client-driven SSRF / internal port-probe oracle; (B2) a
single silent TCP connection **wedges the entire inbound listener** (handshake runs inline in a
serial accept loop); (B3) **no timeouts on any outbound s2s I/O**, so a black-holed partner hangs a
client's whole WebSocket session and leaks the task + TLS link. None breaks confidentiality, but all
three break **availability** of exactly the federation feature Phase 2 shipped, and B1 also breaks
the admission boundary. These block the next build phase.

Below blocking: a rate-limit interaction that throttles ordinary cross-org chat to ~30 msg/min, an
unbounded stranger-driven storage amplifier in the message-request gate, a shared-private-CA
misconfiguration hazard the demo itself models, several dead/duplicated-work items the tracker
already flagged but never filed, and doc-sync/ratification debt (port 8444, the 1 MiB frame ceiling,
an unsigned Docker Hub publish that wants a short ADR).

## Verdict
**Blocked until F1, F2, F3 are resolved.** All three are availability/admission defects on the
federation server plane, in the 2.6/2.7/2.8 seams that per-task review could not reach, and each has
a clear, local fix. F4–F20 are should-fix within this review phase; F16 and the `ROUTE_REPLY_GRACE`
residual also carry an `/adr` obligation. No anonymity "must never" invariant is violated and the
crypto core is sound, so once the three blockers land the tree is green to proceed to the next build
phase (Feature 08 or 09). Next: `/plan-review-phase`.

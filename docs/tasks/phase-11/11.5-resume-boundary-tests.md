# 11.5 — Resume boundary tests: 0 chunks received / all-but-last chunk

**Phase:** 11 — Review of Phase 10 · **Feature:** review fix (F5) · **Depends on:** — · **Status:** done

**User surface:** none — coverage-only task (Definition of Done gate 9 doesn't apply).

## Goal
Close the two untested resume boundary cases — resume at 0 chunks received, and resume at all-but-last
chunk — through the full resume pipeline, not just the bitmap encoder in isolation.

## Scope
- **In:** `apps/streams/tests/resume_protocol.rs` — two new full-pipeline tests (through
  `ResumeRequest`/`send_missing_chunks`, mirroring the existing 8/13, 10/13, {2,5,9}-of-13 tests'
  structure): (a) the receiver has received zero chunks before the drop, forcing a full resend; (b) the
  receiver has received every chunk except the last (exercising the short final-chunk-size boundary).
- **Out:** no change to `apps/streams/src/resume.rs`'s bitmap encoding itself (its empty-case unit test
  already exists in isolation) — this task only adds pipeline-level coverage.

## Deliverables
1. `resume_at_zero_chunks_received_resends_the_whole_file` (or similar name) in
   `apps/streams/tests/resume_protocol.rs`.
2. `resume_at_all_but_the_last_chunk_recovers_the_short_final_chunk` (or similar name) in the same file,
   exercising the file-size boundary where the last chunk is shorter than the full chunk size.

## Risks / notes
Reuse the existing harness's peer/`ice_restart` scaffolding rather than inventing a new one; both new
tests should assert the same zero-wasted-resend-bytes property the existing tests already measure, for
consistency.

## Tests
`cargo nextest run -p meridian-streams --test resume_protocol`.

## Reviews
**test-engineer** (coverage-gap task), **code-reviewer**.

## Outcome
Added `resume_at_zero_chunks_received_resends_the_whole_file` and
`resume_at_all_but_the_last_chunk_recovers_the_short_final_chunk` to `apps/streams/tests/resume_protocol.rs`,
reusing the existing full-pipeline harness (real ratchet session, real `P2pSession::ice_restart`, real
wire-level `ResumeRequest`/bitmap/chunk resend) identically to the pre-existing 8/13 and {2,5,9} tests.
Test 1 confirms a full resend when nothing was delivered; test 2 uses a 787431-byte file (12 full
65536-byte chunks + a genuine 999-byte short final chunk) to pin the short-final-chunk resend length
exactly. Both correctly index the post-11.3 `BTreeMap<u64, Vec<u8>>` `pending_chunks` shape.

Combined test-engineer/code-reviewer pass: **PASS, zero blocking findings**. One non-blocking nit noted
(test 1's `resent_already_delivered_bytes == 0` assertion is vacuously true given nothing was delivered,
but sits immediately beside a strictly stronger exact-resend-set assertion that does the real pinning,
and the test's own comment already says so) — left as-is, not worth the churn. `apps/streams/tests/resume_protocol.rs`
4/4, full `meridian-streams` crate 72/72, clippy clean.

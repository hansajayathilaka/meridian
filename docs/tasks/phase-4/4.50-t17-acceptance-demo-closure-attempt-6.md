# 4.50 — T17 acceptance-demo closure (sixth exit-gate attempt)

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client (gap closure, phase re-exit gate) · **Depends on:** 4.49 · **Status:** pending

## Goal
Mirror 4.28's, 4.38's, 4.41's, 4.45's, and 4.48's role a sixth time: run the T17 demo script live, end to
end, for both account types — and, **only if it genuinely passes**, flip Phase 4's exit-criteria checkbox
and clear the tracker's carry-forward note. This is the task that actually closes Phase 4, if 4.49 did
what it claims.

## Scope
- **In:** a live PTY run of the full demo script from
  [17-terminal-tui-client.md](../../architecture/features/17-terminal-tui-client.md)'s "Working output"
  (unchanged since 4.48's own corrected version), for a **file-backed** account and an **OS-keystore**
  account, covering every step 4.48 already covered, with particular focus on the two steps 4.49's fix
  touches:
  1. onboarding → registered → bundle published → `Screen::Main`, both account types;
  2. initiator adds the responder by `mrd1:` id with petname "bob" and sends a first-contact message;
  3. responder sees the message request (key + safety number + intro) and accepts;
  4. **responder opens a chat with the accepted sender and confirms the sender's original intro message
     is present in the transcript** (4.42's affordance fix, re-confirmed; 4.49's own new fix, confirmed
     for the first time live), then replies;
  5. `^V`/`v` shows the same 60-digit safety number on both sides → mark verified on both, including the
     initiator marking their own plainly-added contact verified in the same session, without a restart
     (4.46's fix, re-confirmed);
  6. restart both peers (`pkill` + relaunch) and confirm contact list, petnames, **full history including
     the original intro message, with no duplicate**, and the ratchet session are all restored with no
     re-handshake (4.44's fix, re-confirmed; 4.49's own restart-parity fix, confirmed for the first time
     live);
  7. `meridian tui --export-json <path>` + `jq '.contacts[0].petname' <path>/contacts.json` (4.47's fix)
     returns `"bob"`.
  Also: record the file-backed session-start latency observed here and compare it against 4.43's/4.45's/
  4.48's own recorded numbers — a regression to minutes is a failure of this gate even if every functional
  step passes. Re-run the standing regression set every prior attempt held itself to: `cargo test -p
  meridian-tui --all-targets --no-fail-fast`, `cargo test -p meridian-cli --bins`, `cargo test -p
  meridian-tui --test live_session_e2e`, `bash harnesses/mitm-sim/run.sh` (T08 regression), `bash
  tools/lint-tui-no-cli.sh`, `bash tools/check-docs.sh`, `cargo clippy --workspace --all-targets -- -D
  warnings`, `cargo fmt --check`, plus 4.49's own new targets.
  Hold to the **two-independent-runs discipline** every prior attempt used — implementer once,
  `reviewer`/`test-engineer` once, independently. **Not relaxed:** five exit-gate attempts in a row have
  each found a real defect this exact way, and 4.48 itself is the specific instance where the two runs
  disagreed and the disagreement was the signal that mattered.
- **Out:** any new feature code; fixing anything newly found live here. **If a genuine defect surfaces,
  report it honestly in this task's own Status section, do not fix it here, file a new task (working
  number 4.51), and leave both the exit-criteria checkbox and the carry-forward note open** — the same
  non-negotiable rule every prior attempt held. Never weaken an assertion (this task's own, or any prior
  task's) to make the demo appear to pass.

## Deliverables

2. **Only if the demo genuinely passes:** a new `docs/architecture/tui-client.md` §12 documenting this
   attempt (§10/§11 stay frozen as historical record, per the existing convention);
   `docs/tasks/phase-4/README.md`'s T17 exit-criteria checkbox flipped; `docs/tasks/README.md`'s
   carry-forward note cleared and ▶ NOW/NEXT advanced to `/start-review-phase` for Phase 5.
3. Any residual coverage gap not closed by 4.49's own new tests, named explicitly rather than silently
   absorbed or silently dropped.

## Risks / notes
- **Hard join on 4.49 only** — a single-dependency join, unlike 4.45's/4.48's two-dependency joins, since
  this wave has exactly one fix task: 4.48's own finding was narrow and single-cause, with no second,
  independent defect bundled alongside it (unlike the fourth wave's 4.46+4.47).
- **Reuse 4.41's/4.45's/4.48's hard-won methodology instead of re-deriving it** (full detail in those
  tasks' Status sections): OS keystore setup, the initiator-role trap
  (`worker::run_send_message` compares raw pubkey bytes, not `mrd1:` id strings), a screen-scraping driver
  parsing narrow, single-line anchors, both peers running **concurrently** (offline delivery is T07, not
  built), distinguishing driver bugs from product defects before reporting anything.
- Nothing from the driver needs to be checked in — but the transcripts quoted in Status must be real
  output, not reconstructed.
- **Definition of Done gate 9:** no new TUI surface — this is a verification task (stated explicitly).

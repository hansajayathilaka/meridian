# 12.18 — T01/T08 conformance-vector byte-identity check across CLI/browser/desktop

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** 12.13, 12.15 · **Status:** pending

**User surface:** none directly — CI verification infrastructure. No TUI surface applies.

## Goal
Prove the feature spec's acceptance criterion — "identical safety numbers across platforms for the same
key pair (the T08 fixtures)" — by extending the existing `xtask`/`test-vectors/{identity-v1,
safety-numbers-v1}.json` conformance mechanism (today exercised only by native/CLI code) with a
WASM-side (via `meridian-wasm`) and desktop-side re-derivation of the same fixtures, asserting
byte-for-byte identity.

## Scope
- **In:** a harness (either a `tools/xtask` extension or a new `harnesses/cross-client-conformance/
  run.sh`) that feeds the existing frozen fixtures through `meridian-wasm` (headless) and the
  `apps/desktop` binary, and diffs the results against the CLI's own already-passing output.
- **Out:** adding new fixtures or changing the existing conformance-vector format — this task only adds
  new *consumers* of the already-frozen vectors, per `test-vectors/README.md`'s existing discipline.

## Deliverables
1. The harness/xtask extension.
2. A CI step running it, asserting byte-identical output across all three implementations for every
   existing `identity-v1`/`safety-numbers-v1` fixture.

## Tests
`bash harnesses/cross-client-conformance/run.sh` (or the confirmed xtask equivalent).

## Reviews
**test-engineer** (new harness, separate call per the task-tracking skill's guidance); **security-reviewer**
(this is the property that makes cross-platform safety-number verification meaningful — a silent
divergence here would be a real, safety-critical defect).

## Status

All five fixes landed, each at its own disjoint location:

- **N2** — [`docs/architecture/features/17-terminal-tui-client.md:102,104`](../../architecture/features/17-terminal-tui-client.md):
  demo script's `^N`/`^V` corrected to the real bindings `n`/`v`. Verified against the actual TUI
  keybinding source, `apps/tui/src/screens/contacts.rs` (`KeyCode::Char('n')` opens the add-contact
  flow at line 424, `KeyCode::Char('v')` opens `Screen::Verify` at line 433) — matches `tui-client.md`'s
  own reference table, which was already correct.
- **N3** — [`apps/core/src/trust.rs:430-438`](../../../apps/core/src/trust.rs): `observe_key_change`'s
  `ConflictingContact` guard simplified from a nested `if let Some(existing) = ... { if &existing.pubkey
  != previous_pubkey { ... } }` to a flat `if self.contacts.contains_key(&new_pubkey) { ... }`, with a
  comment explaining why the two are equivalent (the module's `contacts[k].pubkey == k` invariant — the
  only two insert sites both key by the contact's own `pubkey` — plus the early return just above that
  already guarantees `new_pubkey != previous_pubkey`, so any hit on `new_pubkey` is, by construction,
  always a different contact). Purely a rewording of the same check; the `Err`/success outcome for every
  input is unchanged.
- **N4** — [`apps/tui/src/screens/diagnostics.rs:46`](../../../apps/tui/src/screens/diagnostics.rs)
  (module doc comment, "Accepted risk" section): the `TODO: confirm` on `run_doctor_binary`'s `PATH`
  resolution replaced with a stated, closed decision — `PATH` lookup stays as-is, not hardened/pinned,
  because doing so would harden a boundary this task never actually widens; revisit only if a future
  task changes the trust assumption itself (e.g. `meridian tui` gaining a privilege level `meridian
  doctor` does not share), not as standalone follow-up work.
- **N5** — [`docs/adr/README.md:31`](../../adr/README.md): ADR 0022's summary-table row now leads with
  **"Superseded by 0023" (wrong binary — server, not client)** before the description of the
  superseded decision, instead of trailing it in the Source column; the Source column now carries an
  actual source citation ("executable-pipeline task, original scope") instead of duplicating the
  supersession note.
- **N6** — [`apps/tui/src/surface.rs:229-249`](../../../apps/tui/src/surface.rs): added an explicit doc
  comment on `PaletteAction::PushPane` naming it "the sanctioned third-party extension point", and a
  new "**Not an extension point.**" paragraph on `PaletteAction::PushScreen` stating a third-party
  feature crate cannot add cases to the crate-local `Screen` enum and must use `PushPane` instead. Left
  `find_binding` (task 5.12's `PaletteAction`-adjacent doc comment, further down the same file) fully
  untouched.

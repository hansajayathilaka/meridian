# 9.8 — Lock `MailboxAck{ids:[]}` conformance vector

**Phase:** 9 — Review of Phase 8 · **Feature:** review fix (F8) · **Depends on:** — · **Status:** pending

## Goal
Close a conformance-vector gap directly echoing Phase 7's F7 finding ("conformance vectors cover only
one canonical shape"): `test-vectors/c2s-v1.json`'s `mailbox-ack` vector locks only the populated
`MailboxAck{ids:[1,2,3]}` shape. `MailboxAck{ids:[]}` is a real, reachable wire shape — used whenever
`discard_pending_mailbox_ack` empties the accumulator before a flush — that's proven for
`meridian-proto`'s own encode/decode symmetry (`apps/proto/tests/roundtrip.rs::mailbox_ack_and_ack_ok_roundtrip`)
but not byte-locked across implementations, so CLI/WASM/mobile could silently drift on the empty-array
CBOR shape (`0x80`) with nothing to catch it.

## Scope
- **In:** add a `mailbox-ack-empty` case to `tools/xtask/src/vectors/c2s.rs`, following the same
  non-vacuity discipline the rest of task 8.4's vectors use (neutralize-field/confirm-fail/restore
  cycle), and lock its `frame_hex` in `test-vectors/c2s-v1.json` via the repo's standard `xtask`
  regeneration path.
- **Out:** No other vector shapes — this task is scoped to the one named gap.

## Deliverables
1. A new `mailbox-ack-empty` conformance vector in `test-vectors/c2s-v1.json`, generated via `xtask`,
   with a non-vacuity check proving the vector would actually catch a regression in empty-array
   encoding.

## Risks / notes
No file overlap with other phase-9 tasks — independent. Follow the exact regeneration/verification
procedure task 8.4 (and Phase 7's 7.5) used, since both are recorded as having caught real
fixture-corruption or non-vacuity issues by doing this carefully rather than trusting a first pass.

## Tests
`cargo run -p xtask -- vectors check` (or the repo's equivalent vector-lock verification command),
`cargo nextest run -p meridian-proto`.

## Reviews

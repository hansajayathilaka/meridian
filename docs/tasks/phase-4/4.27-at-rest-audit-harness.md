# 4.27 — At-rest audit harness

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client · **Depends on:** 4.15, 4.16, 4.19, 4.20, 4.22 · **Status:** pending

## Goal
Prove, end to end, that no file the TUI writes ever contains a message body, petname, or key material —
the on-disk counterpart to `demo opacity-audit`, and one of T17's explicit acceptance criteria.

## Scope
- **In:** script a full conversation headlessly (onboard → add contact → chat → verify) driving the
  `App::update` function directly (no real terminal needed, since `update`/`render` are pure), then scan
  every file the run wrote and assert none contains a message body, petname, or key material in
  plaintext.
- **Out:** the store's sealing implementation itself (4.15 owns it) — this task is the audit that
  exercises it under realistic usage, not a redesign.

## Deliverables
1. `apps/tui/tests/at_rest_audit.rs` (or a harness under `harnesses/`, matching `demo opacity-audit`'s
   pattern): scripted conversation + file scan + assertion.

## Risks / notes
- **Failing this test is a security defect, never something to relax.** If it fails, the leak gets fixed
  in the store (4.15) or the screen writing the offending data — the audit itself never gets loosened.

## Tests
`cargo nextest run -p meridian-tui --test at_rest_audit`

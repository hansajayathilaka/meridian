## Outcome

**Verdict: GO — Phase 10's exit criteria are now met.** Full re-run transcript:
[10.24-demo-transcript.md](./10.24-demo-transcript.md).

**Part 1 (real `meridian send`, real rendezvous, real WebRTC, multi-chunk, byte-identical)**:
re-run on the final branch tip (10.19–10.23 included) via a throwaway, uncommitted `#[test]` under
`apps/cli/tests/`, per 10.17's own precedent — nothing from the driver is checked in. **PASS, 5/5**
consecutive clean runs, distinct sha256 each time (genuine fresh transfers). Unaffected by
10.19–10.23's changes, as expected (those tasks touch signaling/restart, not the ordinary
dial/transfer path). One genuine flaw was found and fixed in the throwaway driver itself, not in
shipped code: an early version predicted which side would be the dial initiator by comparing the
*encoded* `mrd1:...` id strings, which does not necessarily agree with `send.rs`'s own raw-public-
key-byte comparison — causing both sides to sometimes (independently, correctly) compute themselves
as initiator against the test's wrong prediction, surfacing as a real but harness-only
"unexpected signaling payload during answer" on both sides roughly half the time. Fixed by spawning
both sides symmetrically and observing the actual outcome from stdout instead of predicting it; not
a tracker finding since it never touched shipped code.

**Part 2 (network cut + `ice_restart()` + resume, real netns/veth — 10.17's original blocking
finding)**: task 10.23 already re-ran `tools/netns-kill-resume.sh run` live, 3/3 clean. Per this
task's own instructions, re-run again independently rather than trusting 10.23's report alone: **2/2
further clean runs**, live, real, on the branch tip including 10.23's own commit — sender/receiver
sha256 match, `resend_ratio=0`, resume bitmap genuinely delivered over the renegotiated data channel.
This is the direct, repeated, independent confirmation that the original `WebRtcTransport::ice_restart`
no-op — the actual defect that held Phase 10's exit gate open since 10.17 — is fixed for the real
`mrd.file/1` scenario the feature spec's own demo script names.

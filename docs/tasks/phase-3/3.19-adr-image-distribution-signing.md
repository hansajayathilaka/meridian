# 3.19 — ADR: container image distribution + signing

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F16 remainder) · **Depends on:** — · **Status:** done

## Goal
Ratify `ghcr.io` as the container distribution channel and make an explicit, recorded signing
decision — the last unratified supply-chain choice from Phase 2's window.

## Scope
- **In:** a short ADR (proposed **0019**, same weight class as ADR 0018) recording (a) `ghcr.io` +
  the built-in `GITHUB_TOKEN` (no long-lived credential) as the channel, (b) the tag policy
  (`:latest` + short-sha), (c) the signing/provenance decision — adopt cosign/attestations **or**
  consciously defer with a recorded residual and a named trigger. Cross-link from
  `docs/operations/docker-image.md`.
- **Out:** **the Docker Hub → ghcr.io migration itself, which already landed after the report was
  written** — do not redo it; the ADR records an already-made choice. Also out: Dokploy-as-target,
  coturn fixes, `wss://` (the report judges none of them ADR-worthy). If the ADR chooses to sign, the
  *implementation* is a follow-up task, not this one.

## Deliverables
1. `docs/adr/0019-container-image-distribution.md`.
2. `docs/adr/README.md` index row.
3. `docs/operations/docker-image.md` cross-link.

## Risks / notes
- The migration already removed the long-lived-credential concern; the ADR must describe the world as
  it now is, not re-argue Docker Hub.
- Unsigned images remain the open residual — if deferring, name the trigger that reopens it
  (e.g. "before the first tagged release" / "before any third party is told to pull this image").

## Outcome
Wrote [ADR 0019](../../adr/0019-container-image-distribution.md) ratifying the already-landed
`ghcr.io` channel (GITHUB_TOKEN auth, no long-lived secret) and `:latest` + `:<short-sha>` tag
policy, plus a new decision: defer image signing/provenance (cosign/SLSA), recording an `R1`
residual (unsigned images, no cryptographic provenance) with a named reopening trigger (first
tagged release, or the first third party told to pull the image). Added the ADR index row and a
cross-link + residual pointer in `docs/operations/docker-image.md` §1.

Reviews: architect + security-reviewer (combined pass) — both **pass**; verified every pipeline
fact against `docker-publish.yml` (accurate), confirmed the residual's security framing is
orthogonal to Meridian's E2EE/anonymity invariants (cross-checked against threat-model.md and the
anonymity-model "must never" list; a directly analogous existing residual — browser code not
binary-signed — already exists in `anonymity-and-retention.md`), confirmed no out-of-scope
pipeline/code changes landed. Two non-blocking nits applied: promoted the residual into its own
`## Accepted residual risks` / `R1` section matching ADR 0016/0017's house style, and de-linked the
loose "C7-class" reference in favor of a properly-cited ADR 0017 C1–C7 pointer. devops — **pass**;
independently verified every operational claim (auth mechanism, tag policy, permissions scope,
`dokploy.env.example` default) against the live pipeline/config files, confirmed zero pipeline/
compose files were touched by this task.

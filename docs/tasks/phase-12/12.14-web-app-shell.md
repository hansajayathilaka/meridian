# 12.14 — `apps/web` app shell

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** 12.13, 12.7, 12.8, 12.9
· **Status:** pending

**User surface:** the browser client itself — this task is what turns `apps/web`'s current scaffold
into a real, servable app. No TUI surface applies (new client platform, not a new protocol feature).

## Goal
Wire SvelteKit routes/build config around the browser adapter (12.13) and the shared screens
(12.7–12.9) into a servable static bundle (`meridian-web`, the feature spec's deliverable 1), replacing
`apps/web`'s current `package.json` TODO scripts (`dev`/`build`/`lint`) with real ones. Adds the CSP
baseline `<meta>`/header configuration — the technical half of deliverable 3 (the prose half is task
12.19).

## Scope
- **In:** SvelteKit route structure wiring 12.7–12.9's screens to 12.13's real adapter; `vite.config.ts`
  build config (this is also where the <4 MB gzipped WASM bundle-size property starts being measured
  for real, not just 12.10's smoke-build report); a CSP baseline (script-src/connect-src restricted to
  what the WASM core + WebRTC signaling actually need, no inline scripts).
- **Out:** the deployment-guide prose itself (12.19); the interop-matrix CI job (12.17) — this task
  produces the buildable artifact that job later drives.

## Deliverables
1. `apps/web/src/routes/**` — real routes replacing the scaffold's placeholder `main.ts`.
2. `apps/web/vite.config.ts`.
3. CSP baseline config (meta tag or server-header equivalent, documented for whichever the
   `demo/two-orgs`-style deployment actually uses).
4. `apps/web/package.json` — real `dev`/`build`/`lint` scripts.
5. `pnpm --filter web build` produces a buildable static bundle.

## Risks / notes
`apps/web/CLAUDE.md`'s existing rules bind this task directly: no bespoke crypto/wire types in JS/TS,
and "leak nothing the anonymity model forbids — no plaintext, identifiers, or contact metadata to logs,
analytics, storage, or third-party requests." The CSP baseline is one concrete enforcement of the
second rule (no unexpected third-party `connect-src`).

## Tests
`pnpm --filter web build` + `pnpm --filter web test`.

## Reviews
**code-reviewer**; **security-reviewer** (CSP is a real security control; also confirms
`apps/web/CLAUDE.md`'s leak-nothing rule holds in the built bundle, not just the source).

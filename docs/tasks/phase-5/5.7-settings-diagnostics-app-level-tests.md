# 5.7 — App-level reconciliation tests for Settings/Diagnostics

**Phase:** 5 — Review of Phase 4 · **Feature:** review fix (F7) · **Depends on:** — · **Status:** pending

## Goal
Close the App-level test coverage gap for Settings and Diagnostics — the same gap class (a live-UI
reconciliation path invisible to lower-layer tests) that took six gap-closure waves to find and fix for
contacts/requests/chat in Phase 4. Neither screen currently has a test combining a real key event, a
real worker dispatch, and reconciliation of the completed effect back into the live screen.

## Scope
- **In:** New App-level tests in the style of `apps/tui/tests/accept_to_chat.rs` (real key events, real
  `worker::dispatch`, real sealed `$MERIDIAN_HOME`) for: Settings (real key edit → real
  `Effect::SaveSetting` → confirm persisted/session-only outcome renders) and Diagnostics (`Ctrl+K` →
  real `Effect::RunDoctor` outcome rendered, including the not-on-`PATH` failure path).
- **Out:** Any production code change — this task is test-only, unless the new tests reveal an actual
  reconciliation bug (in which case, treat that as a new finding requiring its own follow-up, not silent
  in-task scope creep — flag it explicitly per this project's "report, don't quietly patch around it"
  discipline, same as 4.41/4.45/4.48's own precedent).

## Deliverables
1. `apps/tui/tests/screens_settings.rs` (or a new file) gains a real-key-event/real-worker test proving
   a setting change round-trips through the live screen.
2. `apps/tui/tests/screens_help_palette.rs` (or a new file) gains a real-key-event/real-worker test
   proving a `RunDoctor` result — including its failure path — renders in the live diagnostics pane.

## Risks / notes
If either new test finds a genuine reconciliation bug (mirroring Defect C's discovery pattern), stop and
report it rather than silently fixing it inside this test-only task — that would blur this task's scope
and its review sign-off. Report to the phase's own tracking, name it as a new finding.

## Tests
`cargo nextest run -p meridian-tui --test screens_settings --test screens_help_palette --test run_worker_settings`

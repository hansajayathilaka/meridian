# 4.20 — Chat / conversation screen

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client · **Depends on:** 4.4, 4.15, 4.19 · **Status:** pending

## Goal
Land the main conversation experience: scrollback, composer, delivery state, restart-persistent
history — gated by T08's send rules so a blocked contact cannot be messaged from this screen either.

## Scope
- **In:** conversation pane with scrollback, multi-line composer, per-message delivery state, unread
  markers, restart-persistent history via 4.15's store, local dedup by `mid`. Composer consults 4.4's
  `can_send` gate before every send — `Blocked`/`Warn` states surface here even though the modal UI
  itself is 4.22's. Failure copy for an offline peer (pre-T07) must say "not delivered — offline" and a
  retry action, **never** "will deliver later" ([tui-client.md §7](../../architecture/tui-client.md#7-what-the-user-sees-when-things-go-wrong)).
- **Out:** the Verify screen and its modals (4.22); message-request queue (4.21).

## Deliverables
1. `apps/tui/src/screens/chat.rs`.
2. Screen-snapshot tests; a test asserting a `Blocked` contact's composer refuses to enqueue a send
   (defense in depth alongside 4.4's own gate test — this one is UI-level); a test asserting no
   "delivered when they come online" language appears anywhere in failure copy.

## Tests
`cargo nextest run -p meridian-tui --test screens_chat`

## Reviews
- **security-reviewer** — required; this is where 4.4's send-gate actually gets wired into the UI a
  human uses, and where a "make sending less annoying" regression would first appear.

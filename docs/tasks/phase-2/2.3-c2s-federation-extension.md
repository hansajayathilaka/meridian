# 2.3 — c2s extension for federation (hint fields, error codes, vectors)

**Phase:** 2 — Cross-Org Federation · **Feature:** T06 — Cross-Org Federation · **Depends on:** 2.2 · **Status:** pending

## Goal
Extend the client↔server contract so a client can name a **foreign** target through its **own**
server — the wire encoding of the routing invariant — as one atomic, vector-checked change to a
contract existing clients already speak.

## Scope
- **In:** `Fetch.hint`; `RouteBody.to_hint`; the federated `Deliver` origin field per 2.1's decision;
  new error codes (`fed_denied`, `fed_unreachable`, `not_found_at_hint`); backward compatibility for
  existing hint-less clients; doc + vector regeneration. Also: resolve the delegated
  [rendezvous-protocol-v1 §8](../../api/rendezvous-protocol-v1.md) `TODO: confirm` by **re-deferring
  the normalized-schema + Postgres question to T07**, with its reason recorded.
- **Out:** any server behaviour that consumes the new fields (2.7, 2.8); client error copy (2.9).

## Deliverables
1. `apps/proto/src/msg.rs`: optional `hint` / `to_hint` fields
   (`#[serde(default, skip_serializing_if = ...)]` so existing vectors stay byte-identical when
   absent) plus the new `error_codes` constants.
2. [docs/api/rendezvous-protocol-v1.md](../../api/rendezvous-protocol-v1.md): op table, error-code
   list, §4 routing, §8 simplifications — including the T07 re-deferral and its reason.
3. The matching comment update in `apps/rendezvous/src/store/sqlite.rs`.
4. Reconciliation of [wire-protocol.md §2](../../api/wire-protocol.md), which specifies
   `fetch_bundle {target, hint}` and `deliver {from_server, blob}` while the implementation has
   `Fetch{target}` and `Deliver{from}` — spec and code disagree in exactly the fields federation
   depends on. Make them agree; 2.1 names which shape is canonical.
5. Regenerated `test-vectors/*` — assert **no diff** for the absent-field cases.
6. `apps/proto/tests/roundtrip.rs` cases: hint present / absent / empty / over-length.

## Risks / notes
- The hint crosses the wire as a **plain domain string**. The server must never parse `mrd1:` IDs —
  that needs `meridian-identity` and breaks `tools/lint-server-no-core.sh`. Parsing stays client-side
  in `apps/identity/src/id.rs`. State this in the doc.
- `TODO: confirm`: max hint length, and whether the server validates LDH form. `validate_hint` already
  exists client-side; duplicating it server-side is the dependency trap.
- The new `Fetch` field sits next to the `tamper` test hook — keep the F17 discipline (feature-gated,
  absent from release builds, and covered by the package-scoped default-features CI step).
- **Why T07 and not here:** Feature 06 adds no new persisted state — the federation map, policy and
  allowlist are config, rate limits are in-memory, reachability is live `Registry` state, and the
  bundle server B serves is the blob it already stores. T07's mailbox is the first feature that needs
  per-envelope rows, TTL sweeps and quota accounting, i.e. the first consumer a normalized schema
  would have.

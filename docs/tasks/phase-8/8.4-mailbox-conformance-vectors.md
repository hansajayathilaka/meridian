# 8.4 — Conformance vectors for the mailbox wire fields

**Phase:** 8 — Offline Ciphertext Mailbox · **Feature:** T07 · **Depends on:** 8.3 · **Status:** done

## Goal
Lock 8.3's wire shapes into byte-exact conformance vectors so client and server implementations
cannot silently drift, matching every other wire change's discipline (ADR 0016/6.5's precedent).

## Scope
- **In:** regenerate the c2s conformance vector file (`test-vectors/` — the same file 8.3's version
  bump touches) with existing cases byte-identical, plus new cases: `RouteOk{delivered:true}` (no
  `queued`, byte-identical to pre-8.3), `RouteOk{delivered:false, queued:true}`,
  `Deliver{from,blob}` (no `mailbox_id`, byte-identical to pre-8.3),
  `Deliver{from,blob,mailbox_id:Some(n)}`, `MailboxAck{ids:[...]}`, `MailboxAckOk{}`,
  `Err{code:"mailbox_full"}`.
- **Out:** federation vector file changes only if `fed_error_codes::MAILBOX_FULL` needs its own
  vector case (check whether `federation-v1.json` vectors cover error codes at all before adding
  one — don't invent a vector category that doesn't otherwise exist).

## Deliverables
1. Regenerated vector file(s) via the existing `xtask` regeneration path (same tool 7.5 used).
2. A test proving the existing (pre-8.3) vectors are byte-identical after regeneration — the
   backward-compatibility claim, verified, not asserted.
3. New vector cases listed above, each independently loadable and decodable.

## Risks / notes
Non-vacuity matters here the same way it did for 7.4/7.5: prove each new vector case actually
exercises the new field (e.g. a `queued:true` case that a decoder ignoring the field would still
pass is not a real conformance case) — neutralize the field read and confirm the corresponding test
fails before restoring it, the same discipline 7.4 used for `eid` dedup.

## Tests
`cargo nextest run -p meridian-proto --test conformance`

## Reviews
- **architect** — re-derives at least one new vector's bytes by hand (or independently re-runs the
  regeneration) rather than trusting the tool output, matching 7.5's precedent.
- **test-engineer** — non-vacuity of each new case.

## Status
**Done.** Regenerated `test-vectors/c2s-v1.json` via `cargo run -p xtask -- vectors` (the same
`xtask` path 7.5 used) after extending `tools/xtask/src/vectors/c2s.rs`'s `generate_c2s` with seven
new cases: `route-ok-delivered` (`RouteOk{delivered:true}`, no `queued` key — pre-8.3 shape),
`route-ok-queued` (`RouteOk{delivered:false, queued:true}`), `deliver-no-mailbox-id`
(`Deliver{from,blob}`, no `mailbox_id` key — pre-8.3 shape), `deliver-with-mailbox-id`
(`Deliver{from,blob,mailbox_id:Some(42)}`), `mailbox-ack` (`MailboxAck{ids:[1,2,3]}`),
`mailbox-ack-ok` (`MailboxAckOk{}`), and `err-mailbox-full` (`ErrBody{code:"mailbox_full"}`).
`git diff` on the regenerated file is purely additive to the seven pre-8.3 vectors (plus the file's
own `note` string) — confirmed by inspection and locked by a new hardcoded-oracle test,
`apps/proto/tests/conformance.rs::pre_8_3_vectors_are_byte_identical_after_8_4_regeneration`, which
compares each pre-8.3 vector's committed `frame_hex` against its exact byte value copied from the
pre-8.4 commit tree (`cc47eb7`), independent of whatever the file currently says.

`test-vectors/federation-v1.json` already had an error-code vector category (the `err` case,
`fed_error_codes::NOT_FOUND`) — per this task's Scope/Out clause, this means adding
`fed_error_codes::MAILBOX_FULL` as an `err-mailbox-full` case within that existing category is not
inventing a new one, so it was added (`tools/xtask/src/vectors/federation.rs`). No other federation
vector or handler code touched.

`apps/proto/tests/conformance.rs` was extended to independently re-derive the new c2s vectors
(`RouteOk`, `Deliver`, `MailboxAck`, `MailboxAckOk` match arms, and `error_codes::MAILBOX_FULL`
added to the recognized-code assertion), closing the loop the same way it already did for
`Fetch.hint`/`RouteBody.to_hint`.

**Non-vacuity**, performed exactly per this task's Risks/notes discipline (7.4's precedent) — for
each of the three cases most likely to pass vacuously if a decoder just ignored the field, the
conformance test's field read was temporarily replaced with a hardcoded stub, the test was run to
confirm it *fails*, then the real read was restored and the test re-run to confirm it passes again:
- `RouteOk.queued`: stubbed `queued: fields["queued"].as_bool().unwrap()` → `queued: false`.
  Result: `route-ok-queued`'s `frame_hex` assertion failed (`...f4` vs. committed `...f5` with the
  `queued` key), confirming non-vacuity. Restored; passes.
- `Deliver.mailbox_id`: stubbed the field read → `mailbox_id: None`. Result:
  `deliver-with-mailbox-id`'s `frame_hex` assertion failed (missing the `mailbox_id` key/value
  entirely). Restored; passes.
- `MailboxAck.ids`: stubbed the field read → `ids: Vec::new()`. Result: `mailbox-ack`'s `frame_hex`
  assertion failed (empty CBOR array `80` vs. committed `83010203`). Restored; passes.

Each neutralization/restore is documented inline as a comment directly above the corresponding match
arm in `apps/proto/tests/conformance.rs`, and the file diffs back to byte-identical with the restored
state (`diff` against a pre-neutralization backup returned no differences).

Files touched: `tools/xtask/src/vectors/c2s.rs`, `tools/xtask/src/vectors/federation.rs`,
`test-vectors/c2s-v1.json`, `test-vectors/federation-v1.json`, `apps/proto/tests/conformance.rs`,
`test-vectors/CLAUDE.md` (scoped-memory note update). No `apps/rendezvous` or route-handler code
touched, per this task's Scope.

`frame_hex` (last byte `0x10` instead of the generator's actual `[0x11u8; 32]` output) — this was

regeneration producing the correct byte and changing nothing else), most likely introduced by an
environment interruption between implementation and review. Both `c2s_vectors_match_real_encoding`
and this task's own new `pre_8_3_vectors_are_byte_identical_after_8_4_regeneration` test were
correctly failing against the corrupted file — proof the backward-compat test is genuinely
non-vacuous, catching exactly the kind of drift it exists to catch. **Fixed** by regenerating via
`cargo run -p xtask -- vectors` and confirming via full diff that only the one corrupted byte
changed back to its correct value, no other vector touched. **Verdict after fix: PASS**, zero
remaining blocking findings.

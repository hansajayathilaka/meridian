# 3.5 — Stop the reachability pre-check from double-spending route budgets

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F4) · **Depends on:** 3.4 · **Status:** pending

## Goal
One federated message must cost one route unit and one per-account unit, not two — ordinary
cross-org chat currently throttles at ~30 msg/min (≈1 message per 2 s).

## Scope
- **In:** exempt 2.8's internal reachability pre-check from `check_route` (preferred — it is not a
  client-driven op) **or** re-ratify the defaults ×2; re-derive `federation_abuse.rs`'s budget
  arithmetic; correct the stale 2.6 rationale comment at `config.rs:280`.
- **Out:** changing the limiter data structure; 3.7's single-dial change (which does not fix the
  accounting on its own).

## Deliverables
1. `apps/rendezvous/src/federation/{outbound,inbound}.rs` — the accounting change.
2. `apps/rendezvous/src/config.rs` — doc comments stating the **true** per-message cost.
3. New cases in `apps/rendezvous/tests/federation_abuse.rs` — N sustained cross-org messages under
   the documented budget all succeed; the documented org-wide route throughput is actually
   achievable; per-account counters bump once per message.

## Risks / notes
- The exemption must not be reachable by any client-driven op — otherwise it becomes a free
  rate-limit bypass, inverting the fix.
- This changes what ADR 0017 C5's per-account axis actually meters; architect must ratify rather
  than have it assumed.

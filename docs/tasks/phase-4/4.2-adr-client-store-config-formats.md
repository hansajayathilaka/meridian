# 4.2 — ADR 0021: client-local store & config formats

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client · **Depends on:** — · **Status:** done

## Goal
Ratify, as a binding ADR, the at-rest posture and format of everything the TUI writes to disk, so the
store (4.15) and config (4.14) tasks implement a decided shape rather than each inventing one.

## Scope
- **In:** ADR 0021 deciding (a) JSON documents sealed with `meridian_crypto::at_rest::seal`
  (XChaCha20-Poly1305) under the key derived from the account key via `STORE_KEY_INFO` — the same
  mechanism `sessions.bin` already uses — for `contacts.json`, `history/*.jsonl`, `outbox.json`; (b)
  `state.json` deliberately **unsealed** but constrained to contain no petname/message body/key
  material (view geometry + conversation index only) — an invariant the at-rest audit (4.27) checks;
  (c) TOML for `config.toml`, human-edited, never rewritten wholesale by the app; (d) explicit
  `meridian tui --export-json <path>` as the **only** unsealed-export mechanism. Record the rejected
  alternative `store.encrypt = false` (a persistent-plaintext opt-out) with reasoning — realizes
  [data-model.md §2](../../architecture/data-model.md#2-client-local-store-encrypted-via-secretstore-key)
  for the terminal client. Full schemas proposed in
  [tui-client.md §5](../../architecture/tui-client.md#5-local-store--configuration) are what this ADR
  ratifies or amends.
- **Out:** packaging (4.1); any code.

## Deliverables

## Risks / notes
- This is the ADR the security-reviewer will hold every later T17 store/config task against — get the
  sealing boundary (what's sealed vs. `state.json`'s exception) unambiguous.
- Migration policy (refuse-to-open a newer schema version, `.bak` before forward-migrating) belongs here
  too, since it's a format decision, not an implementation detail.

## Status
Done. `docs/adr/0021-client-local-store-config-formats.md` accepted: sealed JSON (`at_rest::seal`) for
`contacts.json`/`history/*.jsonl`/`outbox.json`, unsealed `state.json` restricted to view-geometry +
an opaque non-identifying conversation handle, TOML config via figment, `--export-json` as the only
unsealed-export path, `store.encrypt = false` explicitly rejected. Combined **architect** +
**security-reviewer** review (both required) failed on first pass with four findings, all fixed
in-place: (1) `state.json`'s "no contact ID" condition contradicted its own "conversation index"
allowance — resolved by requiring an opaque, locally-generated handle instead of any pubkey/id/
positional index, with the 4.27 audit's scan clause and task file updated to match (also scans for
contact-identifier-shaped content now, not just petname/body/key); (2) `data-model.md §2`'s "whole
store sealed" claim contradicted this ADR's plaintext `config.toml`/`state.json` — amended with a
scoped exception sentence naming both; (3) no fail-closed condition existed for a sealed file that
fails to *decrypt* (vs. a version mismatch) — added condition 5b, matching `chat.rs`'s existing
`sessions.bin` precedent (fail-closed on AEAD-open failure, fall back to default only on `NotFound`);
(4) clarified `figment` is read/merge-only, comment-preserving write-back is a 4.14 implementation
choice (e.g. `toml_edit`), not something this ADR's tool choice already provides. `bash
tools/check-docs.sh` passes (links resolve).

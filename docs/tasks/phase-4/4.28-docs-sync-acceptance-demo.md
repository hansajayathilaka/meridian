## Status
Done — with an honest, non-passing result for one of the two acceptance demos, deliberately not
papered over. Per this task's own explicit scope ("verification + doc reconciliation only — no new
feature code"), no fix was attempted for what was found; it's carried forward instead.

**T08's acceptance demo genuinely passes end to end**: `bash harnesses/mitm-sim/run.sh` exits 0, 0
silent successes against a `verified` contact, 0 successes against `pinned` without the exact
verification-ux.md warning shown, including through 4.9's recovery window. Track T08 (4.3–4.10) is
fully closed.

**T17's acceptance demo does not pass today** — confirmed by actually running `meridian tui` in a live
terminal (twice independently: once by the implementer, once again by the reviewer, both reproducing the
identical hang). It reaches Onboarding, proceeds through ChooseStore → OrgHint, then hangs indefinitely
on "Generating your identity… please wait…" once submitted. Root cause: `apps/tui/src/lib.rs::run_worker`
is still task 4.11's original inert placeholder — it echoes every dispatched `Effect` straight back as
`WorkerEvent::Completed` with no outcome populated, so no screen's `handle_worker` ever advances past its
first real effect. `Ctrl-Q` still quits and restores the terminal cleanly from the stuck state. This is
more fundamental than screen-navigation wiring alone (there's also no `Preflight`/`Screen::Main` —
`App::new()` always starts on Onboarding), and neither gap was ever assigned its own task across this
phase's 28-task breakdown. Every individual T17 screen (Onboarding through Diagnostics) is genuinely
built and unit/snapshot-tested in isolation — the gap is specifically in wiring them into one live,
run-to-run session, not in the screens' own logic.

This is now documented in three places so it can't be lost: [tui-client.md
§10](../../architecture/tui-client.md#10-current-implementation-status-as-of-task-428) (the full
writeup), [tui-screen-flow.mermaid](../../architecture/diagrams/tui-screen-flow.mermaid) (the real
screen stack + real-vs-missing transitions, including that the three global chords F1/Ctrl-K/Ctrl-R
remain reachable even from the stuck state), and [docs/tasks/README.md's NOW/NEXT carry-forward
section](../README.md#live-carry-forwards-not-owned-by-any-open-task) (flagging it as unowned, for a
future build phase to schedule a dedicated "Preflight/Main navigation + real `run_worker` effect
execution" task before this demo can pass).

# 4.18 — Extension registry (`meridian-tui::surface`)

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client · **Depends on:** 4.11 · **Status:** pending

## Goal
Land the registry every later feature's TUI surface plugs into — the mechanism behind Definition of
Done gate 9 — so a future feature registers a renderer/command/pane without editing the TUI core.

## Scope
- **In:** three registration points per
  [tui-client.md §8](../../architecture/tui-client.md#8-extension-contract--every-feature-ships-a-tui-surface):
  (1) message renderer keyed by stream-type id, (2) palette commands + optional key bindings, (3) a pane
  or screen pushed onto the screen stack. Forward compatibility: an entry whose stream type has no
  registered renderer displays as `[unsupported: mrd.foo/1 — update your client]` rather than breaking
  the transcript.
- **Out:** any concrete renderer/command/pane beyond what T17 itself registers for `mrd.chat/1` (4.20
  registers the chat renderer against this registry, not the other way around — this task ships the
  registry and the placeholder path, not chat-specific content).

## Deliverables
1. `apps/tui/src/surface.rs`: registry types + registration API + placeholder-rendering fallback.
2. Test: an unregistered stream-type entry renders as the labeled placeholder without breaking the
   transcript or the app (an acceptance criterion of the feature spec).

## Risks / notes
- This is an architectural contract other features (T07, T09, T10, T13, T15, T16 per
  [tui-client.md §8](../../architecture/tui-client.md#8-extension-contract--every-feature-ships-a-tui-surface)'s
  table) will build against — get the registration API right the first time; a breaking change here
  later touches every feature that registered against it.

## Tests
`cargo nextest run -p meridian-tui --test surface_registry`

## Reviews
- **architect** — required; this is the extension contract Definition of Done gate 9 depends on.
- **test-engineer** — required; the placeholder-fallback path is exactly the kind of thing that needs an
  explicit adversarial-shaped test (a genuinely unknown stream type must never crash the transcript).

# 10.14 — Soak test: 1 GiB / 10 GiB transfers + throughput report

**Phase:** 10 — File Transfer Stream · **Feature:** T09 · **Depends on:** 10.10, 10.13 ·
**Status:** pending

## Goal
Run the feature spec's named soak test — 1 GiB and 10 GiB transfers on the netns rig under the 1%
loss / 80 ms RTT profile — and produce a throughput report. This is explicitly named as feeding
ADR-6's SCTP-over-DTLS-vs-QUIC question with real numbers: "Ship the numbers, don't hide them."

## Scope
- **In:** automated soak runs at both sizes under task 10.13's profile, byte-perfect delivery
  verification (BLAKE3 match), a throughput report (MB/s achieved, comparison against the ceiling
  `system-design.md` §5.1 flags as a risk for SCTP-over-DTLS).
- **Out:** any transport-layer change in response to the numbers — this task reports, it does not
  redesign. If the numbers reveal something ADR-6-relevant, record it as a carry-forward for a future
  `/spike`, not a scope-creep fix here.

## Deliverables
1. Soak test automation (likely a shell/Rust harness driving two CLI instances across the netns rig).
2. Throughput report (markdown or similar, checked in or linked from this task's Outcome) covering both
   the 1 GiB and 10 GiB runs.

## Risks / notes
This is a long-running test (10 GiB under 1% loss/80ms RTT will take real wall-clock time) — likely an
`--ignored`-by-default test per the task 3.12 CI precedent, run in a scheduled/manual job rather than
every CI push.

## Tests
The soak harness itself; `cargo nextest run --ignored` (or equivalent) for the automated portion.

## Reviews
**test-engineer** + **devops**.

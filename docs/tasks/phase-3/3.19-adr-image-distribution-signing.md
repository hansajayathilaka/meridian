# 3.19 — ADR: container image distribution + signing

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F16 remainder) · **Depends on:** — · **Status:** pending

## Goal
Ratify `ghcr.io` as the container distribution channel and make an explicit, recorded signing
decision — the last unratified supply-chain choice from Phase 2's window.

## Scope
- **In:** a short ADR (proposed **0019**, same weight class as ADR 0018) recording (a) `ghcr.io` +
  the built-in `GITHUB_TOKEN` (no long-lived credential) as the channel, (b) the tag policy
  (`:latest` + short-sha), (c) the signing/provenance decision — adopt cosign/attestations **or**
  consciously defer with a recorded residual and a named trigger. Cross-link from
  `docs/operations/docker-image.md`.
- **Out:** **the Docker Hub → ghcr.io migration itself, which already landed after the report was
  written** — do not redo it; the ADR records an already-made choice. Also out: Dokploy-as-target,
  coturn fixes, `wss://` (the report judges none of them ADR-worthy). If the ADR chooses to sign, the
  *implementation* is a follow-up task, not this one.

## Deliverables
1. `docs/adr/0019-container-image-distribution.md`.
2. `docs/adr/README.md` index row.
3. `docs/operations/docker-image.md` cross-link.

## Risks / notes
- The migration already removed the long-lived-credential concern; the ADR must describe the world as
  it now is, not re-argue Docker Hub.
- Unsigned images remain the open residual — if deferring, name the trigger that reopens it
  (e.g. "before the first tagged release" / "before any third party is told to pull this image").

# 6.1 — SPK rotation policy: age tracking + rotation-due predicate

**Phase:** 6 — Envelope v2 · **Feature:** ADR 0016 (C1, part 1/3) · **Depends on:** — · **Status:** done

## Goal
Give `PrekeyVault` a notion of "how stale is my current signed-prekey generation" so a caller can
decide to rotate. ADR 0016 C1 requires enforced, monitored SPK rotation to become real, with tests,
*before* envelope v2 ships — it is v2's compensating control for R1 (key-compromise impersonation on
the opening message), not an aspiration. Today no code anywhere tracks publish time or answers
"is this generation overdue" — this task builds that primitive; 6.2 acts on it.

## Scope
- **In:** `apps/core/src/chat.rs::PrekeyVault` — a publish-timestamp field, a rotation-due predicate,
  and the rotation-interval constant.
- **Out:** anything that *acts* on the predicate (republishing, warning, monitoring — task 6.2);
  server-side metrics (flagged for 6.2, not built here); the crypto/AAD rewrite (6.3).

## Deliverables
1. `PrekeyVault`: new `spk_published_at: Option<u64>` field (parallel to `spk_public`/`spk_secret`),
   set by whatever call already publishes a fresh bundle (`set_bundle` or its equivalent — confirm the
   exact call site by reading the current method, don't guess the name).
2. `SPK_ROTATION_INTERVAL_SECS: u64` constant next to the existing `PREV_GENERATION_GRACE_SECS`.
   `TODO: confirm` the exact value with **architect** — ADR 0016 only says "~weekly, monitored" as a
   target, no numeric requirement. Proposed default: `7 * 24 * 3600`.
3. `PrekeyVault::rotation_due(&self, now_unix: u64) -> bool` and
   `PrekeyVault::generation_age_secs(&self, now_unix: u64) -> Option<u64>`.
4. `#[serde(default)]` on the new field, mirroring `PrekeyVault::previous`'s own precedent, so a
   `ChatState` sealed by pre-6.1 code still deserializes without panicking.

## Risks / notes
- **Unknown-age semantics is a real decision, not a formality.** A state sealed before this task
  deserializes with `spk_published_at: None`. `TODO: confirm` with **architect**: does `rotation_due`
  treat "unknown age" as due-now (fail-safe: rotate promptly, one extra publish) or not-due (avoid a
  surprise mass-republish across every existing session on upgrade)? Record the decision and reasoning
  in this task's Outcome section — this is exactly the kind of security-relevant default ADR 0016 asks
  not to leave implicit (it's a component of R1's compensating control).
- Pure metadata addition — no crypto/wire-format change, no vector churn expected. If vectors move,
  that's a signal this task went wider than intended.
- This task is independent of 6.3 (the AAD/wire rewrite) and can be developed in parallel with it.

## Tests
```
cargo nextest run -p meridian-core --lib
```
New unit tests: `rotation_due` is `false` immediately after publish, `true` once
`now_unix - spk_published_at >= SPK_ROTATION_INTERVAL_SECS`; the chosen unknown-age default is
asserted explicitly (not left to fall out of whatever the code happens to do); a `ChatState` sealed
without the new field deserializes without panicking.

## Outcome

Implemented exactly as scoped, entirely within `apps/core/src/chat.rs::PrekeyVault` — no other file
(and no envelope/AAD/wire code) touched.

- **`spk_published_at: Option<u64>`** added to `PrekeyVault`, parallel to `previous`, with
  `#[serde(default)]`. `set_bundle` now unconditionally sets it to `now_unix` on every call (first
  publish and every republish alike), so a fresh generation's age clock always starts at zero.
- **`SPK_ROTATION_INTERVAL_SECS: u64 = 7 * 24 * 3600`** (one week), placed next to
  `PREV_GENERATION_GRACE_SECS`. Chosen because it matches ADR 0016's own stated "~weekly" target
  directly, keeps the compromise-window bound human-legible, and stays well clear of
  `PREV_GENERATION_GRACE_SECS`'s 60-second reconnect-race window so normal republish cadence never
  fights that grace period. No numeric requirement exists in the ADR beyond "~weekly, monitored", so
  this is a policy default, not a derived constant — documented in a comment at the constant itself.
- **`PrekeyVault::generation_age_secs(&self, now_unix: u64) -> Option<u64>`** and
  **`PrekeyVault::rotation_due(&self, now_unix: u64) -> bool`** added. `rotation_due` is a pure
  predicate — no republishing, warning, or metrics (that remains 6.2's job).

**Unknown-age semantics decision (the real decision this task asked to make and document):**
`rotation_due` treats `spk_published_at: None` — i.e. `generation_age_secs` returning `None`,
covering both "no bundle ever published" and "vault deserialized from a state sealed before this
task" — as **due-now** (fail-safe/fail-secure), not as not-due. Reasoning: the alternative (treating
unknown age as not-due) risks silently running an SPK generation of unknown — possibly very old —
age past ADR 0016's rotation window with nothing to ever flag it, which is exactly the "aspirational,
not real" rotation posture ADR 0016 C1 exists to close out. The cost of the fail-safe choice is
bounded and one-time per session: on upgrade from a pre-6.1 build, the very first check of the
predicate reports "due" once; once (task 6.2) that is acted on with a republish, `set_bundle` sets
`spk_published_at` and every subsequent check has a real, known age to reason from — not a repeating
or escalating cost. This is implemented at the `rotation_due` call site with a comment explaining the
choice, and asserted directly by the `rotation_due_treats_unknown_age_as_due_now` test (not left to
fall out incidentally of another test).

**Tests added** (in `apps/core/src/chat.rs`'s existing crate-private `mod tests`, alongside the other
`PrekeyVault`/`ChatState` unit tests that already exercise `set_bundle`):
- `rotation_due_is_false_immediately_after_publish` — age 0 is never due.
- `rotation_due_becomes_true_once_the_interval_elapses` — false the instant before
  `SPK_ROTATION_INTERVAL_SECS`, true at and past it.
- `rotation_due_treats_unknown_age_as_due_now` — the unknown-age decision, asserted directly.
- `a_vault_serialized_without_spk_published_at_still_deserializes` — strips the
  `spk_published_at` CBOR map entry out of a current encoding (both a bare `PrekeyVault` and a whole
  `ChatState` with the vault nested under `vault`, mirroring `seal_at_rest`/`open_at_rest`'s actual
  shape) using the same `ciborium::value::Value`-editing technique
  `apps/core/tests/desync_recovery.rs::state_bytes_excluding_desync_counts` already uses for
  simulating a pre-field legacy shape, then confirms deserialization succeeds with the field
  defaulting to `None` rather than panicking.

  = 7 * 24 * 3600` matches ADR 0016's "~weekly" target and stays clear of `PREV_GENERATION_GRACE_SECS`;
  fail-safe unknown-age-is-due-now semantics is the right call for R1's compensating control and is

- **code-reviewer** — PASS. Threshold logic, `saturating_sub` arithmetic, and the `#[serde(default)]`
  migration path (tested against both a bare `PrekeyVault` and a nested `ChatState`) are all correct; full
  44-test suite green; clippy clean. Two non-blocking nits raised and resolved/carried forward:
  1. `set_bundle`'s own doc comment didn't mention it now also stamps `spk_published_at` — fixed in this
     diff (doc comment updated).
  2. Backward clock skew (`now_unix < spk_published_at`) saturates `generation_age_secs` to `0`, so
     `rotation_due` reports "not due" rather than surfacing the anomaly. Bounded/non-blocking (mirrors
     existing `saturating_sub` convention elsewhere in this file; real elapsed time eventually dominates)
     — carried forward as a should-fix note for 6.2, not fixed here since 6.2 is where the predicate gets
     acted on and is the more natural place to decide whether to add anomaly surfacing.

# 9.7 — Federated-path `ttl_days == 0` test

**Phase:** 9 — Review of Phase 8 · **Feature:** review fix (F7) · **Depends on:** — · **Status:** done

**User surface:** none — test-only coverage addition; no production code change (Definition of Done
gate 9).

## Goal
Cover the federated route path's `ttl_days == 0` short-circuit (`apps/rendezvous/src/federation/inbound.rs:294-298`,
`handle_fed_route`), which mirrors the local path's "mailbox disabled" short-circuit but — unlike the
local path (`route_to_offline_peer_errors_when_mailbox_disabled`) — has no test proving it actually
fires. "TTL=0 disables the store entirely" is a named acceptance criterion in the feature spec; without
this test the federation boundary could silently regress (e.g. start enqueueing anyway) with nothing to
catch it.

## Scope
- **In:** a new test in `apps/rendezvous/tests/federation_mailbox.rs` or `federation_route.rs`
  (whichever already hosts the federated mailbox test suite), constructing `FederationPairOpts`/
  `FedRouteDeps` with `ttl_days: 0` and asserting the federated route to an offline recipient errors
  (mailbox disabled) rather than silently enqueueing, mirroring the existing local-path test's
  structure and assertions.
- **Out:** No production code change — `handle_fed_route`'s `ttl_days == 0` short-circuit already exists
  and (per the review) appears correct; this task only proves it.

## Deliverables
1. A federated-path test for `ttl_days == 0`, structurally mirroring the local path's existing
   `route_to_offline_peer_errors_when_mailbox_disabled`.

## Outcome
Added `federated_enqueue_against_bs_real_live_state_ttl_zero_drops_without_enqueueing` against a real,
live two-org federated pair with an offline recipient. One correction to this task file's own shorthand:
the federated path's `ttl_days == 0` short-circuit is documented (its own doc comment, plus phase-8's
architect consult and task 8.6's own status) to be fire-and-forget-on-success — it returns `Ok(())` and
silently drops, with no wire-visible error signal, unlike the local path which has a live connection to
write an error reply to. The test asserts that actual, reviewed contract (`Ok(())` + empty mailbox)
rather than an error return. test-engineer PASS, independently re-confirmed both the divergence (traced
to the phase-8 architect consult) and non-vacuity (empirically neutered the short-circuit, watched the
test fail with a real enqueued row, restored, confirmed green again). No production code change.

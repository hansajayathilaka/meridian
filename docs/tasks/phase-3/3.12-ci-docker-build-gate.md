# 3.12 — Build the rendezvous image pre-merge (and run what we think we run)

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F12 + the unscheduled `--ignored` runner) · **Depends on:** — · **Status:** pending

## Goal
The Dockerfile + entrypoint (privilege drop, chown, coturn logic) must be validated **before** merge,
and a scheduled runner must exist for the `#[ignore]`d capacity test.

## Scope
- **In:** a build-only `docker build -f apps/rendezvous/Dockerfile .` step in `ci.yml`; optionally a
  `docker run` smoke asserting bind + privilege drop; a scheduled job running
  `cargo test -p meridian-rendezvous -- --ignored`; verify branch protection actually gates the
  publish (closes `docs/operations/docker-image.md`'s branch-protection `TODO: confirm`).
- **Out:** publishing/signing (3.19's ADR decides that); a `demo/two-orgs` CI smoke (deferred — the
  report judges docker-only/human-run acceptable).

## Deliverables
1. `.github/workflows/ci.yml` — a new docker build job.
2. A scheduled workflow (or `schedule:` trigger) for the `--ignored` runner.
3. `docs/operations/docker-image.md` — the branch-protection TODO resolved with the **observed**
   setting, not an assumed one.

## Risks / notes
- This repo's recurring failure mode is **gates that cannot fail** (1.12, 1.28, 1.32, 2.16). The
  acceptance criterion is therefore two-part: the job passes on its own PR, **and** a
  deliberately-broken-Dockerfile trial run is recorded in the Outcome proving it goes red.
- `docker build` in CI needs no registry credentials (build-only, no push) — keep it that way so the
  gate cannot leak the publish credential.

## Tests
```
docker build -f apps/rendezvous/Dockerfile .
```
then the new CI job itself, observed on this task's own PR.

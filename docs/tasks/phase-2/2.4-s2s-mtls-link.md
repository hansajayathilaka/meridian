# 2.4 — s2s mTLS link: listener + dialer (WebPKI and private-CA modes)

**Phase:** 2 — Cross-Org Federation · **Feature:** T06 — Cross-Org Federation · **Depends on:** 2.2 · **Status:** done

## Goal
Server A can open a mutually authenticated s2s connection to server B in both WebPKI and private-CA
(air-gap) modes, and each side learns the peer's authenticated **origin domain** — the value every
policy and rate-limit decision downstream hangs on.

## Scope
- **In:** the `[federation]` config block; rustls server + client config; CA-bundle loading;
  SAN/CN → origin-domain extraction **pinned to the domain that was intended to be dialled**;
  the `FedHello` exchange; link lifecycle and the allowlisted `meridian_federation_link_up` metric.
- **Out:** discovery (2.5), policy and limits (2.6), any `fed_*` handler (2.7, 2.8).

## Deliverables
1. `apps/rendezvous/src/federation/mod.rs`, `apps/rendezvous/src/federation/link.rs`.
2. `apps/rendezvous/src/config.rs`: `Federation { enabled, bind, cert_path, key_path,
   ca_bundle_path, .. }` — every default **fail-closed** (`enabled = false`).
3. `apps/rendezvous/src/metrics.rs`: `meridian_federation_link_up` (already on
   `tools/metrics-allowlist.txt`).
4. `apps/rendezvous/tests/federation_mtls.rs`: happy path in both modes; **untrusted CA rejected**;
   **valid cert for the wrong domain rejected**; missing client cert rejected.

## Risks / notes
- **Highest `lint-server-no-core.sh` risk task** — new deps (`tokio-rustls`, `rustls-pemfile`,
  `rcgen` as a dev-dep). All non-`meridian-*`, so structurally safe, but this is the PR where the
  dependency graph changes most. Run the lint **and** its `--selftest` here.
- Security-critical: without SAN-to-intended-domain pinning, **any** cert issued by the private CA
  impersonates **any** org. That is the entire air-gap trust model. 2.1 fixes which name must match.
- `TODO: confirm`: the default federation port.
- **Resolved by [ADR 0017](../../adr/0017-federation-trust-boundary.md) C7**: TLS terminates
  **in-process**, never at a proxy/VIP as [ADR 0008](../../adr/0008-infra-topology.md) does for c2s.
  c2s is proxy-terminated today ([rendezvous-protocol-v1 §8](../../api/rendezvous-protocol-v1.md)) and
  that is safe there because c2s identity comes from the post-TLS `Auth` signature, not the TLS layer;
  s2s has no such second factor, so delegating termination would let an unauthenticated hop assert any
  peer identity.
- `TODO: confirm`: whether `meridian_federation_link_up` may carry a `peer_domain` label — a label is
  a metric, and a per-partner counter is a cross-org contact-graph materialization
  ([anonymity-and-retention.md](../../security/anonymity-and-retention.md) must-never #2).
  security-reviewer call.
- Shares the `config::Federation` struct with 2.5 — trivially mergeable, but sequence if one developer.

## Outcome
`apps/rendezvous/src/federation/{mod,link}.rs` implement the s2s mTLS link (WebPKI + private-CA,
domain-pinned, in-process termination per ADR 0017 C7). `config::Federation` added with fail-closed
defaults (`enabled = false`); `meridian_federation_link_up` registered as an aggregate gauge with no
`peer_domain` label (security-reviewer confirmed: a per-partner label would materialize the cross-org
contact graph, forbidden by anonymity-and-retention.md must-never #2). Default federation port: 8444
(TODO: confirm — not IANA-registered, chosen adjacent to c2s's 8443).

**Reviews:** architect — consistent, no revision. security-reviewer — APPROVE-WITH-CHANGES; required
fail-closed cert-loading regression tests added in a follow-up commit. code-reviewer —
approve-with-nits; the `missing_client_cert_is_rejected` test-isolation nit addressed via doc comment
in the same follow-up commit. Non-blocking forward-note for 2.6: the accept side (`FederationListener`)
does not yet pin the inbound peer's identity against a specific expected partner — that's `federation_map.toml`
policy territory (2.5/2.6), not a 2.4 gap.

Tests: `cargo nextest run -p meridian-rendezvous --test federation_mtls` (9/9 pass), clippy/fmt clean,
`lint-server-no-core.sh` (+ `--selftest`) and `lint-metrics-allowlist.sh` pass.

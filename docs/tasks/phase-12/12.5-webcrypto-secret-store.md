# 12.5 — `WebCryptoSecretStore` (`apps/store`, wasm32-gated)

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** 12.1 · **Status:** pending

**User surface:** none directly — foundational store primitive consumed by the browser adapter (12.13)
and the account-creation flow inside 12.7. No TUI surface applies.

## Goal
Implement [ADR 0026](../../adr/0026-browser-client-local-store.md)'s browser `SecretStore`: a new
`WebCryptoSecretStore`, mirroring `apps/store/src/os.rs`'s/`file.rs`'s existing impl shape, backed by
non-extractable WebCrypto `CryptoKey`s. This is the first `SecretStore` impl in the tree that can
honestly report `nonextractable() == true`.

## Scope
- **In:** `apps/store/src/webcrypto.rs`, `wasm32`-gated, implementing `SecretStore` exactly per
  `core-api-contracts.md`'s frozen signature: `store()` imports the given raw seed via
  `SubtleCrypto.importKey('raw', ..., extractable: false, ...)` and discards the JS reference to the raw
  bytes immediately afterward — no code path may export or log the raw seed after import; `use_key`
  computes signing/DH results via `crypto.subtle`'s non-extractable-key operations, returning only the
  computed output; `derive_key` computes a domain-separated HKDF-Expand output via `crypto.subtle`,
  returning **extractable** raw bytes (this is deliberate per ADR 0026 — the derived per-purpose sealing
  key is allowed to exist as raw WASM memory; only the *base account key* stays non-extractable
  throughout); `nonextractable()` returns `true`.
- **Out:** IndexedDB record sealing/schema (that's a separate module, task 12.12, per the ADR's
  crate-placement split — `meridian-crypto`'s `at_rest::seal`/`open` needs both `meridian-store` and
  `meridian-crypto`, which would cycle if placed inside `apps/store` itself); any browser `Transport`
  work (12.11); any UI.

## Deliverables
1. `apps/store/src/webcrypto.rs` — `WebCryptoSecretStore`.
2. `apps/store/Cargo.toml` — `wasm32`-gated `web-sys`/`js-sys`/`wasm-bindgen` dependencies.
3. Tests round-tripping `store`/`use_key`/`derive_key`.
4. A negative test asserting the raw seed never appears as an extractable `CryptoKey` — e.g. attempting
   `crypto.subtle.exportKey` against the stored key and asserting it throws/rejects.

## Risks / notes
This is genuinely new, security-load-bearing code (ADR 0026 binding condition 1) — keep the diff
narrowly scoped to exactly what the ADR specifies; do not invent additional convenience methods on the
trait or bypass paths that could return raw key material.

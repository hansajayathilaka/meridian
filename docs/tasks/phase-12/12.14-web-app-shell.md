# 12.14 — `apps/web` app shell

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** 12.13, 12.7, 12.8, 12.9
· **Status:** done

**User surface:** the browser client itself — this task is what turns `apps/web`'s current scaffold
into a real, servable app. No TUI surface applies (new client platform, not a new protocol feature).

## Goal
Wire SvelteKit routes/build config around the browser adapter (12.13) and the shared screens
(12.7–12.9) into a servable static bundle (`meridian-web`, the feature spec's deliverable 1), replacing
`apps/web`'s current `package.json` TODO scripts (`dev`/`build`/`lint`) with real ones. Adds the CSP
baseline `<meta>`/header configuration — the technical half of deliverable 3 (the prose half is task
12.19).

## Scope
- **In:** SvelteKit route structure wiring 12.7–12.9's screens to 12.13's real adapter; `vite.config.ts`
  build config (this is also where the <4 MB gzipped WASM bundle-size property starts being measured
  for real, not just 12.10's smoke-build report); a CSP baseline (script-src/connect-src restricted to
  what the WASM core + WebRTC signaling actually need, no inline scripts).
- **Out:** the deployment-guide prose itself (12.19); the interop-matrix CI job (12.17) — this task
  produces the buildable artifact that job later drives.

## Deliverables
1. `apps/web/src/routes/**` — real routes replacing the scaffold's placeholder `main.ts`.
2. `apps/web/vite.config.ts`.
3. CSP baseline config (meta tag or server-header equivalent, documented for whichever the
   `demo/two-orgs`-style deployment actually uses).
4. `apps/web/package.json` — real `dev`/`build`/`lint` scripts.
5. `pnpm --filter web build` produces a buildable static bundle.

## Risks / notes
`apps/web/CLAUDE.md`'s existing rules bind this task directly: no bespoke crypto/wire types in JS/TS,
and "leak nothing the anonymity model forbids — no plaintext, identifiers, or contact metadata to logs,
analytics, storage, or third-party requests." The CSP baseline is one concrete enforcement of the
second rule (no unexpected third-party `connect-src`).

**Known, confirmed dependency gap, found by task 12.13's own review — read before wiring routes for
the messaging screens.** `apps/web/src/lib/adapter.ts` (task 12.13) is real for account creation
(`generateAccount`/`currentAccount`/`closeAccount`, genuine `crypto.subtle`) and proves the real WebRTC
transport substrate end to end, but ~30 of `MeridianClientAdapter`'s methods — everything 12.7's
(chat/contacts/message-requests), 12.8's (verification), and 12.9's (file transfer) screens actually
call for live messaging — fail closed with `MeridianAdapterError("unavailable", …)`, because
`meridian-wasm` (task 12.10) exports identity operations only; no `ChatState`/`TrustStore`/session
wasm-bindgen surface exists yet. Account persistence across a page reload is also structurally blocked
today (`WebCryptoSecretStore`'s non-extractable `CryptoKey` has no accessor, and `IndexedDbStore`'s
sealed records can't carry one). Full finding: [12.13's Outcome](./12.13-browser-wasm-adapter.md#outcome).

This task can therefore build the real onboarding/account-creation route and wire the real CSP/build
config end to end, but the messaging screens (12.7–12.9) will only be exercisable against a
**fail-closed adapter** until a future task adds the missing `meridian-wasm` session/chat bindings — do
not silently assume a working chat substrate while wiring routes for those screens, and do not weaken
or work around the fail-closed behavior to make routes "look" functional. If this task's own build/test
gate needs the messaging routes to demonstrably work end to end (not just render against a fake
adapter, which 12.7–12.9's own tests already cover), that need routes back as a blocking dependency on
the not-yet-scoped session/chat wasm-bindgen follow-up — flag it explicitly rather than inventing a
workaround, mirroring exactly how 12.13 itself handled finding this gap.

## Tests
`pnpm --filter web build` + `pnpm --filter web test`.

## Reviews
**code-reviewer**; **security-reviewer** (CSP is a real security control; also confirms
`apps/web/CLAUDE.md`'s leak-nothing rule holds in the built bundle, not just the source).

## Outcome
Real SvelteKit routes replace the scaffold's placeholder `main.ts`: an onboarding route (the one flow
that fully works today, real `generateAccount` via 12.13's adapter) plus protected routes for
contacts/requests/chat/verify/files, all passing the real, unmodified `WasmMeridianClientAdapter`
straight into the 12.7-12.9 screens with no special-casing that would hide 12.13's known fail-closed gap.
CSP baseline via `svelte.config.js`'s `kit.csp` (`mode: "hash"`, no `'unsafe-inline'`/`'unsafe-eval'` in
`script-src`, `connect-src` restricted to `'self'` + local WS + bare `stun:`/`turn:`/`turns:` scheme-
sources) — confirmed real in the built `dist/index.html`, not just configured. `frame-ancestors` is
absent from the built meta tag by CSP spec's own mandated drop for meta-delivery (not a shortcut);
already anticipated by task 12.19's own Goal, which names documenting the CSP baseline as in-scope.

While proving the routes correctly surface (not hide or crash on) the adapter's fail-closed errors, found
and fixed a real, pre-existing bug in `shared-ui/src/screens/Contacts.svelte`/`Chat.svelte` (task 12.7's
owned files): both stores already computed `$store.error` on a failed adapter call, but neither screen
rendered it, so a failure looked identical to a genuinely empty list. Fixed with the same `role="alert"`
banner pattern `MessageRequests`/`Verification`/`FileTransfer` already established, plus two new
regression tests. This is an on-the-fly, out-of-this-task's-declared-Scope fix, flagged here rather than
landing silently — a real bug matching an established pattern, not new scope.

The combined review (code-reviewer + security-reviewer) returned **PASS** on both lenses, zero blocking
findings, after independently rebuilding and inspecting the actual built `dist/index.html`'s CSP meta tag
byte-for-byte (not trusting the config alone), grepping the built bundle for leaked identifiers/telemetry
(none found — the one flagged `http://` hit is the standard SVG XML namespace URI, not a network call),
and confirming the `Contacts.svelte`/`Chat.svelte` fix's two new tests genuinely exercise the fixed paths.
6/6 `meridian-web` tests, 0 `svelte-check` errors, 86/86 `shared-ui` tests (including the 2 new
regression tests) — all independently reproduced. Gzipped WASM bundle: ~166 KB (well under the 4 MB
budget task 12.20 enforces; this is still 12.10's identity-only build, expected to grow once session/chat
bindings land per 12.13's own carried-forward gap).

# 2.2 — `federation-protocol-v1.md` + s2s wire types + conformance vectors

**Phase:** 2 — Cross-Org Federation · **Feature:** T06 — Cross-Org Federation · **Depends on:** 2.1 · **Status:** pending

## Goal
Publish the new versioned server-to-server wire contract and its `meridian-proto` types, so every
later task codes against a fixed, vector-checked contract instead of inventing one per PR.

## Scope
- **In:** the contract doc; s2s frame + body types in `meridian-proto`; conformance vectors and their
  generator; the `tools/lint-no-serde-on-blob.sh` allowlist extension as an explicit, reviewed line
  item; index/nav updates.
- **Out:** all behaviour — no listener, dialer, discovery, policy or handler (2.4–2.9). No c2s changes
  (2.3).

## Deliverables
1. `docs/api/federation-protocol-v1.md` — framing, ops, error codes, versioning, and the "what two
   federating orgs may learn" ceiling restated from
   [anonymity-and-retention.md](../../security/anonymity-and-retention.md).
2. `apps/proto/src/fed.rs`: `FedOp`, `FedFrame`, `FedHello`, `FedFetchBundle`, `FedBundle`,
   `FedRoute`, `FedReachability`, `FedReachable`, `FedErr`, `fed_error_codes`.
3. `test-vectors/federation-v1.json` + `tools/xtask/src/vectors/federation.rs`, registered in
   `tools/xtask/src/vectors/mod.rs::generate`.
4. `apps/proto/tests/fed_roundtrip.rs`.
5. Updates to [docs/api/README.md](../../api/README.md) and
   [wire-protocol.md §4](../../api/wire-protocol.md) pointing at the new doc as the authority.

## Risks / notes
- The origin-attestation shape is **decided by 2.1** — implement that decision, do not re-open it.
- `TODO: confirm`: s2s framing/transport. The docs say "mTLS" and name ops but never the framing —
  CBOR `{op,id,body}` over a length-delimited mTLS stream, a second axum WSS listener, or HTTP/2.
- `TODO: confirm`: `Frame.id` semantics for s2s. The c2s space is client-chosen with `id = 0` reserved
  for server-initiated frames; an s2s reuse needs its own id space.
- `TODO: confirm`: whether reusing the c2s `Op` enum lets a *client* socket nominally speak federation
  ops. The `serve` loop rejects unknown ops today, but a merged enum stops distinguishing the planes.
- [wire-protocol.md §4](../../api/wire-protocol.md)'s optional `contact_token{issuer_sig, audience,
  exp}` is documented, but contact tokens are explicitly **out of scope** (→ T08/T14). Record the
  field as reserved-and-unimplemented; do not implement it.
- Types must live in `meridian-proto` — it is the only placement that keeps
  `tools/lint-server-no-core.sh` green (the lint is a crate-**name** allowlist, so even a new
  `meridian-federation` crate would fail it without touching core).
- Extending `tools/lint-no-serde-on-blob.sh`'s type allowlist is intended friction: it must be a
  reviewed line item here, never a silent edit in a later task, and must never admit a content-shaped
  type.

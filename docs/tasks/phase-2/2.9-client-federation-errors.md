# 2.9 — Client-side federation error taxonomy: clean `closed` error + the stale-hint case

**Phase:** 2 — Cross-Org Federation · **Feature:** T06 — Cross-Org Federation · **Depends on:** 2.7, 2.8, 1.33 · **Status:** pending

## Goal
Every federation failure surfaces at the client as a distinct, diagnosable, **non-security** message.
Specifically: a `closed`-policy org produces a clean error rather than a hang, and the stale-hint case
(Bob re-registered at org-c) reports "unreachable at hint" and **never** a security warning.

## Scope
- **In:** `SignalError` / `SessionError` variants for `fed_denied`, `fed_unreachable`,
  `not_found_at_hint`; CLI copy; the hard distinction between a *reachability* failure and a
  *verification* failure; no hangs on any path.
- **Out:** retry/backoff; multi-hint IDs (Phase 3 by spec).

## Deliverables
1. `apps/signaling/src/error.rs` and `apps/core/src/session.rs`: new variants, kept **distinct** from
   `BundleVerification`.
2. `apps/cli/src/chat.rs`, `session_connect.rs`, `main.rs`: the user-facing copy.
3. `apps/cli/tests/federation_errors.rs`: `closed` org → clean non-zero exit with a named cause and
   **no hang**; stale hint → "unreachable at hint"; an assertion that **neither** path emits
   verification or security-warning copy.

## Risks / notes
- [ADR 0001](../../adr/0001-identity-scheme.md)'s consequence is the whole point of this task: a stale
  hint degrades **reachability, never security**. Conflating the two trains users to dismiss real
  key-substitution warnings — and [verification-ux.md](../../security/verification-ux.md) makes
  security copy canonical and un-softenable.
- **Depends on 1.33.** Without the bounded `recv_sdp` wait, "clean client-side error" is a hang. 1.33
  supplies the bounded wait plus a distinct error variant that this task extends to the federated
  cases.
- Inherits 2.6's unresolved `TODO: confirm` on how much rejection reason may be relayed. If the answer
  is "collapse `closed`/`allowlist`/`not_found` into one code to avoid leaking Org B's policy and
  target existence", this task must still produce a *diagnosable* message — name the ambiguity in the
  copy rather than inventing a precision the wire does not carry.

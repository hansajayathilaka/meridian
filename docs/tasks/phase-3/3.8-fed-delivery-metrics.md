# 3.8 — Count federated deliveries in `envelopes_routed_total`

**Phase:** 3 — Review of Phase 2 · **Feature:** review fix (F8 + N4) · **Depends on:** 3.4 · **Status:** pending

## Goal
Ops dashboards stop under-counting exactly the traffic Phase 2 added.

## Scope
- **In:** route inbound federated delivery through `deliver_one` (or call `metrics.envelope_routed()`
  there); replace `handle_fed_route`'s full CBOR re-encode-to-measure with `req.envelope.len()` (N4).
- **Out:** any new metric name or label. The allowlist is binding and there must be **no per-partner
  label** — that would materialize the cross-org contact graph (anonymity-and-retention must-never #2).

## Deliverables
1. `apps/rendezvous/src/federation/inbound.rs` — L181 (re-encode) and L211 (delivery path).
2. A test in `apps/rendezvous/tests/federation_route.rs` asserting the counter increments once per
   federated delivery **and** that no new label appears.

## Risks / notes
- The tempting fix (a `peer_domain` label so operators can see *which* partner) is exactly the
  forbidden one — 2.4 already settled this for `meridian_federation_link_up`.

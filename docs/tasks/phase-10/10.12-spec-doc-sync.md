# 10.12 — `mrd.file/1` spec section + wire/design doc corrections

**Phase:** 10 — File Transfer Stream · **Feature:** T09 · **Depends on:** 10.4, 10.6, 10.9 ·
**Status:** pending

## Goal
Write the `docs/api/stream-types-v1.md` section for `mrd.file/1`, precise enough that a third-party
engineer could implement it from the doc alone (the feature's own acceptance criterion: an engineer not
on this task builds a toy `mrd.echo/1` stream from the doc in under a day), and correct the two
implementation-precision gaps this phase's planning surfaced in existing docs.

## Scope
- **In:**
  1. New `mrd.file/1` section in `docs/api/stream-types-v1.md`: manifest schema, the exact merkle
     construction (from task 10.3's Outcome), the exact per-chunk AEAD nonce encoding (from task 10.5's
     Outcome), the resume-in-stream design (from task 10.9), backpressure watermark behavior (task
     10.7).
  2. Correct `docs/api/wire-protocol.md` §5: the `Resume = {sid, bitmap: bstr}` line documents a ctrl
     frame that was never implemented and, per task 10.9's settled resolution, never will be (resume
     rides in-stream) — annotate or remove this line so the doc matches what's actually built.
  3. Small `/doc-sync` correction to `docs/architecture/system-design.md` line ~202 ("the initiator
     opens a new SCTP data channel") to reflect task 10.4's actual symmetric-explicit-open design.
  4. Note in `docs/architecture/system-design.md` §7.2 (or `stream-types-v1.md`) recording reshare/dedup
     of identical ciphertext as an explicit follow-up, per the feature spec's own out-of-scope note.
- **Out:** any code change — this is a doc-only task, run after the shapes it documents have actually
  landed (hence its dependency on 10.4/10.6/10.9).

## Deliverables

# 12.10 — `meridian-wasm` crate scaffold + smoke build + bundle-size report

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** 12.4 · **Status:** in progress

**User surface:** none directly — build-pipeline foundation for the browser `Transport` shim (12.11) and
IndexedDB store (12.12). No TUI surface applies.

## Goal
Scaffold `apps/wasm`, the wasm-bindgen cdylib crate `stack.md`'s documented target layout calls for,
wrapping `meridian-core`'s identity/store/crypto/session facade — using `LoopbackTransport`/
`MemorySecretStore` stand-ins, not the real browser impls — to prove the bindgen build pipeline end to
end before the real, harder pieces (browser `Transport`, `WebCryptoSecretStore`+IndexedDB) are wired in.
This directly follows the feature spec's own risk note: "schedule the WASM smoke build as day-1 of this
task regardless [of the ratchet library's wasm32 story]."

## Scope
- **In:** `apps/wasm` crate scaffold; `wasm-bindgen`/`tsify` wiring into `just codegen`, emitting
  `bindings/typescript`; a `wasm-pack build --release` CI step reporting gzipped bundle size (informational
  only at this stage — the hard <4 MB gate is task 12.20's); a smoke test round-tripping
  `generate_account`/`sign`/`safety_number` through the compiled `.wasm` in a headless runner.
- **Out:** the real `BrowserTransport` (12.11) and `WebCryptoSecretStore`/IndexedDB store (12.12) wiring
  — this task's stand-ins are deliberately not the production implementations, exactly so this task can
  land independently and prove the pipeline before those harder pieces exist.

## Deliverables
1. `apps/wasm/Cargo.toml`, `apps/wasm/src/lib.rs`.
2. `wasm-pack build -p meridian-wasm --release` CI step + size report.
3. Smoke test: `generate_account` → `sign` → `verify` and `safety_number` round-trip through the
   compiled artifact.

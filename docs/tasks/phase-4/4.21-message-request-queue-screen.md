## Status
Done. `apps/tui/src/screens/requests.rs` is the Requests screen: sender key, safety number, short
intro, accept/reject, reached via `^R` (global) or `r` in the Contacts list — neither hook existed yet
from task 4.19, so this task added both. Wraps already-reviewed 4.7 primitives directly:
`ChatState::pending_requests`/`accept_request`/`reject_request`, both pure in-memory ops with no wire
signal by construction. Accept/reject require a `y`/`n` confirm step (mirrors `contact_detail.rs`'s
block/delete confirms — accept ties into TOFU-pinning, reject discards session key material, both
consequential enough to not be single-keypress). TOFU-pin is deferred to after acceptance, matching
task 4.7's own ordering fix. `reject_leaves_no_trace_indistinguishable_from_a_sender_never_queued_at_all`
mirrors `apps/core/tests/message_request_gate.rs`'s core-level "leaves no trace" property at the UI
layer, field-for-field against a from-scratch control.

**Review (combined `reviewer`, as named — "no new trust decision made here"):** one blocking
correctness/security finding, fixed and re-confirmed clean:
- **Worker-event correlation gap** — `handle_worker` matched only on decision-kind and `Effect` variant
  shape, discarding the event's own `sender_ik` payload and acting on `state.mode`'s `sender_ik`
  instead, never checking the two matched. The reviewer reproduced it directly: with two queued
  requests, a stale completion event naming one sender could be misapplied while a different sender's
  decision was in flight, silently removing the wrong entry from the queue. The exact bug class task
  4.20's chat screen hit and fixed one task earlier (a worker-event handler not correlating a
  completion to the specific in-flight request) — recurring here despite the precedent, closed with the
  equivalent `request.sender_ik == sender_ik` guard on all four decision/outcome match arms, plus a
  regression test shaped exactly like the reviewer's own reproduction (matching effect variant and
  decision kind, differing only in the named sender).

`cargo test -p meridian-tui` (`screens_requests.rs` grew from 21 to 22 tests during review), `cargo
test -p meridian-cli --bins`, `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D
warnings`, and `bash tools/lint-tui-no-cli.sh` all clean.

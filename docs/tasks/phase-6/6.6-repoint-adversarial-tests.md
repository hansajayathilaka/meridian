# 6.6 — Test re-pointing: v1 detector → v2 AEAD, plus the new C3/R1 adversarial cells

**Phase:** 6 — Envelope v2 · **Feature:** ADR 0016 (test obligations) · **Depends on:** 6.3 · **Status:** pending

## Goal
Satisfy ADR 0016's explicit instruction: the v1-pinned test cells "fail at the v2 cutover regardless —
the detector they name ceases to exist... Re-point, never delete." Also close the two test obligations
the ADR marks "OPEN (v2)": the sign-flipped-`sender_pub` case (C3) and the documented KCI cell (R1).

## Scope
- **In:**
  - `apps/core/tests/preamble_mutation.rs` (the mitm-sim harness): every cell currently asserting
    `ChatError::BadSignature` re-pointed at whatever v2's real AEAD-failure detector is (determined by
    6.3's actual returned error type — do not guess in advance). Keep all four ADR-required properties:
    rejection by the new detector, OTK-pool depth unchanged (with a positive control), no session
    installed (`ChatState` byte-identical), and the genuine envelope subsequently succeeding.
  - `apps/core/tests/chat_manager.rs`: new cell — sign-flipped `sender_pub` (`A` vs. `−A`) is rejected,
    proving the AAD's raw-Ed25519-encoding requirement (C3) is actually enforced, not just the
    Montgomery-normalized form.
  - New KCI cell (R1): an "enumerated accepted residual" test proving — not silently — that an
    attacker holding only the responder's signed-prekey secret can forge a first-contact session. Per
    `testing/strategy.md`'s "0 silent successes outside the enumerated accepted residuals" rule, this
    is documented-by-test, not swept under a passing suite.
- **Out:** `apps/rendezvous`/other production-code comment fixes (moved to 6.7 — those are doc
  corrections, not test re-pointing); the `eid`/AAD/commit-on-decrypt implementation itself (6.3, 6.4).

## Deliverables
1. All files above.
2. Explicit regression run (no edits) of
   `apps/transport/tests/webrtc_backend.rs::tampered_remote_fingerprint_never_connects` — stays green,
   proving §4.6 fingerprint binding never depended on the removed signature.

## Risks / notes
- **Picking the wrong new detector silently weakens the test.** `TODO: confirm` against 6.3's actual
  implementation: does a forged/mutated preamble surface as a generic AEAD-open failure, a
  `ChatError::Desync` (header opens under neither `HKr` nor `NHKr`), or a new dedicated variant? Assert
  against the real behavior, not a guess.
- The ADR's own text on the KCI cell: "Extending the enumerated list requires a new ADR with
  security-reviewer sign-off; the list is not to be extended to make a harness go green." This task
  does **not** extend the list — R1 is already enumerated in ADR 0016 — but the sign-off discipline
  around how it's tested still applies; do not write the KCI test in a way that implies R1 is
  newly-discovered or negotiable.
- Every pre-existing v1 cell must show as **modified**, never **deleted**, in the diff.

  and passes against post-6.3 code (proves the re-pointing is real, not vacuous).
- **code-reviewer** — general correctness.

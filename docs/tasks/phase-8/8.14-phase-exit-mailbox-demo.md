# 8.14 — Phase exit: full demo script + doc sync

**Phase:** 8 — Offline Ciphertext Mailbox · **Feature:** T07 · **Depends on:** 8.1–8.13 · **Status:** pending

## Goal
Close Phase 8: run the feature spec's acceptance demo end-to-end (adjusted for the federated-case
framing this phase's architect consult settled), and sync every doc this phase touched.

## Scope
- **In:** run the demo script from `docs/architecture/features/07-offline-mailbox.md` live —
  same-server offline queue/deliver/purge/TTL=0 case exactly as written, plus the cross-org case
  with its framing corrected (sender sees optimistic `delivered:true`; `meridian-admin mailbox dump`
  at the recipient's org is the real proof, per 8.6's decision — this task's job is to *demonstrate*
  that correction live, not silently accept the spec's literal wording). Full workspace gate:
  `cargo build --workspace`, `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D
  warnings`, `cargo nextest run`. Doc sync: `docs/api/wire-protocol.md`,
  `docs/api/rendezvous-protocol-v1.md`, `docs/api/federation-protocol-v1.md` (§8/§6 "known
  simplifications" sections updated to remove the now-closed "offline delivery returns
  not_connected" / "no behavior yet" mailbox lines), `docs/architecture/data-model.md` if anything
  drifted from the original mailbox table note, `docs/architecture/roadmap.md` (T07 marked done,
  unblocking T14 per its dependency row).
- **Out:** T14 itself — this task only confirms T07 is genuinely done so T14 becomes pickable by a
  future `/pick-next-phase`, per phase-8/README.md's own deferral note.

## Deliverables
1. A recorded demo transcript (matching this project's convention, e.g. phase-6's
   `6.8-demo-transcript.md`) proving every acceptance criterion live: TTL-provable purge,
   redelivered-duplicate drop, out-of-order/skipped-key decrypt, quota→sender error, `TTL=0`
   pure-P2P, opacity dump, cross-org queue+deliver.
2. Doc-sync commits across the files listed in Scope.
3. `docs/tasks/README.md` and `docs/tasks/phase-8/README.md` updated to closed/done state.

## Risks / notes
If the live demo finds a defect (this project's own track record across phases 4/5/6/7 says this is
likely, not exceptional), follow the established pattern: don't force a PASS — record the defect,
open the next-numbered fix-task, and re-attempt the exit gate after it lands, exactly as phase 4's
seven attempts and phase 6/7's own closures did. Do not weaken any acceptance criterion to make this
task pass.

## Tests
Full workspace gate (see Scope) + the demo script, run live.

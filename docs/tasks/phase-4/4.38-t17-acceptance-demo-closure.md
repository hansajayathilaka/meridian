# 4.38 — T17 acceptance-demo closure

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client (gap closure, phase re-exit gate) · **Depends on:** 4.29–4.37 · **Status:** pending

## Goal
Mirror task 4.28's own role, but now actually succeeding: run the T17 demo script end to end and record a
genuinely passing result. Re-confirm T08's demo hasn't regressed. This is the task that finally lets
Phase 4 be marked done per the task-tracking skill's own §7 ("a build phase isn't done until its
acceptance demo runs") — 4.28 could only document the gap; this task is what closes it.

## Scope
- **In:** run [17-terminal-tui-client.md](../../architecture/features/17-terminal-tui-client.md)'s full
  demo script live (onboarding → verified chat → restart → key-change-blocks → `--export-json`), at
  least twice independently (mirroring 4.28's own "implementer once, reviewer once" discipline that
  caught nothing wrong last time and should be trusted again). Add a durable, scripted two-process
  regression test that exercises the *real* `run_worker` end to end (two temp `$MERIDIAN_HOME`s, a local
  `meridian-rendezvous`, driving `App::update` for both "peers") — this closes a residual coverage gap
  found during planning: `apps/tui/tests/at_rest_audit.rs` (task 4.27) deliberately bypasses `run_worker`
  entirely and hand-calls the real store functions itself, precisely because `run_worker` was a known
  stub at the time — so **none of the existing at-rest audit coverage actually exercises the real
  `run_worker` this gap-closure set writes**. Flip `docs/tasks/phase-4/README.md`'s T17 exit-criteria
  checkbox. Update `tui-client.md` §10 to describe the fixed state (or remove it if no longer needed).
  Clear `docs/tasks/README.md`'s carry-forward note for this gap.
- **Out:** any new feature code — verification + doc reconciliation only, same scope discipline as 4.28.
  If the live run reveals a genuine defect, the fix belongs in the relevant 4.29–4.37 task (reopen via a
  new fix-task number if all of them are already closed, per this project's "never reopen a closed task,
  always a new number" convention), not papered over here.

## Deliverables
1. Updated `tui-client.md`, `docs/tasks/phase-4/README.md`, `docs/tasks/README.md`.

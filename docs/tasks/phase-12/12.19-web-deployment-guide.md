# 12.19 — `web-deployment-guide.md`

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** 12.14 · **Status:** pending

**User surface:** none — operator-facing documentation. No TUI surface applies.

## Goal
Ship the feature spec's deliverable 3: a deployment guide covering the served-JS trust caveat verbatim
(`system-design.md` §6/§9.4: "a web app is only as trustworthy as its served JS... enterprises should
prefer the desktop build or serve the web client from their own audited origin"), the CSP baseline from
task 12.14, and [ADR 0026](../../adr/0026-browser-client-local-store.md)'s IndexedDB-eviction residual
(R1) documented honestly as a browser-platform constraint, not silently omitted.

## Scope
- **In:** `docs/operations/web-deployment-guide.md` (matching the sibling `docs/operations/*.md` files'
  style — see `docker-image.md`, `release-binaries.md`) covering: how to serve `meridian-web`'s static
  bundle from an org's own rendezvous host or any origin; the served-JS trust caveat, stated as directly
  as `system-design.md` does, not softened; the CSP baseline (task 12.14's actual config, documented
  accurately); ADR 0026 R1 (IndexedDB eviction policy).
- **Out:** any change to the actual CSP config or trust-caveat wording in `system-design.md` itself —
  this task documents what already exists, it doesn't invent new policy.

## Deliverables
1. `docs/operations/web-deployment-guide.md`.
2. `docs/INDEX.md` (or the relevant nav doc) cross-link, if that's this repo's existing convention for
   new operations docs — check the sibling docs' own inbound links before deciding.

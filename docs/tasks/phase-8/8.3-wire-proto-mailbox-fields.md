# 8.3 — Wire/proto: `RouteOk.queued`, `mailbox_full`, `Deliver.mailbox_id`, `MailboxAck`/`MailboxAckOk`

**Phase:** 8 — Offline Ciphertext Mailbox · **Feature:** T07 · **Depends on:** — · **Status:** done

## Goal
Give the mailbox the wire vocabulary it needs — types only, no server behavior — per this phase's
architect consult (recorded below), so 8.5–8.7 have a fixed contract to implement against.

## Scope
- **In**, all in `apps/proto/src/msg.rs` unless noted:
  - `RouteOk` gains one additive field: `queued: bool` (`#[serde(default, skip_serializing_if =
    "is_false")]` — omitted when `false`, so existing `delivered:true` traffic stays byte-identical).
  - `Deliver` gains one additive field: `mailbox_id: Option<u64>` (present only on a mailbox-drain
    push, absent/omitted for a live route).
  - New types `MailboxAck { ids: Vec<u64> }` and `MailboxAckOk {}`, plus their `Op` variants
    (`MailboxAck`, `MailboxAckOk`) — `ids` are the mailbox's own server-assigned row `id`s, **never**
    the opaque `eid` inside the blob (the server cannot read `eid`; see data-model.md's note and
    task 7.6).
  - New error code `error_codes::MAILBOX_FULL = "mailbox_full"` (msg.rs) and
    `fed_error_codes::MAILBOX_FULL` (`apps/proto/src/fed.rs`).
  - Bump the c2s wire version per `meridian-proto`'s existing convention (wire-protocol.md §1's
    versioning rule).
- **Out:** no route-handler behavior (8.5, 8.6), no delivery-on-reconnect logic (8.7), no
  conformance vectors (8.4 — separate task since vector regeneration is its own reviewable unit).

## Deliverables
1. The four wire-shape changes above in `apps/proto/src/msg.rs` and `apps/proto/src/fed.rs`.
2. Round-trip serde tests for each new/changed type (encode → decode → equal; old-shape
   `RouteOk{delivered:true}` and `Deliver{from, blob}` with no `mailbox_id` still decode/encode
   identically to before this task — the compatibility claim itself, tested).
3. `docs/api/wire-protocol.md` §2 op table updated: `mailbox_ack` entry corrected from the stale
   `{envelope_ids[]}` placeholder to `MailboxAck{ids: [uint]}` / `MailboxAckOk{}`, and the new
   `RouteOk`/`Deliver`/error-code fields documented inline.

## Risks / notes
This is the task that fixes wire-protocol.md's pre-existing `mailbox_ack{envelope_ids[]}` placeholder
— that name was always going to collide with `MessageEnvelope::eid` once the mailbox's actual PK
shape was decided (data-model.md, task 7.6); this task is where that gets corrected rather than
inherited. Do not make `RouteOk.queued`/`Deliver.mailbox_id` non-optional — the additive/optional
shape is what keeps this a non-breaking wire change (no version-negotiation dance needed, matching
how `Fetch.hint`/`RouteBody.to_hint` were added in task 2.3).

## Status
**Done.** All four wire-shape changes landed in `apps/proto/src/msg.rs`/`fed.rs`/`frame.rs`/`lib.rs`
exactly per this phase's architect consult: `RouteOk.queued: bool` (additive, omitted when false),
`Deliver.mailbox_id: Option<u64>` (omitted when `None`), `MailboxAck{ids}`/`MailboxAckOk{}` +
`Op` variants, `error_codes::MAILBOX_FULL`/`fed_error_codes::MAILBOX_FULL`. `WIRE_VERSION` bumped
1→2 (a deliberate policy choice per the consult's point 7, documented inline; verified inert today
since nothing yet reads/negotiates on it). `ids` are documented as the mailbox's own row ids, never
the opaque `eid` — matches task 7.6's prior resolution.

Backward compatibility is tested at the byte level, not just structurally: `roundtrip.rs` asserts
the encoded CBOR contains no new key at all for the old-shape `RouteOk{delivered:true}` and
`Deliver{from,blob}` cases. `docs/api/wire-protocol.md` §2's stale `mailbox_ack{envelope_ids[]}`
placeholder is corrected to `MailboxAck{ids:[uint]}`/`MailboxAckOk{}`, with the new fields
documented inline. Existing `RouteOk`/`Deliver` construction sites in
`apps/rendezvous/src/ws.rs`/`federation/inbound.rs`, `apps/core/src/signal_relay.rs`,
`apps/cli/src/opacity.rs`, and `apps/cli/tests/support/mod.rs` got mechanical field additions
(`queued: false` / `mailbox_id: None` / `mailbox: Mailbox::default()`) to keep the workspace
compiling — no behavior changes.

# 12.15 — `apps/desktop` app shell

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** 12.6, 12.7, 12.8, 12.9
· **Status:** done

**User surface:** the desktop client itself — window chrome around the same shared screens the browser
uses. No TUI surface applies (new client platform, not a new protocol feature).

## Goal
Wire the desktop TS adapter (12.6) and the shared screens (12.7–12.9) into a real Tauri window (menus,
window chrome), reusing `shared-ui` per ADR 0012's plan — producing `meridian-desktop`, the feature
spec's deliverable 1's second half (unsigned at this point; signing is task 12.16).

## Scope
- **In:** `apps/desktop/ui/**` (the Svelte frontend consumed by Tauri's WebView), window/menu chrome,
  `apps/desktop/tauri.conf.json` window configuration.
- **Out:** signed release/updater configuration (12.16 — this task produces an unsigned debug/dev build
  only); the interop-matrix CI job (12.17).

## Deliverables
1. `apps/desktop/ui/**` — Svelte frontend wiring 12.6's adapter to 12.7–12.9's screens.
2. `apps/desktop/tauri.conf.json` — window config.
3. `cargo tauri build` (debug) produces a runnable desktop app.

## Risks / notes
Reuse `shared-ui` and the browser's own screens as-is — any desktop-specific screen divergence should be
a deliberate, reviewed exception (e.g. a native file picker instead of drag-drop for 12.9's screen), not
silent duplication of UI logic that then drifts from the browser's.

## Tests
`cargo tauri build` (debug) + `pnpm --filter desktop test`.

## Reviews
**code-reviewer**.

## Outcome
`apps/desktop/ui/src/App.svelte`: local view-state (no router — a native window, not a URL) switching
between `CreateAccount`/`Contacts`/`Chat`/`Verification`/`FileTransfer`/`MessageRequests`, every screen
reused byte-for-byte unmodified from `shared-ui`. A native application menu (Meridian/Edit/View/Window)
wired to `handle_menu_event` in `apps/desktop/src/main.rs`. `build.rs` now generates real ACL
permissions for all 16 Tauri commands (previously none existed — nothing would have been callable from
the WebView), backed by a new `apps/desktop/capabilities/default.json`.

Found and fixed a real bug: `muda`'s GTK/Linux backend (this repo's dev/CI target) silently drops every
predefined menu item type except `Separator`/`Copy`/`Cut`/`Paste`/`SelectAll`/`About` — `Quit`/
`Minimize`/`CloseWindow`/`Undo`/`Redo` never appear on Linux, no compile-time signal. Confirmed against
the actual pinned `muda` source. Fixed by using custom `.text(id, label)` items handled explicitly via
`AppHandle::exit`/`WebviewWindow::minimize`/`::close` instead of the predefined constructors.

Deliberately did not add a native file-picker for the file-transfer screen (the task's Risks/notes names
this as an example allowed exception, not a requirement) — `shared-ui/src/screens/FileTransfer.svelte`
has no prop/event seam to inject an externally-picked path without forking its internals, and 12.6's
`sendFile` already fails closed honestly when a `File`/`Blob` lacks a `.path`, rather than reading bytes
into an unasked-for temp file.

The review (code-reviewer, the task's sole named lens) returned **PASS**, zero blocking findings, after
independently verifying the `muda` bug against the pinned crate source and confirming all 16 commands
have matching ACL entries in both directions (no gaps). One action item fixed before commit: the stale,
git-tracked `apps/desktop/dist/index.html` placeholder from task 12.3 (diverging on every build with
hashed asset filenames) is now untracked via `git rm --cached`, matching `apps/web/dist`'s
never-tracked precedent. Two non-blocking nits recorded, not requiring action now: `cargo tauri build`/
`dev` must be invoked from `apps/desktop/`, not the repo root (a Tauri-CLI cwd-resolution footgun,
verified against the real `tauri-cli` source — worth a one-line note for whoever next touches this
crate's docs); and a desktop CSP baseline (mirroring `apps/web/svelte.config.js`'s real one from 12.14)
has no tracked follow-up task yet — correctly out of this task's own declared Scope→In (window config
only), worth picking up whenever a future desktop-touching task is planned.

`cargo tauri build --debug` succeeds end-to-end; the built binary ran 15s+ under `xvfb-run` with no
panic/crash (only benign software-rendering warnings expected in this sandbox). 39/39 existing
`meridian-desktop-ui` tests unaffected, `tsc --noEmit` clean.

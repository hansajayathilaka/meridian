# 4.16 — Onboarding screen

**Phase:** 4 — Verification & Trust + Terminal TUI Client · **Feature:** T17 — Terminal TUI Client · **Depends on:** 4.14, 4.15 · **Status:** pending

## Goal
Take a user with no account on disk from nothing to a registered, published identity — the first thing
a new `meridian tui` run shows, and the start of the acceptance demo's walkthrough.

## Scope
- **In:** keystore choice (OS keychain / passphrase-wrapped file) → org hint → keypair generation via
  `meridian-identity` → `mrd1:…@domain` ID + in-terminal QR render → rendezvous registration + prekey-
  bundle publish, all through `meridian-core`/`meridian-identity` (no new protocol logic — every
  capability already exists per the design doc's opening rule).
- **Out:** unlock (4.17, the returning-user path); any T08 verification screen content.

## Deliverables
1. `apps/tui/src/screens/onboarding.rs`: screen states + transitions.
2. Screen-snapshot tests (`TestBackend`) at 80×24 and a narrow width, for each onboarding sub-step.

## Tests
`cargo nextest run -p meridian-tui --test screens_onboarding`

## Reviews
- **reviewer** (combined) — orchestrates existing core capability, no new security surface.

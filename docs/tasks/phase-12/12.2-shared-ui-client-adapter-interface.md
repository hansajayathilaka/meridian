# 12.2 — `shared-ui` package + `MeridianClientAdapter` TS interface

**Phase:** 12 — Browser & Desktop Clients · **Feature:** T11 · **Depends on:** — · **Status:** pending

**User surface:** foundational — no screens yet, but this is the seam every browser/desktop screen
(12.7–12.9) and both concrete platform adapters (12.6, 12.13) build against. No TUI surface applies
(ADR 0012: SvelteKit/Tauri UI is out of the TUI's scope by construction).

## Goal
Scaffold the `shared-ui` pnpm package — Svelte visual primitives (message list, contact row, layout
shell) shared between the browser and desktop UIs per ADR 0012 — plus a platform-agnostic TypeScript
interface, `MeridianClientAdapter`, mirroring `core-api-contracts.md`'s operation surface (account
generate/open, chat send/receive, contacts/trust, stream/file ops, verification). Concrete platform
adapters (browser wasm-bindgen, desktop Tauri) implement this interface in later tasks; screens are
written once against the interface and a fake implementation, then reused by both shells unmodified.

## Scope
- **In:** `shared-ui` package scaffold (`package.json`, `pnpm-workspace.yaml` entry, build/lint/test
  scripts replacing `apps/web`'s current TODO placeholders where shared); the `MeridianClientAdapter`
  TypeScript interface; a `FakeMeridianClientAdapter` test double for screen-level component tests
  (in-memory, deterministic, no real crypto/network).
- **Out:** any concrete adapter implementation (browser: 12.13; desktop: 12.6); any actual screen
  (12.7–12.9); the `meridian-wasm` crate itself (12.10).

## Deliverables
1. `shared-ui/package.json`, `pnpm-workspace.yaml` entry.
2. `shared-ui/src/lib/adapter.ts` — the `MeridianClientAdapter` interface.
3. `shared-ui/src/lib/fake-adapter.ts` — `FakeMeridianClientAdapter` test double.
4. Base layout/primitive components used by later screen tasks (message list, contact row, shell).
5. `shared-ui/src/lib/adapter.test.ts` (or equivalent) exercising the fake adapter's contract.

## Risks / notes
`core-api-contracts.md`'s operation list is explicitly "illustrative," not exhaustive — it names no
bulk "list contacts"/"list conversations" query, which every screen needs. `TODO: confirm` — derive the
missing enumeration operations from what `apps/cli`/`apps/tui` already call into `meridian-core` for the
equivalent screens (grep their command handlers), rather than inventing new core behavior; if a genuinely
new core-level query is needed that neither existing client calls today, flag it back rather than adding
one silently — that would be a `meridian-core` API change requiring its own review, out of this task's
scope.

## Tests
`pnpm --filter shared-ui test` (vitest component/unit tests against the fake adapter).

## Reviews
**architect** (new cross-app pattern — confirms the interface doesn't drift from ADR 0012's
"framework-agnostic TS boundary" intent and doesn't leak protocol/wire concerns into the UI layer, per
`apps/web/CLAUDE.md`'s "no bespoke crypto or wire types in JS/TS" rule); **code-reviewer**.

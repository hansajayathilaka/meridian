# 2.13 — A replayed envelope permanently wedges the receiving ratchet

**Phase:** 2 — Cross-Org Federation · **Feature:** on-the-fly (surfaced by 1.32) · **Depends on:** — · **Status:** done

## Goal
Make `Ratchet::decrypt` discard its state changes when decryption fails, so a duplicate delivery
degrades one message rather than the whole session.

## The defect
`Ratchet::decrypt` (`apps/crypto/src/ratchet.rs`) advances the receiving chain **before** it
authenticates:

```rust
let ckr = self.ckr.ok_or(CryptoError::UndecryptableHeader)?;
let (next_ck, mk) = kdf_ck(&ckr);
self.ckr = Some(next_ck);   // committed…
self.nr += 1;               // …committed…
let aad = self.message_aad(enc_header);
aead_open(&mk, ct, &aad)    // …and only now can it fail
```

On `aead_open` failure `ckr`/`nr` are **not** rolled back. A replayed envelope re-derives a chain key
that no longer matches, fails to open, and leaves the chain one step ahead of the sender — so every
subsequent *genuine* message from that peer fails with `Crypto(Crypto)`. Permanently.

Measured directly in
[`apps/cli/tests/relay_attacks.rs::replayed_delivery_is_not_accepted_twice`](../../../apps/cli/tests/relay_attacks.rs).
That cell asserts only the confidentiality/authenticity property (nothing is accepted twice) and
deliberately does **not** assert the wedging either way — asserting today's behaviour would entrench
it.

**Why it matters.** Unauthenticated, needs no key material, permanent, and mountable by any routing
relay — the baseline A2/A3 adversary, who by design sees every blob and can re-send one. It also
breaks *benign* duplicate delivery, which a mailbox (T07) or a flaky reconnect can produce with no
attacker at all. Confidentiality and authenticity are unaffected; this is purely availability.

It contradicts [threat-model.md](../../security/threat-model.md) goal 6 — "availability degradation is
honest but not silent" — so the default disposition is **fix**, not "accept as residual". Recording it
as a residual instead would need explicit security-reviewer sign-off.

## Scope
- **In:** roll back `ckr`/`nr` (and any `dh_ratchet`/`skip_message_keys` mutations on the failing
  path) when `aead_open` fails, per the Double Ratchet spec's "discard changes to the state object";
  a regression test that fails against today's code.
- **Out:** replay *dedup* by envelope id (that is a separate, additive property — this task is only
  about not corrupting state on a failed decrypt); envelope v2 / ADR 0016 work.

## Deliverables
1. `apps/crypto/src/ratchet.rs`: failure-atomic `decrypt` — no observable state change unless
   `aead_open` succeeds.
2. `apps/crypto/tests/`: a cell asserting the ratchet is **byte-identically** unchanged after a
   failed decrypt (the 1.18 pattern), and that a genuine message opens afterwards.
3. Extend `apps/cli/tests/relay_attacks.rs::replayed_delivery_is_not_accepted_twice` to assert the
   session **survives** the replay, and drop its `UNRESOLVED FINDING` note.
4. Update the A2/A3 rows of [threat-mitigation-matrix.md](../../security/threat-mitigation-matrix.md)
   to point at the fix instead of the open defect.

## Risks / notes
- `meridian-crypto` was frozen in Phase 1 Group B. Changing it means checking whether the
  conformance vectors (`test-vectors/ratchet-v1.json`) move: they should **not** — this changes only
  the failure path, and any vector churn is a signal the fix went wider than intended.
- Watch the interaction with `skip_message_keys`: a failed decrypt that already populated the
  skipped-key store must not leave those entries behind, or the rollback is incomplete and the
  store becomes an unbounded-growth surface (ADR 0016 R2).
- The regression test **must be shown to fail against the current code** before the fix lands.

## Outcome
`apps/crypto/src/ratchet.rs`: `DoubleRatchet::decrypt` now stages `ckr`/`nr`/`dh_ratchet`/
`skip_message_keys` mutations on a checkpoint copy of `self`, committing (`*self = checkpoint`) only
after `aead_open` succeeds — no observable state change on any failure path, including the compound
old-chain-then-new-chain `skip_message_keys` case during a DH-ratchet catch-up. Regression tests
(`apps/crypto/tests/ratchet_replay.rs`) were shown to **fail against the pre-fix code** before the
fix landed, per the task's own required process gate — `nr` diverged and the compound case's
skipped-key store grew residual entries. `apps/cli/tests/relay_attacks.rs`'s
`replayed_delivery_is_not_accepted_twice` now asserts the session survives the replay; its
`UNRESOLVED FINDING` note is dropped. Conformance vectors (`test-vectors/ratchet-v1.json`) unchanged
— confirmed by md5 before/after a real regeneration, not merely asserted.

**Reviews:** security-reviewer — APPROVE-WITH-CHANGES. Traced the atomicity fix, zeroization on
both discard and commit, and `try_skipped`'s pre-existing correctness directly against code, not the
implementer's description — all confirmed sound. Found two required issues in the same pass: (1)
HIGH — the fix's initial mechanism (`#[derive(Clone)]` on `DoubleRatchet`) made the type's `Clone`
public, and since the AEAD key+nonce are both derived solely from the single-use message key, a
public `Clone` let any external holder fork a live session and reuse a key+nonce pair on a later
encrypt/decrypt — catastrophic, not just availability-degrading. Fixed by replacing the derive with
a crate-private `checkpoint()` method confined to `ratchet.rs`. (2) MEDIUM — the
`threat-mitigation-matrix.md` A3 row this task edits also claimed "replay dedup by eid" as an active
mitigation; `wire-protocol.md` states v1 has no envelope-level replay protection at all. Corrected
in the same edit. test-engineer — verdict held up under independent reproduction (reverted the fix,
confirmed both new tests and the extended integration test fail; reverted the revert cleanly);
confirmed the compound-case test is genuinely non-vacuous and the byte-identical comparison covers
the full struct (no `#[serde(skip)]` fields).

Tests: `cargo nextest run -p meridian-crypto` (15/15 pass), `cargo nextest run -p meridian-cli --test
relay_attacks` (6/6 pass), `cargo test --workspace` green, clippy/fmt clean, `check-docs.sh` no
broken links.
